# 创建线程池

## 两种创建方式

### 1. ExecutorService 的静态工厂方法

`Executors` 类提供了多种静态工厂方法，快速创建常用线程池：

```java
// 固定线程数的线程池
ExecutorService fixedPool = Executors.newFixedThreadPool(3);

// 单线程池（保证顺序执行）
ExecutorService singlePool = Executors.newSingleThreadExecutor();

// 可缓存线程池（按需创建，空闲回收）
ExecutorService cachedPool = Executors.newCachedThreadPool();

// 定时任务线程池
ScheduledExecutorService scheduledPool = Executors.newScheduledThreadPool(3);
```

| 工厂方法 | 核心线程数 | 最大线程数 | 阻塞队列 | 特点 |
|---|---|---|---|---|
| `newFixedThreadPool(n)` | n | n | LinkedBlockingQueue（无界） | 固定线程数，队列无界 |
| `newSingleThreadExecutor()` | 1 | 1 | LinkedBlockingQueue（无界） | 单线程，保证顺序执行 |
| `newCachedThreadPool()` | 0 | Integer.MAX_VALUE | SynchronousQueue（无容量） | 按需创建，空闲60s回收 |
| `newScheduledThreadPool(n)` | n | Integer.MAX_VALUE | DelayedWorkQueue | 支持定时和周期性任务 |

### 2. ThreadPoolExecutor 手动创建（推荐）

```java
ThreadPoolExecutor executor = new ThreadPoolExecutor(
    2,                              // 核心线程数
    5,                              // 最大线程数
    60L,                            // 空闲线程存活时间
    TimeUnit.SECONDS,               // 时间单位
    new ArrayBlockingQueue<>(100),  // 有界阻塞队列
    new ThreadFactory() {           // 线程工厂（自定义线程名）
        private final AtomicInteger counter = new AtomicInteger(1);
        @Override
        public Thread newThread(Runnable r) {
            return new Thread(r, "my-pool-thread-" + counter.getAndIncrement());
        }
    },
    new ThreadPoolExecutor.CallerRunsPolicy()  // 拒绝策略
);
```

## 为什么不推荐使用 Executors 创建？

阿里巴巴 Java 开发手册明确规定：**线程池不允许使用 Executors 去创建，而是通过 ThreadPoolExecutor 的方式**。

### FixedThreadPool / SingleThreadExecutor：无界队列 --> OOM

```java
// 源码
public static ExecutorService newFixedThreadPool(int nThreads) {
    return new ThreadPoolExecutor(nThreads, nThreads,
        0L, TimeUnit.MILLISECONDS,
        new LinkedBlockingQueue<Runnable>());  // 默认容量 Integer.MAX_VALUE
}
```

- 使用 `LinkedBlockingQueue`，默认容量为 `Integer.MAX_VALUE`（约 21 亿）
- 任务提交速度远大于处理速度时，队列无限增长，最终导致 **OOM**

### CachedThreadPool：最大线程数无上限 --> OOM

```java
// 源码
public static ExecutorService newCachedThreadPool() {
    return new ThreadPoolExecutor(0, Integer.MAX_VALUE,
        60L, TimeUnit.SECONDS,
        new SynchronousQueue<Runnable>());
}
```

- 最大线程数为 `Integer.MAX_VALUE`
- 任务来就创建线程，无上限，大量并发时创建海量线程 --> **OOM**

### ScheduledThreadPool：最大线程数无上限

- 与 CachedThreadPool 同理，最大线程数为 `Integer.MAX_VALUE`

## 手动创建的推荐配置

### 核心线程数

根据任务类型选择：

| 任务类型 | 核心线程数 | 说明 |
|---|---|---|
| CPU 密集型 | N + 1 | N = CPU 核心数；+1 保证某线程因页缺失等原因暂停时，仍有线程可用 |
| IO 密集型 | 2N | 线程在等待 IO 时不占用 CPU，可多分配线程 |
| 混合型 | 拆分为 CPU 密集 + IO 密集，分别使用不同线程池 |

```java
int cpuCount = Runtime.getRuntime().availableProcessors();

// CPU 密集型
int corePoolSizeCpu = cpuCount + 1;

// IO 密集型
int corePoolSizeIO = cpuCount * 2;
```

> **注意**：以上公式是经验值，实际应该通过压测确定最优线程数。

### 阻塞队列选择

| 队列类型 | 特点 | 适用场景 |
|---|---|---|
| `ArrayBlockingQueue`（有界） | 有界，FIFO，数组实现 | 需要控制队列大小，防止 OOM |
| `LinkedBlockingQueue` | 默认无界，可指定容量 | 一般场景（务必指定容量） |
| `SynchronousQueue` | 不存储元素，直接交付 | 高吞吐、直接提交（CachedThreadPool） |
| `PriorityBlockingQueue` | 支持优先级排序 | 任务有优先级需求 |
| `DelayQueue` | 延迟取出 | 定时任务（ScheduledThreadPool） |

**推荐**：使用 `ArrayBlockingQueue` 或指定容量的 `LinkedBlockingQueue`，避免无界队列导致 OOM。

### 拒绝策略选择

当线程池的工作线程数达到最大且队列已满时，新提交的任务触发拒绝策略：

| 拒绝策略 | 行为 | 适用场景 |
|---|---|---|
| `AbortPolicy`（默认） | 抛出 RejectedExecutionException | 需要感知任务被拒绝的场景 |
| `CallerRunsPolicy` | 由提交任务的线程自己执行 | 不丢弃任务，降低提交速度（推荐） |
| `DiscardPolicy` | 静默丢弃任务 | 允许丢弃任务 |
| `DiscardOldestPolicy` | 丢弃队列头（最老）的任务，再提交 | 优先执行新任务 |

> **自定义拒绝策略**：可以实现 `RejectedExecutionHandler` 接口，如记录日志、持久化到数据库、MQ 等。

### 线程命名（ThreadFactory）

自定义 ThreadFactory 给线程池中的线程命名，便于排查问题：

```java
ThreadFactory threadFactory = new ThreadFactory() {
    private final AtomicInteger counter = new AtomicInteger(1);
    @Override
    public Thread newThread(Runnable r) {
        Thread t = new Thread(r, "order-pool-" + counter.getAndIncrement());
        t.setDaemon(false);  // 非守护线程
        return t;
    }
};

// 也可以使用 Guava
ThreadFactory namedFactory = new ThreadFactoryBuilder()
    .setNameFormat("order-pool-%d").build();
```

## 不同场景的线程池配置建议

### 快速响应的 Web 服务

```java
new ThreadPoolExecutor(
    Runtime.getRuntime().availableProcessors(),      // 核心线程数 = CPU 核数
    Runtime.getRuntime().availableProcessors() * 2,  // 最大线程数 = 2 * CPU 核数
    60L, TimeUnit.SECONDS,
    new ArrayBlockingQueue<>(1000),                  // 有界队列
    new NamedThreadFactory("web-pool"),
    new ThreadPoolExecutor.CallerRunsPolicy()        // 队列满时由调用线程执行
);
```

### 批处理 / 后台任务

```java
new ThreadPoolExecutor(
    Runtime.getRuntime().availableProcessors() * 2,  // IO 密集型
    Runtime.getRuntime().availableProcessors() * 4,
    120L, TimeUnit.SECONDS,
    new ArrayBlockingQueue<>(500),
    new NamedThreadFactory("batch-pool"),
    new ThreadPoolExecutor.DiscardOldestPolicy()     // 丢弃最老任务
);
```

### 定时任务

```java
// 仍然推荐手动创建 ScheduledThreadPoolExecutor
ScheduledExecutorService scheduler = new ScheduledThreadPoolExecutor(
    2,
    new NamedThreadFactory("scheduled-pool")
);
scheduler.scheduleAtFixedRate(task, 0, 5, TimeUnit.MINUTES);
```

## 线程池参数动态调整

HPE（美团）等公司实践：线程池核心参数可通过配置中心动态调整，无需重启：

```java
// ThreadPoolExecutor 提供了动态调整方法
executor.setCorePoolSize(newCoreSize);
executor.setMaximumPoolSize(newMaxSize);
```

## 一句话总结

创建线程池推荐使用 ThreadPoolExecutor 手动创建，不推荐使用 Executors 工厂方法（无界队列和无限线程数会导致 OOM）；核心线程数按任务类型选择（CPU 密集型 N+1，IO 密集型 2N），必须使用有界队列并合理选择拒绝策略。

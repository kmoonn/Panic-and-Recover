# 登录失败排查

## 面试题：用户反馈登录失败，你如何排查？

这是一道经典的测开场景题，考察系统性排查思维和对登录链路的理解。核心原则：**从用户侧到服务端，从外到内逐层排查**。

---

## 排查思路总览

```
用户反馈"登录失败"
        │
        ▼
   ① 确认现象 ──→ 什么表现？谁能复现？
        │
        ▼
   ② 前端排查 ──→ 请求发出去了吗？参数对吗？
        │
        ▼
   ③ 网络排查 ──→ 请求到达服务器了吗？
        │
        ▼
   ④ 后端排查 ──→ 服务处理对吗？数据库查到没？
        │
        ▼
   ⑤ 定位原因 ──→ 修复 → 验证 → 复盘
```

---

## 一、确认现象

| 确认项 | 方法 |
|--------|------|
| 具体表现 | 是页面白屏？提示错误？一直转圈？闪退？ |
| 影响范围 | 只影响一个用户？部分用户？所有用户？ |
| 复现条件 | 什么设备/浏览器/网络？特定账号？特定时间？ |
| 错误信息 | 页面上有没有报错提示？错误码是什么？ |
| 是否有变更 | 最近有没有发版？配置变更？ |

**关键区分**：

| 表现 | 可能方向 |
|------|---------|
| 点击登录无反应 | 前端 JS 报错 / 事件未绑定 |
| 提示"账号或密码错误" | 后端校验逻辑 / 数据库问题 |
| 提示"网络异常" | 网络/网关问题 |
| 一直转圈无响应 | 请求超时 / 服务挂了 |
| 提示"验证码错误" | 验证码服务问题 / 缓存问题 |

---

## 二、前端排查

### 1. 浏览器 DevTools

```
F12 → Network 标签页
├── 请求是否发出？
│   ├── 没有 → JS 报错 / 事件绑定问题 / 请求被拦截
│   └── 有 → 看状态码
│       ├── 4xx → 前端参数问题
│       ├── 5xx → 后端问题
│       └── 一直 Pending → 网络问题 / 服务超时
└── Console 标签页
    └── 有没有 JS 报错？(Uncaught TypeError, CORS error...)
```

### 2. 常见前端问题

| 问题 | 排查方法 |
|------|---------|
| 请求未发出 | Console 看 JS 报错，检查按钮事件绑定 |
| 参数错误 | Network 看请求 Payload，对比接口文档 |
| CORS 跨域 | Console 看 `Access-Control-Allow-Origin` 错误 |
| Cookie 问题 | Application → Cookies，检查 Token 是否设置 |
| 前端校验拦截 | 检查表单校验逻辑（如密码格式限制） |

---

## 三、网络排查

### 1. 抓包分析

```
用 Charles/Fiddler 抓包：
├── 请求是否到达代理？ → 没到：DNS/代理问题
├── 请求是否到达服务器？ → 看响应是否有返回
├── 响应延迟多少？ → 超时则可能是服务慢或网络抖动
└── HTTPS 证书问题？ → 看是否有 SSL 错误
```

### 2. 常见网络问题

| 问题 | 排查方法 |
|------|---------|
| DNS 解析失败 | `nslookup` / `dig` 检查域名解析 |
| 网关/CDN 问题 | `curl -v` 测试直接访问源站 |
| 请求被 WAF 拦截 | 查看 WAF 日志，确认是否误拦截 |
| 请求超时 | `ping` / `traceroute` 检查网络连通性 |

## 四、后端排查

### 1. 查看日志

```bash
# 查看应用日志
tail -f /var/log/app/login.log | grep "ERROR"

# 查看网关日志（Nginx）
tail -f /var/log/nginx/access.log | grep "login"

# 查看错误日志
tail -f /var/log/app/error.log
```

### 2. 常见后端问题

| 问题 | 排查方法 |
|------|---------|
| 密码校验失败 | 检查加密方式是否一致（MD5/SHA256/BCrypt） |
| 数据库连接失败 | 检查连接池状态、数据库是否可达 |
| Redis 会话问题 | 检查 Token 是否过期、Redis 是否正常 |
| 第三方登录失败 | 检查 OAuth 回调、AppID/Secret 配置 |
| 并发问题 | 检查是否有锁竞争、分布式 Session 不一致 |
| 验证码服务异常 | 检查短信/邮件服务状态、频率限制 |

### 3. 数据库排查

```sql
-- 查看用户是否存在
SELECT * FROM users WHERE username = 'test_user';

-- 查看密码哈希是否正确
SELECT password_hash FROM users WHERE username = 'test_user';

-- 查看是否有登录日志
SELECT * FROM login_logs WHERE user_id = 123 ORDER BY created_at DESC LIMIT 10;

-- 检查是否被锁定
SELECT * FROM users WHERE username = 'test_user' AND locked_until > NOW();
```

## 五、登录链路全景图

```
用户输入账号密码
    │
    ▼
前端校验（格式、非空）
    │
    ▼
发送登录请求（HTTPS）
    │
    ▼
CDN / WAF / 负载均衡
    │
    ▼
API 网关（鉴权、限流、路由）
    │
    ▼
登录服务
    ├──→ 验证码校验（Redis/短信服务）
    ├──→ 密码校验（数据库/加密服务）
    ├──→ 风控检查（频率限制、IP 黑名单）
    └──→ 生成 Token（JWT / Session）
         │
         ▼
    写入 Session/Redis
         │
         ▼
    返回 Token 给前端
         │
         ▼
    前端存储 Token（Cookie/LocalStorage）
         │
         ▼
    后续请求携带 Token
```

每一层都可能出问题，排查时从两端向中间逼近。

---

## 面试回答模板

> 1. 先确认现象——什么表现、影响范围、是否可复现
> 2. 前端排查——DevTools 看请求是否发出、参数是否正确、有没有 JS 报错
> 3. 网络排查——抓包看请求是否到达服务器、状态码、延迟
> 4. 后端排查——查日志定位报错位置，看数据库/Redis/第三方服务状态
> 5. 定位原因后修复、验证、补充测试用例、复盘

---

## 一句话总结

> 登录失败排查遵循"从外到内、逐层定位"原则：先确认现象和范围，再前端看请求/参数/JS报错，再网络看抓包/状态码/延迟，最后后端查日志/数据库/Redis/第三方服务，从两端向中间逼近定位根因。

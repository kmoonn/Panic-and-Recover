# 百度搜索功能测试

## Q: 如何设计百度搜索功能的测试用例？

### 解题思路

这类题本质上考察的是：**能不能把一个高频用户功能，按输入、展示、状态、异常、性能、安全几个维度拆完整**。回答时不要只说“测输入框和结果页”，而要覆盖：

1. **怎么搜**：按钮、回车、图片搜索、多关键词、搜索语法
2. **搜出来对不对**：结果相关性、字段展示、跳转、分页、排序、去重
3. **状态相关功能**：历史记录、删除、样式
4. **高并发与性能**：多用户同时搜索、耗时、稳定性
5. **安全性**：XSS、注入类异常输入、非法参数

---

## 一、搜索入口与触发方式

| 测试点 | 操作 | 预期 |
|--------|------|------|
| 点击搜索按钮 | 输入关键词后点击“百度一下” | 正常发起搜索，请求参数正确 |
| 回车触发搜索 | 输入关键词后按 Enter | 与点击按钮效果一致 |
| 空关键词点击搜索 | 不输入内容直接点击搜索 | 按产品设计处理：停留当前页 / 提示输入 / 展示默认页 |
| 连续多次点击搜索 | 连续点击按钮 | 只发起一次有效搜索或按节流策略处理，不出现重复请求风暴 |
| 搜索中再次发起新搜索 | 首次搜索未完成时修改关键词再搜 | 旧请求被取消或结果不覆盖新关键词结果 |
| 图片搜索入口 | 上传图片进行搜索 | 能正常识别图片并返回对应结果 |
| 搜索语法 `filetype:` | 输入 `Java 并发 filetype:pdf` | 能按规则返回特定类型文档结果，语法不生效时有合理降级 |

## 二、输入框与关键词校验

| 测试点 | 输入数据 | 预期 |
|--------|---------|------|
| 普通文本搜索 | `mysql explain` | 正常返回相关结果 |
| 中文搜索 | `最长回文子串` | 正常返回中文相关结果 |
| 英文搜索 | `RAG evaluation` | 正常返回英文相关结果 |
| 数字搜索 | `2026` | 正常返回数字相关结果 |
| 特殊字符搜索 | `C++`、`a+b`、`#AI` | 特殊字符按产品规则解析，不乱码、不报错 |
| 超长关键词 | 输入超长字符串 | 页面不卡死，按长度限制处理或正常截断 |
| 前后空格 | `  mysql explain  ` | 自动预处理，结果与去空格后一致 |
| 大小写混输 | `MySQL Explain` | 结果合理，不因大小写产生异常 |
| 多关键词 | `mysql explain 索引优化` | 能返回覆盖多个关键词的相关结果 |
| 无意义乱码 | `@@@###%%%` | 系统稳定，返回合理空结果或弱相关结果，不报错 |
| 敏感脚本输入 | `<script>alert(1)</script>` | 前端不弹窗，页面不被注入，后端安全处理 |

## 三、搜索结果展示

| 测试点 | 操作 | 预期 |
|--------|------|------|
| 结果基本展示 | 输入正常关键词搜索 | 返回结果列表，标题、摘要、来源、链接等字段展示完整 |
| 结果相关性 | 搜索特定问题 | 前几条结果与搜索词高度相关 |
| 关键词高亮 | 搜索后观察页面 | 关键词在标题或摘要中高亮展示（若产品支持） |
| 空结果页 | 搜索极冷门或错误词 | 展示“未找到相关结果”及推荐引导 |
| 重复结果 | 观察同一页结果 | 不应出现大量完全重复结果 |
| 失效链接结果 | 点击结果 | 若目标页已失效，应有合理兜底，不影响搜索页稳定 |
| 结果跳转 | 点击任一结果 | 正常跳转到对应页面，不跳错、不 404 |
| 新开页行为 | 点击结果 | 是否新开页符合产品设计 |
| 返回搜索页 | 从结果页返回 | 关键词、分页状态、滚动位置尽量保留 |

## 四、分页、排序与参数异常

| 测试点 | 输入/操作 | 预期 |
|--------|----------|------|
| 默认分页 | 正常搜索 | 默认每页数量正确 |
| 翻到第 2 页 | 点击下一页 | 结果正确切换到第 2 页 |
| 翻到第 10 页/20 页 | 连续翻页 | 分页稳定，数据不重复、不丢失 |
| 固定页码访问 | 手动构造 `page=10` | 正常展示第 10 页结果 |
| 负数页码 | `page=-1` | 自动兜底到第一页或返回合法错误处理 |
| 页码类型错误 | `page=abc` | 参数兜底，不报 500 |
| 极大页码 | `page=999999` | 返回空结果/尾页兜底，不超时 |
| total 数量校验 | 多次翻页观察总数 | total 与分页数量逻辑一致 |
| 排序切换 | 切换综合/时间等排序 | 排序条件生效，结果顺序合理变化 |
| 排序后分页 | 先排序再翻页 | 排序状态保持一致 |

## 五、历史记录相关

| 测试点 | 操作 | 预期 |
|--------|------|------|
| 历史记录展示 | 搜索后返回首页 | 能看到最近搜索记录 |
| 历史记录样式 | 查看历史区域 | 样式清晰，不遮挡输入框或按钮 |
| 点击历史记录 | 点击某条历史关键词 | 能直接触发该关键词搜索 |
| 删除单条历史记录 | 删除一条记录 | 该条记录立即消失 |
| 清空全部历史 | 清空历史记录 | 历史区域被清空，刷新后状态符合预期 |
| 未登录/登录状态差异 | 切换登录态 | 历史记录存储范围和同步逻辑符合设计 |

## 六、并发、性能与稳定性

| 测试点 | 操作 | 预期 |
|--------|------|------|
| 多用户同时搜索 | 多用户并发搜索热门词 | 服务稳定，无明显错误率上升 |
| 高频重复搜索 | 多用户同时搜索同一词 | 响应时间可接受，缓存策略生效时结果一致 |
| 响应耗时 | 搜索后统计首屏返回时间 | 在可接受范围内，例如核心请求 P95/P99 达标 |
| 弱网搜索 | 模拟弱网/高延迟 | 页面有加载态，不白屏、不假死 |
| 搜索超时 | 模拟后端超时 | 给出超时提示，可重试 |
| 服务降级 | 搜索服务异常 | 有合理兜底页或提示，不影响页面稳定性 |

## 七、安全性

| 测试点 | 输入/操作 | 预期 |
|--------|----------|------|
| XSS 输入 | `<script>alert(1)</script>` | 页面不执行脚本，搜索词安全转义 |
| HTML 注入 | `<img src=x onerror=alert(1)>` | 不执行注入代码 |
| SQL 注入风格输入 | `' OR 1=1 --` | 服务稳定，不报错、不泄露异常堆栈 |
| 参数篡改 | 手动改 query 参数、页码、排序参数 | 非法参数被校验和兜底 |
| 敏感信息泄露 | 搜索异常场景 | 返回信息中不暴露内部 SQL、路径、堆栈 |

## 八、可进一步补充的搜索功能点

如果面试官继续追问，还可以主动补这些维度，显得测试思路更完整：

### 1. 搜索建议 / 联想词

| 测试点 | 操作 | 预期 |
|--------|------|------|
| 输入时联想词展示 | 输入部分关键词 | 展示联想词列表，内容与输入相关 |
| 联想词点击搜索 | 点击联想词 | 正常按该词发起搜索 |
| 键盘上下选择联想词 | 使用方向键和 Enter | 焦点切换正确，Enter 可触发 |
| 联想词为空 | 输入冷门词 | 合理展示空态或不展示联想层 |
| 联想词刷新时机 | 快速连续输入 | 联想词跟随最新输入更新，不出现旧结果覆盖 |

### 2. 结果页筛选条件

| 测试点 | 操作 | 预期 |
|--------|------|------|
| 切换搜索类型 | 网页 / 图片 / 视频 / 资讯 | 搜索范围切换正确，结果类型对应变化 |
| 时间筛选 | 选择最近一天/一周/一年 | 结果范围受筛选条件影响 |
| 来源筛选 | 指定站点或来源 | 结果符合限定条件 |
| 条件叠加 | 同时加关键词 + 时间 + 类型 | 条件组合生效，不互相覆盖 |
| 筛选后刷新页面 | 刷新结果页 | 当前筛选条件尽量保持 |

### 3. 兼容性与易用性

| 测试点 | 操作 | 预期 |
|--------|------|------|
| 浏览器兼容 | Chrome / Safari / Edge / Firefox | 核心搜索链路正常 |
| 分辨率适配 | 不同窗口尺寸 | 输入框、按钮、结果布局正常 |
| 键盘可操作性 | Tab / Enter / Esc | 输入与搜索流程可用 |
| 无障碍支持 | 屏幕阅读器、焦点态 | 基础可访问性符合设计要求 |
| 移动端体验 | 手机浏览器输入搜索 | 展示与交互正常，不遮挡 |

## 九、把这题回答得更像“面试高分答案”的方式

面试现场不需要把所有测试点一次性背出来，更推荐用“主线 + 重点补充”的方式表达：

```text
1. 先按输入、结果、状态、异常、安全五个大类搭骨架
2. 再挑 2~3 个最容易体现测试深度的点展开
   - 分页参数异常
   - 并发与性能
   - XSS/非法输入
3. 最后补一句：如果产品支持联想词、筛选、图片搜索，我也会继续覆盖这些扩展能力
```

这样既有结构，也显得你有测试经验，而不是只在背 checklist。

## 设计方法对照

| 方法 | 在本题中的应用 |
|------|----------------|
| **等价类划分** | 关键词类型：中文、英文、数字、特殊字符、图片、多关键词 |
| **边界值分析** | 关键词长度、页码 1/10/20/负数/超大值 |
| **场景法** | 搜索 → 查看结果 → 翻页 → 点击跳转 → 返回 |
| **错误推测** | XSS、非法参数、重复点击、超时、重复结果 |
| **性能与并发测试** | 热词高并发、多用户同时搜索、弱网场景 |

## 面试回答模板

> 我会按五个维度来设计百度搜索功能测试用例。第一是搜索入口和输入触发，比如按钮、回车、图片搜索、多关键词和 `filetype:` 语法；第二是结果页本身，包括字段展示、相关性、跳转、重复结果、分页和排序；第三是历史记录这类状态功能；第四是并发和性能，比如多用户同时搜索、弱网和耗时；第五是安全性，重点看 XSS、参数篡改和异常输入。这样能比较完整地覆盖一个搜索产品的核心风险。

## 一句话总结

> 百度搜索功能测试要从搜索触发、输入类型、结果展示、分页排序、历史记录、并发性能、安全性七个维度展开，既覆盖正常流程，也覆盖参数异常、弱网和 XSS 等高风险场景。

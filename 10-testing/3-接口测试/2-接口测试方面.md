# 测试一个接口从哪些方面入手

## 思维导图

```
接口测试
├── 功能性
│   ├── 正常场景
│   ├── 异常场景
│   └── 边界值
├── 安全性
│   ├── 鉴权
│   ├── 参数篡改
│   └── 注入攻击
├── 性能
│   ├── 响应时间
│   ├── 并发能力
│   └── 稳定性
├── 兼容性
│   ├── 参数格式
│   └── 编码/字符集
└── 幂等与并发
    ├── 重复提交
    └── 并发操作
```

## 1. 功能性

### 正常场景（Happy Path）

- 必填参数全部正确，验证返回结果符合预期
- 选填参数组合各种合法值
- 不同返回状态码的业务场景（如 200 成功、201 创建成功）

### 异常场景

| 维度 | 测试点 |
|---|---|
| 缺少必填参数 | 返回 400 + 明确错误信息 |
| 参数类型错误 | 传 string 给 int 字段、传数组给对象字段 |
| 参数长度超限 | 超过数据库字段最大长度 |
| 非法值 | 负数、空字符串、null、特殊字符 |
| 不存在的资源 | 查询/删除不存在的 ID，返回 404 |
| 重复操作 | 重复创建已存在的资源 |

### 边界值

- 数值：0、最小值、最大值、边界 ±1
- 日期：最小日期、最大日期、闰年 2.29、跨时区
- 集合：空列表、单元素列表、超大列表
- 字符串：空串、纯空格、超长串、含 emoji/特殊字符

## 2. 安全性

| 测试点 | 说明 |
|---|---|
| 未登录访问 | 不带 token 应返回 401 |
| 越权访问 | 用 A 的 token 访问 B 的资源，应返回 403 |
| Token 过期 | 过期 token 应返回 401 |
| SQL 注入 | 参数传 `' OR 1=1 --`，应被拦截 |
| XSS | 参数传 `<script>alert(1)</script>`，应被转义 |
| 敏感信息泄露 | 响应不应返回密码、手机号明文等 |
| 接口限流 | 超频请求应返回 429 |

## 3. 性能

| 测试点 | 方法 |
|---|---|
| 单次响应时间 | 单请求 P99 < 200ms |
| 并发能力 | 逐步加并发，找出 QPS 上限 |
| 稳定性 | 持续压测 30min，观察有无内存泄漏/OOM |
| 大数据量 | 返回分页 / 大列表时的响应时间 |
| 弱网环境 | 高延迟/丢包下是否超时重试、是否幂等 |

## 4. 兼容性

| 测试点 | 说明 |
|---|---|
| 参数格式 | JSON / Form 表单 / XML 均能正确解析 |
| 字符编码 | UTF-8 中文、emoji 不乱码 |
| 版本兼容 | v1 / v2 接口同时可用 |
| 大小写 | 字段名大小写是否敏感 |

## 5. 幂等性与并发

### 幂等性

同一请求执行多次，结果应与执行一次相同：

| HTTP 方法 | 天然幂等？ | 说明 |
|---|---|---|
| GET | ✅ | 查询不改变状态 |
| PUT | ✅ | 整体替换，多次结果一样 |
| DELETE | ✅ | 删一次和删多次结果一样 |
| POST | ❌ | 每次可能创建新资源 |

- POST 重复提交：前端防重 / 后端唯一键 / 幂等 token

### 并发安全

- 多个请求同时修改同一资源（如扣库存）：是否超卖
- 乐观锁 / 悲观锁 / 分布式锁是否生效

## 6. 业务逻辑

| 测试点 | 说明 |
|---|---|
| 前置条件 | 未满足前置条件时调用应失败（如未支付就发货） |
| 状态流转 | 订单状态只能从"待支付"→"已支付"，不能跳过 |
| 关联数据 | 删除父资源时子资源如何处理（级联删除 / 拒绝删除） |
| 事务一致性 | 操作失败时是否全部回滚 |

## 7. 返回值与协议

| 测试点 | 说明 |
|---|---|
| 状态码正确 | 成功 200、创建 201、参数错 400、未鉴权 401、禁止 403、不存在 404、服务错 500 |
| 响应格式 | JSON 结构符合文档，字段类型正确 |
| 错误信息 | 错误码 + 可读提示，不暴露堆栈 |
| 响应头 | Content-Type、Cache-Control、CORS 头正确 |

## 实战清单模板

```
接口：POST /api/orders
□ 正常下单（全部参数正确）
□ 缺少必填参数（商品ID、数量）
□ 数量为0 / 负数 / 超库存
□ 未登录下单 → 401
□ 下单他人商品 → 403
□ 重复提交 → 不重复创建
□ 并发扣库存 → 不超卖
□ 库存不足 → 返回明确错误
□ 响应时间 < 500ms
□ SQL 注入 / XSS 拦截
```

## 一句话总结

> 从功能、安全、性能、兼容、幂等并发、业务逻辑、返回协议七个维度系统设计接口测试

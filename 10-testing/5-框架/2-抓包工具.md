# 抓包工具

## 什么是抓包

抓包（Packet Capture）是拦截和查看网络请求与响应的过程，是接口测试和问题排查的核心技能。

**核心用途**：看清客户端和服务器之间到底发了什么——请求参数、响应内容、状态码、耗时。

---

## 主流抓包工具对比

| 工具 | 平台 | 抓包方式 | HTTPS | 适用场景 |
|------|------|---------|-------|---------|
| **Charles** | 跨平台（GUI） | 代理 | ✅ 需装证书 | Web/APP 接口调试 |
| **Fiddler** | Windows（GUI） | 代理 | ✅ 需装证书 | Web 接口调试 |
| **Wireshark** | 跨平台（GUI） | 网卡抓包 | ❌ 加密不可读 | 网络层排障（TCP/UDP） |
| **tcpdump** | Linux（CLI） | 网卡抓包 | ❌ 加密不可读 | 服务器端抓包 |
| **mitmproxy** | 跨平台（CLI） | 代理 | ✅ 需装证书 | 自动化/脚本化抓包 |
| **Burp Suite** | 跨平台（GUI） | 代理 | ✅ 需装证书 | 安全测试 |

## Charles

### 基本配置

```
1. 启动 Charles → 默认代理端口 8888
2. 手机/浏览器设置代理 → 指向电脑 IP:8888
3. 安装 HTTPS 证书 → Help → SSL Proxying → Install Charles Root Certificate
```

### HTTPS 抓包

```
Proxy → SSL Proxying Settings → 勾选 Enable SSL Proxying
Add → Host: *   Port: 443（抓所有 HTTPS）
```

| 操作 | 快捷键/路径 |
|------|------------|
| 开始/停止录制 | Ctrl+R / Command+R |
| 过滤请求 | Proxy → Recording Settings |
| 修改请求 | 右键 → Compose |
| 修改响应 | 右键 → Map Local / Map Remote |
| 模拟慢网络 | Proxy → Throttle Settings |
| 重放请求 | 右键 → Repeat |
| 断点拦截 | 右键 → Breakpoints |

### Map Local（Mock 响应）

将指定接口的响应映射到本地文件，用于 Mock 测试：

```
1. 右键请求 → Map Local
2. 选择本地 JSON 文件作为响应
3. 后续该接口的请求都会返回本地文件内容
```

### Throttle（模拟弱网）

```
Proxy → Throttle Settings
┌─────────────────────────────┐
│ ☑ Enable Throttling         │
│ Bandwidth: 256 Kbps         │ ← 模拟 3G 网络
│ Latency: 100 ms             │
│ MTU: 1500                   │
└─────────────────────────────┘
```

## Fiddler

### 与 Charles 的对比

| 维度 | Charles | Fiddler |
|------|---------|---------|
| 平台 | Win/Mac/Linux | 主要 Windows |
| 界面风格 | 更现代 | 偏传统 |
| 脚本能力 | 弱 | JScript 强 |
| 自动响应 | Map Local/Remote | AutoResponder |
| 免费 | 付费（30天试用） | 免费（Classic版） |
| 过滤 | Proxy Settings | Filters 标签页 |

### Fiddler 常用操作

```
1. 过滤：Filters 标签 → 勾选 Show only if URL contains
2. AutoResponder：拖拽请求 → 设置 Mock 规则
3. Composer：手动构造请求发送
4. 断点：bpu 接口URL（请求断点）/ bpu 响应断点
5. 模拟弱网：Rules → Performance → Simulate Modem Speeds
```

## Wireshark

### 适用场景

Charles/Fiddler 工作在应用层（HTTP），Wireshark 工作在网络层（所有协议），适合：
- TCP 连接问题排查（SYN 重传、RST、TIME_WAIT）
- DNS 解析问题
- 网络延迟分析
- 非 HTTP 协议分析

### 常用过滤表达式

| 过滤器 | 含义 |
|--------|------|
| `http` | 只看 HTTP 协议 |
| `tcp.port == 8080` | 只看 8080 端口 |
| `ip.addr == 10.0.0.1` | 只看指定 IP |
| `tcp.flags.syn == 1` | 只看 SYN 包 |
| `tcp.analysis.retransmission` | 只看重传包 |
| `dns` | 只看 DNS 协议 |
| `http.request.method == "POST"` | 只看 POST 请求 |

### 三次握手抓包示例

```
过滤: tcp.flags.syn == 1

1. [SYN]      客户端 → 服务器    Seq=0
2. [SYN, ACK] 服务器 → 客户端    Seq=0, Ack=1
3. [ACK]      客户端 → 服务器    Seq=1, Ack=1
```

## mitmproxy

### 适用场景

适合**自动化抓包**和**批量接口测试**，用 Python 脚本控制请求/响应。

### 基本使用

```bash
# 启动代理
mitmproxy -p 8080

# 无界面模式
mitmdump -p 8080

# 保存流量
mitmdump -p 8080 -w traffic.flow
```

### 脚本示例：自动修改响应

```python
# addon.py
from mitmproxy import http

def response(flow: http.HTTPFlow):
    """自动修改指定接口的响应"""
    if "/api/user" in flow.request.url:
        # 修改响应状态码
        flow.response.status_code = 200
        # 修改响应内容
        flow.response.text = '{"name": "mock_user", "id": 999}'

def request(flow: http.HTTPFlow):
    """自动修改请求参数"""
    if "/api/login" in flow.request.url:
        # 添加请求头
        flow.request.headers["X-Test"] = "true"
```

```bash
# 使用脚本启动
mitmdump -p 8080 -s addon.py
```

## HTTPS 抓包原理

```
客户端                    代理（Charles）                 服务器
  │                           │                           │
  │ ① 发起 HTTPS 请求        │                           │
  │ ───────────────────────→ │                           │
  │                           │                           │
  │ ② 返回代理自签证书        │                           │
  │ ←─────────────────────── │                           │
  │ （客户端需信任该证书）     │ ③ 代替客户端与服务器建连  │
  │                           │ ───────────────────────→ │
  │                           │                           │
  │                           │ ④ 服务器返回真实证书       │
  │                           │ ←─────────────────────── │
  │                           │                           │
  │ ⑤ 客户端↔代理 加密通信    │ ⑥ 代理↔服务器 加密通信    │
  │                           │                           │
  │       代理可解密查看明文   │                           │
```

**本质**：中间人攻击（MITM），代理作为中间人，与客户端和服务器各建一条 TLS 连接，因此能解密查看明文。

**安装证书**：客户端需信任代理的根证书，否则浏览器会报证书不可信。

## 移动端抓包

### iOS

```
1. 设置 → Wi-Fi → 配置代理 → 手动
   服务器: 电脑IP  端口: 8888
2. Safari 访问 chls.pro/ssl → 安装证书
3. 设置 → 通用 → 关于 → 证书信任设置 → 启用 Charles 证书
```

### Android

```
1. Wi-Fi → 长按 → 修改网络 → 代理 → 手动
   主机名: 电脑IP  端口: 8888
2. 浏览器访问 chls.pro/ssl → 安装证书
3. Android 7+ 需额外配置（App 不信任用户证书）
```

### Android 7+ 抓不到 HTTPS？

Android 7.0 起，App 默认只信任系统级 CA 证书，不信任用户安装的证书。解决方案：

| 方案 | 说明 |
|------|------|
| Root 后装到系统证书区 | `adb push cert.pem /system/etc/security/cacerts/` |
| 修改 APK 的 network_security_config | 添加 `user` 证书信任 |
| 用模拟器（如 MuMu） | 某些模拟器自带 Root |

## 面试高频

### Charles 和 Wireshark 的区别？

| 维度 | Charles | Wireshark |
|------|---------|-----------|
| 工作层 | 应用层（HTTP/HTTPS） | 网络层（所有协议） |
| HTTPS | 可解密查看 | 看不到明文 |
| 操作方式 | 代理模式 | 网卡抓包 |
| 适合 | 接口测试、前端调试 | 网络排障、协议分析 |

### 抓包工具如何实现弱网模拟？

代理工具在转发请求时，人为增加延迟和限制带宽：
- 设置带宽上限（如 256 Kbps 模拟 3G）
- 增加延迟（如 +100ms）
- 设置丢包率

底层通过令牌桶算法或固定速率发送实现。

### 如何抓取 App 的接口数据？

1. 手机和电脑在同一局域网
2. 手机 Wi-Fi 代理指向电脑 IP + 端口
3. 安装并信任 HTTPS 证书
4. 操作 App，在电脑端查看请求/响应

---

## 一句话总结

> 抓包工具分两类：应用层代理型（Charles/Fiddler/mitmproxy）可解密 HTTPS、适合接口调试和 Mock；网络层抓包型（Wireshark/tcpdump）适合 TCP/DNS 等底层排障，HTTPS 抓包原理是中间人攻击需装证书，移动端注意 Android 7+ 的证书信任问题。

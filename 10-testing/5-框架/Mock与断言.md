# Mock与断言

Mock 隔离外部依赖让单测快稳；Stub 喂返回值，Mock 验证交互；Mock 用过头会测成"测 mock 本身"。

## 为什么要 Mock

隔离外部依赖（DB、第三方接口、下游服务），让单测**快、稳、不受环境影响**，只测本单元逻辑。

## Stub vs Mock

| 概念 | 侧重点 | 类比 |
|------|--------|------|
| Stub | **喂返回值**（"调它就返回 X"） | 替身演员，按剧本演 |
| Mock | **验证交互**（"某方法被调了几次、传了什么参数"） | 监视器，记录谁调了什么 |

## 工具

| 语言 | 工具 | 核心API |
|------|------|---------|
| Java | Mockito | `when().thenReturn()`、`verify()` |
| Python | `unittest.mock` / `pytest-mock` | `patch`、`MagicMock` |

## ⭐ 加分/易错

Mock 用过头会测成"测 mock 本身"——**核心业务逻辑别全 mock 掉**。集成/接口测试反而要用真实依赖或**契约测试**兜住 mock 与真实的偏差。

## 一句话总结

> Mock 隔离依赖让单测快稳；Stub 喂数据、Mock 验交互；别把核心逻辑全 mock 掉，集成测试要用真实依赖或契约测试兜底。

# UI自动化测试

Selenium 做 Web UI、Appium 做移动端；显式等待治 flaky；脚本自愈用多定位器/AI匹配兜底定位失败。

## Selenium

Web UI 自动化，通过 WebDriver 驱动浏览器；核心是**元素定位**（id/css/xpath）+ 操作 + 断言。

## Appium

移动端（Android/iOS）UI 自动化，一套 API 跨平台，底层各接原生框架。

## 稳定性关键

**显式等待**（等元素可见/可点击）而非硬 `sleep`；用**稳定的定位策略**（优先 id/语义化，少用脆弱的绝对 xpath）。

## ⭐ 加分/易错

UI 自动化最大痛点是**flaky（不稳定）**——异步渲染、动画、环境慢。对策：显式等待、重试、失败截图、Page Object 模式降耦合。项目里移动端 UI 巡检踩过这些坑（回 `kuaishou/03-kuaichat-ui.md`）。

## ⭐ 延伸：脚本自愈（Self-Healing Test）

AI 测开高频，百度 AI 测开 JD 明写"脚本自愈"。

**是什么**：UI 用例最脆的地方是**定位器**——前端一改（id 变了、层级动了），脚本就挂。自愈 = **定位失败时自动换一种方式找到元素、让用例继续跑**，而不是直接 fail。

**传统做法**：**多定位器兜底**——给一个元素配多个定位策略（id → name → css → 文本 → 相对位置），主定位失效自动降级到备用；再配失败重试。

**AI 版自愈**：失败时用**元素多维特征快照**（文本、属性、DOM 相对位置、甚至视觉截图）做相似度匹配，找到"最像原来那个"的元素继续；有的框架还会**自动把新定位器回写**进用例。

**扣回我的经验**：快手 KRunner 是 **Tags + Vision** 的自研框架（回 `kuaishou/03-kuaichat-ui.md`）——**视觉兜底**正是自愈的核心思想之一（标签定位失效时靠视觉找元素）。别硬吹"我做过完整自愈框架"，如实说"用过 Tags+Vision、理解自愈思路、能迁移"。

**❌ 易错**：自愈不是万能——它降低维护成本，但**可能掩盖真实 UI 缺陷**（元素真的没了却被"自愈"到别的元素）。所以自愈要配**告警**：自愈生效时记录并提示人工确认，别默默吞掉。

## 一句话总结

> UI 自动化用显式等待 + Page Object 治 flaky；脚本自愈 = 定位失败时自动换策略（传统多定位器兜底/AI 特征匹配），但要配告警防掩盖真缺陷。

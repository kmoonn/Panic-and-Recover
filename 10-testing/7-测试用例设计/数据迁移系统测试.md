# 数据迁移系统测试用例

## 面试题：如何测试一个数据迁移系统

数据迁移 = 把数据从源（旧库/旧系统）搬到目标（新库/新系统），核心诉求是 **「一条不多、一条不少、一条不错」**：不能丢数据、不能重复、不能改变语义，且往往要求**可回滚、可断点续传、不长时间停服**。核心方法：**按「迁移前校验 → 迁移中执行 → 迁移后核对 → 切换回滚」四阶段拆解，重点盯数据一致性、完整性、幂等与回滚**。

---

## 迁移流程

```
迁移前评估校验 → 迁移执行（全量/增量）→ 迁移后数据核对 → 业务切换 → 回滚预案
      │              │                      │              │           │
      ▼              ▼                      ▼              ▼           ▼
   前置校验环节     执行环节               核对环节        切换环节    回滚环节
```

---

## 一、迁移前校验环节

| 测试点 | 正常 | 异常/边界 |
|---|---|---|
| 源数据探查 | 源表结构/总量/编码正确识别 | 源有脏数据/空值/非法编码？ |
| 表结构映射 | 源字段 → 目标字段映射正确 | 字段类型不兼容（varchar→int）？长度截断？ |
| 目标环境 | 目标库表已建、权限足够 | 目标已有数据（覆盖/追加/报错）？ |
| 迁移范围 | 按配置圈定要迁的表/时间段 | 范围为空？范围超大？ |
| 依赖关系 | 主外键、关联表按序迁移 | 外键先于主键迁入导致约束失败？ |

---

## 二、迁移执行环节

| 测试点 | 正常 | 异常/边界 |
|---|---|---|
| 全量迁移 | 全部数据成功搬迁 | 千万级大表内存/超时？ |
| 增量迁移 | 只迁变更数据（基于时间戳/binlog） | 迁移期间源又有新写入？ |
| 断点续传 ⭐ | 中断后从断点继续，不重头 | 迁到一半宕机 → 重跑是否重复/丢失？ |
| 幂等性 ⭐ | 重复执行结果一致 | 同一批数据迁两次 → 是否重复插入？ |
| 类型转换 | 日期/数字/编码正确转换 | 时区差异？浮点精度丢失？中文乱码？ |
| 性能 | 大批量批处理高效 | 迁移拖垮源库/目标库？锁表影响线上？ |

---

## 三、迁移后核对环节（迁移核心）

| 测试点 | 校验方法 |
|---|---|
| **总量一致** | 源表行数 = 目标表行数（分表分区分别核对） |
| **抽样比对** | 随机抽样逐字段比对内容一致 |
| **全量校验** | 关键字段做 checksum/hash 比对（如按主键排序求 MD5） |
| **金额/数值汇总** | 源与目标 SUM/COUNT 汇总值一致（对账思路） |
| **无重复** | 目标表主键/唯一键无重复 |
| **无丢失** | 源有目标无的差集为空 |
| **关联完整** | 外键关联可正常 JOIN，无孤儿数据 |

> **一致性校验是迁移的验收核心**：总量比对（快，粗筛）+ 抽样比对（中）+ checksum 全量比对（准，慢），按数据量和重要性组合使用。

---

## 四、业务切换与回滚环节

| 测试点 | 正常 | 异常/边界 |
|---|---|---|
| 停机窗口 | 停服迁移在窗口内完成 | 超时未完成如何处理？ |
| 不停机迁移 | 双写/灰度切流平滑过渡 | 双写期间新老库不一致？ |
| 数据回切 | 校验不通过可回滚到源 | 已切流后发现问题能否回滚？ |
| 回滚完整性 ⭐ | 回滚后源数据未被污染 | 迁移过程改动了源数据？ |
| 灰度切换 | 按比例切流验证 | 部分切流时新老数据混用一致性？ |

---

## 五、异常与容错

| 场景 | 预期 |
|---|---|
| 迁移中断网/宕机 | 断点续传，不丢不重 |
| 目标库写入失败 | 记录失败批次、重试或告警 |
| 源数据边迁边变 | 增量补迁/双写保证最终一致 |
| 脏数据/非法数据 | 记录到错误表跳过，不中断整体 |
| 迁移超时 | 分批限流，不拖垮线上库 |

---

## 六、安全与合规

| 测试点 | 说明 |
|---|---|
| 敏感字段脱敏 | 手机号/身份证/密码迁移时是否按需脱敏 |
| 传输加密 | 跨网络迁移是否加密传输 |
| 权限最小化 | 迁移账号权限是否越权 |
| 审计日志 | 迁移操作是否可追溯（谁迁了什么） |

---

## 七、兼容性与性能

| 维度 | 测试点 |
|---|---|
| 异构数据源 | MySQL→PG、Oracle→MySQL、关系库→NoSQL 类型兼容 |
| 数据量级 | 小表/百万/千万/亿级不同量级 |
| 性能 | 迁移吞吐（行/秒）、对源库线上影响、目标库写入压力 |
| 稳定性 | 长时间迁移不 OOM、不丢连接 |

---

## 用例设计方法总结

| 方法 | 应用 |
|---|---|
| **等价类划分** | 数据量级（空/少/海量）、迁移模式（全量/增量）、数据类型 |
| **边界值分析** | 字段长度上界、超大表、时间范围边界、批处理大小 |
| **状态迁移** | 迁移状态（未迁→迁移中→已迁→已核对→已切换/已回滚） |
| **错误推测** | 中断续传、重复执行、脏数据、边迁边变、类型丢精度 |
| **对账思想** | 总量/汇总/checksum 三级校验（借鉴金融对账） |

---

## 一句话总结

> 数据迁移测试按「前校验→执行→核对→切换回滚」四阶段设计，核心是**数据一致性**——不多（无重复）、不少（无丢失）、不错（内容/类型/编码一致），用**总量比对+抽样+checksum 三级校验**验收；重点风险是**断点续传与幂等（中断重跑不丢不重）、边迁边变的增量一致、类型转换丢精度/乱码、可回滚不污染源**，辅以脱敏合规与大数据量性能测试。

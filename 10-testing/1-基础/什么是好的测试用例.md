# 什么是好的测试用例

> 面试高频观点题：「你觉得什么样的测试用例是好用例？」考察你有没有质量标准，而不是会不会写步骤。用例要素/优先级见[用例要素与优先级](用例要素与优先级.md)，本篇侧重**评判标准**。

## 一句话总结

> 好用例不是写得多、写得细，而是**目标明确、可执行、断言有效、能发现真实问题、还能复用**——一条用例应该清楚"测什么、怎么测、期望什么"，并且换个人也能照着跑出一致结果。

## 好用例的六个标准

| 标准 | 含义 | 反例 |
|---|---|---|
| **目标明确** | 一条用例只验证一个点，标题就能看出测什么 | "测试登录功能"——太笼统，说不清测哪条路径 |
| **可执行** | 前置、步骤、数据齐全，换个人也能跑出一致结果 | 缺测试数据/前置条件，只有他自己知道怎么跑 |
| **预期明确 + 断言有效** | 有确定的预期结果，且断言真正校验业务，而非"返回 200" | 断言只判 HTTP 200，业务错了也算过（见[断言有效性](断言有效性.md)） |
| **可复现** | 不依赖偶然环境/脏数据，每次结果稳定 | 依赖上一条用例的残留数据，单独跑就挂 |
| **有发现问题的价值** | 覆盖真实风险（异常/边界/并发），而非只堆主流程 | 十条用例全是 Happy Path，异常一条没有 |
| **可维护/可复用** | 结构清晰、低耦合，需求变了改动小，能进回归 | 用例互相依赖、写死环境，一改就连锁崩 |

## 好用例集合(用例设计)还要看

单条用例好还不够，一**组**用例的质量看：

- **覆盖度**：正常 + 异常 + 边界 + 参数校验 + 风险点是否都覆盖（等价类、边界值、状态迁移、错误推测）。
- **无冗余**：不同用例不重复测同一逻辑，等价类内取代表值即可。
- **有优先级**：P0 核心主流程先行，冒烟/回归可挑出来。
- **正交**：多因素组合用正交实验裁剪，而非全排列。

## 判断口诀

```
一条好用例问三句：
  测什么？   → 目标单一、标题清楚
  怎么测？   → 前置/步骤/数据齐全、可复现
  期望什么？ → 预期明确、断言校验业务、能发现真实问题
```

## 八股速记

**Q：什么样的测试用例是好用例？⭐**

- 单条：**目标明确、可执行可复现、预期明确断言有效、能发现真实问题、可维护复用**。
- 一组：**覆盖全（正常/异常/边界）、无冗余、有优先级、正交裁剪**。

**⭐ 加分/易错**：
- 强调**断言有效性**——"返回 200 就算过"是最典型的坏用例（业务错了照样漏），好断言要校验业务预期。
- 强调**可复现/低耦合**——用例间互相依赖、写死数据是回归自动化的大坑（呼应讯飞接口自动化纳入版本发布前流程）。
- 用例不是越多越好，是**查得准**——呼应[AI用例生成评估](../../13-ai/7-其他/4-AI用例生成评估.md)的"有效命中率"。

# 常见测试方法与场景

## Q: 你知道常见的测试方法有哪些？可以想到哪些场景？

按**测试目的**分类，每种方法对应不同的质量维度和典型场景：

---

## 一、功能测试

> 验证"软件能不能做对的事"——最基础的测试维度。

| 子类型 | 关注点 | 典型场景 |
|--------|--------|---------|
| 正常流程 | Happy Path 是否走通 | 登录成功、下单成功 |
| 异常流程 | 错误输入/异常路径 | 密码错误、库存不足 |
| 边界值 | 临界点行为 | 金额 = 0、文件大小 = 上限 |
| 等价类 | 每类输入选代表 | 年龄输入：负数/0~150/超150 |
| 状态迁移 | 状态切换是否正确 | 订单：待支付→已支付→已发货 |

---

## 二、性能测试

> 验证"软件在压力下还能不能用"。

| 子类型 | 关注点 | 典型场景 |
|--------|--------|---------|
| 负载测试 | 预期负载下的表现 | 1000 并发用户，响应 < 500ms |
| 压力测试 | 超出负载时的表现 | 5 倍日常流量，系统是否降级而非崩溃 |
| 稳定性测试 | 长时间运行的可靠性 | 连续跑 72 小时，内存是否泄漏 |
| 并发测试 | 同时操作的一致性 | 100 人同时抢同一张票，不超卖 |
| 基准测试 | 单次请求的基线性能 | 单接口 P99 延迟 < 200ms |

**常见指标**：QPS、TPS、响应时间（P50/P99）、错误率、CPU/内存占用

---

## 三、安全测试

> 验证"软件会不会被攻击、数据会不会泄露"。

| 子类型 | 关注点 | 典型场景 |
|--------|--------|---------|
| 注入攻击 | SQL/命令/XXE 注入 | 输入 `' OR 1=1 --` 是否绕过登录 |
| XSS | 跨站脚本 | 评论区输入 `<script>alert(1)</script>` 是否被执行 |
| CSRF | 跨站请求伪造 | 伪造请求修改用户密码 |
| 越权 | 水平/垂直越权 | 用户 A 能否访问用户 B 的数据 |
| 认证鉴权 | 登录态安全 | Token 过期后是否仍可访问、密码明文存储 |
| 敏感数据 | 数据泄露 | 接口返回是否含手机号/身份证等脱敏字段 |
| 暴力破解 | 账户安全 | 登录失败 5 次后是否限制/验证码 |

---

## 四、兼容性测试

> 验证"软件在不同环境下都能不能用"。

| 维度 | 典型场景 |
|------|---------|
| 浏览器 | Chrome / Firefox / Safari / Edge，各版本表现一致 |
| 操作系统 | Windows / macOS / Linux / iOS / Android |
| 分辨率 | 1920×1080 / 1366×768 / 移动端适配 |
| 网络环境 | WiFi / 4G / 5G / 弱网 / 离线 |
| 设备型号 | 不同品牌手机、不同屏幕尺寸 |
| 软件版本 | 旧版 API 是否向后兼容 |

---

## 五、异常/容错测试

> 验证"出了问题软件能不能优雅处理"。

| 场景 | 测试点 | 预期 |
|------|--------|------|
| 网络异常 | 断网/超时/抖动 | 提示"网络异常"，不崩溃，可重试 |
| 服务依赖失败 | 下游接口超时/500 | 降级处理/兜底数据，不雪崩 |
| 数据异常 | 空数据/脏数据/格式错误 | 不崩溃，友好提示 |
| 资源耗尽 | 磁盘满/内存不足/连接池耗尽 | 优雅降级，不丢失数据 |
| 并发冲突 | 多人同时修改同一条数据 | 不脏写，乐观锁/悲观锁生效 |
| 超大输入 | 超长字符串/超大文件 | 不 OOM，有大小限制 |
| 权限异常 | 未登录/过期/角色不足 | 拦截并提示，不暴露内部信息 |

---

## 六、其他测试方法

| 方法 | 关注点 | 典型场景 |
|------|--------|---------|
| 易用性测试 | 操作是否直观、体验是否友好 | 新用户能否 30 秒内完成注册 |
| 可靠性测试 | 故障恢复能力 | 主库宕机后从库能否自动接管 |
| 本地化/国际化 | 多语言/多时区/多货币 | 日期格式、货币符号、RTL 布局 |
| 可访问性测试 | 无障碍支持 | 屏幕阅读器、键盘导航、色盲适配 |
| 回归测试 | 修改后原有功能是否受影响 | 发版前跑全量自动化回归 |
| 冒烟测试 | 核心流程是否可用 | 新版本部署后先验证主流程能跑通 |
| 探索式测试 | 不预设用例，凭经验自由探索 | 发现用例设计时未考虑的边界 |

---

## 方法 vs 场景对照

```
功能测试 → 登录、下单、支付
性能测试 → 秒杀压测、接口延迟、长时间运行
安全测试 → SQL注入、XSS、越权、Token过期
兼容测试 → 多浏览器、多设备、多网络
异常测试 → 断网、超时、脏数据、并发冲突
         ↘  还有：易用性、可靠性、国际化、无障碍...
```

## 一句话总结

> 常见测试方法按目的分：功能（做对的事）、性能（压力下还能用）、安全（不被攻击）、兼容（各环境都能用）、异常容错（出问题能优雅处理），面试中要能对每个方法举出具体场景。

# 游戏测试开发做什么

> 面试认知题：投游戏公司测开岗常被问「你了解游戏测开和普通业务测开的区别吗？」。考察你**是否理解游戏这个业务形态的特殊性**，而不是把它当普通 CRUD 系统测。

## 一句话总结

> 游戏测开 = 测试思维 + 游戏领域知识 + 工具研发能力：既要保障**功能/性能/兼容/安全**这些通用质量，又要应对游戏独有的**帧同步/状态同步、防外挂、数值平衡、海量并发、多端一致、随机性验证**，核心产出是**自动化测试工具、机器人、性能监控体系**，而非只点点点。

## 游戏测开 vs 普通业务测开

| 维度 | 普通业务测开 | 游戏测开 |
|---|---|---|
| 被测对象 | Web/API/后台系统 | 客户端（引擎）+ 游戏服务器 + 匹配/对战/结算 |
| 核心质量 | 功能正确、接口稳定 | 帧同步一致性、手感/延迟、数值平衡、防作弊 |
| 实时性 | 请求-响应即可 | 强实时（UDP + 帧同步），延迟/丢包致命 |
| 状态 | 无状态/短事务 | 长连接、有状态战局、需断线重连 |
| 随机性 | 逻辑确定 | 掉落/暴击/匹配含随机，需按概率统计验证 |
| 自动化难点 | UI/接口自动化成熟 | 画面/操作难自动化，需**游戏机器人+图像识别** |

## 游戏测开的主要工作

| 方向 | 具体做什么 |
|---|---|
| **功能与玩法测试** | 任务、战斗、背包、商城、社交、活动的逻辑正确性 |
| **自动化工具研发** ⭐ | 写游戏机器人（自动打怪/组队/对战）、录制回放、图像识别定位 UI、协议层自动化 |
| **性能测试** | 客户端帧率(FPS)、内存/显存、发热耗电；服务器承载(万人同服)、匹配延迟、结算 TPS |
| **兼容性测试** | 海量机型/分辨率/GPU/OS 版本适配，机型云真机农场 |
| **弱网/断线测试** | 模拟丢包/高延迟/切网/断线重连，验证帧同步与状态恢复 |
| **防外挂/安全** | 加速器、透视、自动瞄准检测；协议加密、反作弊验证 |
| **数值与平衡验证** | 用脚本模拟大量对局，统计掉落率、胜率、经济系统是否平衡 |
| **服务器压测** | 模拟海量玩家并发登录/匹配/对战/广播，找容量拐点 |

## 游戏测开独有的技术点（加分）

- **帧同步一致性**：所有客户端按相同输入算出相同结果，测「不同步(desync)」——同一操作多端结果必须一致。
- **随机性验证**：掉落/暴击不能用单次断言，要**跑大样本按概率分布统计**（如暴击率 30%，跑一万次看是否收敛）。
- **游戏机器人/AI 挂机测试**：用机器人自动跑主线、刷副本，做 monkey 测试和长时间稳定性（找内存泄漏/崩溃）。
- **弱网+断线重连**：游戏走 UDP + 应用层可靠（见[游戏为什么用UDP](../../04-network/2-传输层/游戏为什么用UDP.md)），重点测丢包/乱序/重连后状态一致。
- **多端一致性**：iOS/Android/PC/主机同一战局表现一致。

## 我能迁移过去的能力（结合经历答）

面试时把**已有能力映射到游戏场景**，证明可迁移：

- **UI 自动化 + 图像识别**：快聊移动端 UI 自动化巡检、Midscene 视觉定位 → 游戏画面/UI 自动化天然契合。
- **接口/协议自动化**：讯飞接口自动化、字节 API Testing Agent → 游戏服务器协议层测试同理。
- **性能压测**：JMeter 压测、QPS/TPS 认知 → 游戏服务器万人并发压测。
- **AI 造数/工具研发**：造数 Skill → 游戏机器人、批量对局造数据。
- **网络底层**：UDP/丢包/弱网知识 → 游戏弱网测试。

## 八股速记

**Q：了解游戏测开做什么吗？⭐**

- 通用质量（功能/性能/兼容/安全）**＋** 游戏独有：**帧同步一致性、弱网断线重连、防外挂、数值平衡、多端一致、随机性统计验证**。
- 核心不是点点点，而是**研发自动化工具**——游戏机器人、图像识别 UI 自动化、协议层自动化、服务器压测。

**⭐ 加分/易错**：
- 强调**随机性要按概率大样本统计**（不能单次断言）、**帧同步测 desync**——这两点最能体现「懂游戏」。
- 主动把已有能力迁移过去（UI 自动化→游戏画面、协议自动化→游戏服务器、UDP 知识→弱网测试），证明不是零基础。

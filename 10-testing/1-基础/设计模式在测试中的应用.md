# 设计模式在测试中的应用

面测开，设计模式不用背全，但要能说清自动化框架/测试代码里哪些地方用了模式，这是区别于"只会写脚本"的加分点。

## 六大落地场景

- **Page Object（UI 自动化核心）**：把页面元素和操作封装成对象，用例只调页面方法，UI 变了只改 Page 类——降耦合、治 flaky（呼应快手 Kuaichat UI 自动化）。本质是**封装 + 单一职责**。
- **Builder 造测试数据**：用建造者/工厂 + 默认值快速构造请求/实体，用例只覆盖关心字段，可读性高（呼应建造者模式 + 字节 AI 数据生成造数）。
- **策略模式管多环境/多用例**：不同环境配置、不同断言策略、不同数据源用策略切换，消除 if/else（呼应策略模式）。
- **工厂产出测试组件**：按类型产出 driver / client / mock，测试代码不关心具体构造。
- **代理/Mock**：Mock 框架底层就是动态代理生成假对象（呼应代理模式 + Spring Mock）。
- **模板方法组织用例流程**：`setup → 执行 → 断言 → teardown` 骨架固定、步骤可变（呼应模板方法）。

## 一句话总结
> Page Object、Builder 造数、策略管环境、Mock 靠代理、模板方法组织用例——设计模式在测试中的落地比背定义更重要。

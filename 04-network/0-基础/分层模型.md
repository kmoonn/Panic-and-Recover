# 网络分层模型

## Q1: OSI 七层模型是什么?

| 层号 | 层名 | 职责 | 常见协议/设备 | 数据单位 |
|------|------|------|--------------|---------|
| 7 | **应用层** | 为用户提供网络服务接口 | HTTP, FTP, SMTP, DNS, SSH | 报文 (Message) |
| 6 | **表示层** | 数据格式转换、编解码、加解密、压缩 | JPEG, ASCII, SSL/TLS | 报文 |
| 5 | **会话层** | 建立/管理/终止应用程序间的会话 | RPC, SQL, NetBIOS | 报文 |
| 4 | **传输层** | 端到端可靠传输、流量控制、差错控制 | TCP, UDP | 段 (Segment) |
| 3 | **网络层** | 路由选择、寻址、拥塞控制 | IP, ICMP, OSPF, BGP | 包 (Packet) |
| 2 | **数据链路层** | 帧编码、MAC 寻址、差错检测/纠正 | Ethernet, PPP, VLAN | 帧 (Frame) |
| 1 | **物理层** | 透明传输比特流，定义电气/机械特性 | 铜缆、光纤、集线器 | 比特 (Bit) |

### 记忆口诀

```

           应表会传网数物 (倒过来读: "应表会传网数物")
```

## Q2: TCP/IP 四层模型是什么?

| 层号 | 层名 | 对应 OSI | 常见协议 |
|------|------|---------|---------|
| 4 | **应用层** | 应用层+表示层+会话层 | HTTP, FTP, DNS, SMTP, SSH |
| 3 | **传输层** | 传输层 | TCP, UDP |
| 2 | **网际层** | 网络层 | IP, ICMP, ARP |
| 1 | **网络接口层** | 数据链路层+物理层 | Ethernet, PPP, Wi-Fi |

> TCP/IP 模型将 OSI 的上三层合并为应用层，下两层合并为网络接口层，更加务实。

---

## Q3: TCP/IP 五层模型是什么? (教学最常用)

五层模型是 OSI 和 TCP/IP 的折中，**既保持了层次清晰，又符合实际协议栈**，是计算机网络教学中最常用的模型。

| 层号 | 层名 | 职责 | 常见协议/设备 | 数据单位 |
|------|------|------|--------------|---------|
| 5 | **应用层** | 为用户提供服务 | HTTP, DNS, FTP, SMTP | 报文 |
| 4 | **传输层** | 端到端传输 | TCP, UDP | 段 |
| 3 | **网络层** | 路由寻址 | IP, ICMP, ARP | 包 |
| 2 | **数据链路层** | 帧传输、MAC 寻址 | Ethernet, PPP, 交换机 | 帧 |
| 1 | **物理层** | 比特流传输 | 集线器、中继器、网线 | 比特 |

## Q5: 每层的职责与常见协议详解

### 应用层 (Layer 5/7)

| 协议 | 端口 | 用途 |
|------|------|------|
| HTTP | 80 | Web 页面传输 |
| HTTPS | 443 | 加密的 Web 传输 |
| DNS | 53 | 域名解析 |
| FTP | 20/21 | 文件传输 |
| SMTP | 25 | 发送邮件 |
| SSH | 22 | 安全远程登录 |

### 传输层 (Layer 4)

| 协议 | 特点 |
|------|------|
| TCP | 面向连接、可靠传输、流量控制、拥塞控制 |
| UDP | 无连接、不可靠、低延迟、适合实时应用 |

### 网络层 (Layer 3)

| 协议 | 用途 |
|------|------|
| IP | 寻址和路由 |
| ICMP | 差错报告 (ping) |
| ARP | IP → MAC 地址解析 |
| OSPF/BGP | 路由协议 |

### 数据链路层 (Layer 2)

| 协议/设备 | 说明 |
|-----------|------|
| Ethernet | 最常见的局域网技术 |
| MAC 地址 | 数据链路层寻址 |
| 交换机 | 基于MAC转发帧 |

### 物理层 (Layer 1)

| 设备/介质 | 说明 |
|-----------|------|
| 集线器 (Hub) | 广播信号到所有端口 |
| 中继器 (Repeater) | 信号放大再生 |
| 双绞线/光纤 | 传输介质 |

## Q6: 为什么 OSI 失败了，TCP/IP 却成功了?

这是面试经典问题！

| 对比维度 | OSI 七层 | TCP/IP |
|----------|---------|--------|
| **设计理念** | 先有理论模型，再有实现 | 先有实现 (ARPANET)，再总结模型 |
| **层次划分** | 过于理想化，表示层/会话层实际很少独立 | 务实，合并功能相近的层 |
| **协议实现** | 协议制定缓慢，实现复杂 | 协议简单高效，广泛实现 |
| **推动力量** | 官方标准化组织 (ISO) | 实践驱动的社区 + 互联网爆发 |
| **市场因素** | 政府主导，商业落地慢 | 学术+商业共同推动，快速迭代 |
| **核心问题** | **过度设计** — 功能划分太细，实现复杂 | **实用主义** — 只分真正需要的层 |

### 总结原因

```
OSI 失败:
  1. 理论先行，脱离实践 — "完美但不实用"
  2. 会话层/表示层在实际中几乎空置
  3. 标准化过程缓慢，错失互联网发展窗口
  4. 实现复杂，性能差

TCP/IP 成功:
  1. 实践先行，简洁高效 — "不完美但好用"
  2. 与 Unix/BSD 深度绑定，随操作系统广泛部署
  3. 乘着互联网爆发的东风
  4. 核心协议 (IP/TCP) 设计优秀，经受住了规模考验
```

## Q7: 数据封装过程是什么?

每一层将上层数据加上自己的头部 (和可能的尾部)，形成本层的协议数据单元 (PDU)。

```
应用层:    数据 (Data)
            │
            ▼ 加上 TCP/UDP 头
传输层:    [TCP Header | Data]       → 段 (Segment)
            │
            ▼ 加上 IP 头
网络层:    [IP Header | TCP Header | Data]  → 包 (Packet)
            │
            ▼ 加上 MAC 头 + FCS 尾
数据链路层: [MAC Header | IP Header | TCP Header | Data | FCS]  → 帧 (Frame)
            │
            ▼ 转为比特流
物理层:    0101010110...             → 比特 (Bit)
```

### 封装要点

| 层 | 添加的头部 | 包含的关键信息 |
|----|-----------|--------------|
| 传输层 | TCP/UDP Header | 源端口、目的端口、序列号、校验和 |
| 网络层 | IP Header | 源 IP、目的 IP、TTL、协议号 |
| 数据链路层 | MAC Header + FCS | 源 MAC、目的 MAC、帧校验序列 |

> **解封装**是逆过程：每层剥离自己的头部，将剩余部分交给上层。

## Q8: 为什么要分层?

| 优势 | 说明 | 类比 |
|------|------|------|
| **各层独立** | 每层只需调用下层接口，无需关心下层实现 | 调用 API 不关心内部实现 |
| **灵活可替换** | 每层可独立升级替换，不影响其他层 | 换硬盘不影响操作系统 |
| **简化问题** | 复杂问题分解为多个简单子问题 | 分治思想 |
| **标准化** | 每层接口标准化，不同厂商可互操作 | USB 标准让任何设备都能接入 |

### 软件开发类比

```
网络分层           软件分层
应用层         →    Controller 层 (接口)
传输层         →    Service 层 (业务)
网络层         →    Repository 层 (数据)
数据链路层     →    驱动层
物理层         →    硬件
```

## 一句话总结

**OSI 七层过于理想而失败，TCP/IP 四层因务实而成功，教学最常用五层折中模型；每层封装自己的头部，下层为上层提供服务，分层的核心价值是解耦、灵活、简化、标准化。**

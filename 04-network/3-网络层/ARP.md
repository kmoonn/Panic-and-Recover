# ARP 地址解析协议

## 什么是 ARP？

ARP（Address Resolution Protocol，地址解析协议）用于将**网络层的 IP 地址**映射为**数据链路层的 MAC 地址**。在以太网中，数据帧必须使用 MAC 地址才能在链路层传输，因此发送数据前必须通过 ARP 获取目标的 MAC 地址。

```
网络层：  知道目标 IP 地址 ──→ 需要知道目标 MAC 地址 ──→ 链路层才能封装帧
                ↑                                           ↑
                └───────────── ARP 协议 ─────────────────────┘
```

## ARP 的工作流程

以主机 A（IP: 192.168.1.1）向主机 B（IP: 192.168.1.2）发送数据为例：

```
步骤1：查询 ARP 缓存
  A 查本地 ARP 缓存表 → 有则直接使用 MAC 地址，跳到步骤5

步骤2：广播 ARP 请求
  A 向同链路所有主机广播：
  "谁有 192.168.1.2？请告诉 192.168.1.1，我的 MAC 是 AA:AA:AA:AA:AA:AA"
  ┌──────────────────────────────────────────────────┐
  │ 以太网帧：目标 MAC = FF:FF:FF:FF:FF:FF（广播）  │
  │ ARP 请求：发送方 IP=192.168.1.1, MAC=AA:AA:...   │
  │           目标 IP=192.168.1.2, MAC=00:00:...（待填）│
  └──────────────────────────────────────────────────┘

步骤3：目标主机单播 ARP 应答
  B 收到后发现自己的 IP 匹配，向 A 单播回应：
  "192.168.1.2 的 MAC 是 BB:BB:BB:BB:BB:BB"

步骤4：更新 ARP 缓存
  A 收到应答，将 192.168.1.2 → BB:BB:BB:BB:BB:BB 存入缓存

步骤5：正常通信
  A 使用 B 的 MAC 地址封装以太网帧，发送数据
```

### 跨网段通信时的 ARP

当目标 IP 不在同一子网时，主机不会直接 ARP 目标的 IP，而是 ARP **默认网关**的 IP：

```
A(192.168.1.1) → B(10.0.0.1)

1. A 发现 B 不在同一子网
2. A ARP 请求：谁有网关 192.168.1.254 的 MAC？
3. 网关回应自己的 MAC
4. A 将数据帧发送给网关，由网关转发
```

## ARP 缓存表

ARP 缓存表存储了 IP → MAC 的映射关系，避免每次通信都要广播请求。

```bash
# 查看 ARP 缓存
$ arp -a
? (192.168.1.1) at aa:bb:cc:dd:ee:ff on eth0
? (192.168.1.254) at 11:22:33:44:55:66 on eth0

# Linux 下查看
$ ip neigh show
192.168.1.1 dev eth0 lladdr aa:bb:cc:dd:ee:ff REACHABLE
```

- 缓存条目有**生存时间**（通常 20~1200 秒），超时后需重新 ARP
- **静态条目**：手动配置，不会过期（但不推荐，网络变化时需手动更新）

## ARP 欺骗/攻击

### 原理

ARP 协议是**无状态、无认证**的——主机收到 ARP 应答后会无条件更新缓存，不验证应答来源的真实性。攻击者可利用这一点发送伪造的 ARP 应答。

```
攻击场景：中间人攻击

正常：A ────────────────── B
攻击：A ──→ 攻击者(C) ──→ B

1. 攻击者 C 向 A 发送伪造 ARP 应答："192.168.1.2 的 MAC 是 CC:CC:CC:CC:CC:CC"
2. C 向 B 发送伪造 ARP 应答："192.168.1.1 的 MAC 是 CC:CC:CC:CC:CC:CC"
3. A 和 B 的 ARP 缓存被篡改，数据都经过 C
4. C 可窃听、篡改或丢弃数据
```

### 防御手段

| 方法 | 说明 |
|------|------|
| 静态 ARP 绑定 | 手动绑定 IP-MAC 映射，不接收动态更新 |
| DAI（Dynamic ARP Inspection） | 交换机验证 ARP 报文合法性 |
| 802.1X 端口认证 | 只允许认证设备接入 |
| ARP 监控工具 | 检测 ARP 异常，及时告警 |

## RARP（反向 ARP）

- **功能**：MAC → IP，与 ARP 方向相反
- **用途**：早期无盘工作站通过 MAC 地址获取自己的 IP 地址
- **现状**：已被 **DHCP** 完全取代，基本不再使用

## 免费 ARP（Gratuitous ARP）

免费 ARP 是一种特殊的 ARP 请求，发送者请求的是**自己的 IP 地址**对应的 MAC。

```
主机 A 广播："谁有 192.168.1.1？告诉 192.168.1.1，我的 MAC 是 AA:AA:AA:AA:AA:AA"
            ↑ 请求自己的 IP
```

### 两大用途

| 用途 | 说明 |
|------|------|
| **IP 冲突检测** | 如果收到应答，说明同一网络中有其他主机使用了相同 IP |
| **更新交换机 MAC 表** | 通知交换机更新端口与 MAC 的映射（IP 漂移、HA 切换场景） |

典型场景：服务器主备切换时，新主发送免费 ARP，交换机立即将流量转发到新主。

## 面试高频：ARP 的工作原理

**回答要点**：
1. 发送数据时先查 ARP 缓存，有则直接使用
2. 缓存没有则广播 ARP 请求（目标 MAC = FF:FF:FF:FF:FF:FF）
3. 目标主机单播 ARP 应答（携带自己的 MAC 地址）
4. 发送方收到应答后更新缓存，后续直接使用
5. 跨网段时 ARP 的是网关的 MAC，而非目标主机的 MAC
6. ARP 缓存有生存时间，超时需重新解析

## 一句话总结

ARP 协议通过"广播请求、单播应答"的方式将 IP 地址解析为 MAC 地址，是网络层到链路层通信的桥梁；但其无认证机制也带来了 ARP 欺骗的安全风险。

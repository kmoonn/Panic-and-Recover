# HTTP vs HTTPS

- 端口号
  - HTTP：默认端口 80
  - HTTPS：默认端口 443
- URL前缀
- 安全性
  - HTTP基于TCP、明文传输、无法校验双方身份、数据易被窃听、篡改、冒充
  - HTTPS = HTTP + TLS/SSL，在应用层和传输层之间加了加密层，加密传输、安全可靠
- 资源消耗
  - HTTP需要身份校验、加解密
- 连接过程
  - HTTP：TCP 三次握手后直接通信
  - HTTPS：TCP 三次握手 → TLS 握手 → 再开始 HTTP 通信
- 证书
  - HTTP：不需要证书
  - HTTPS：需要 CA 颁发的数字证书，用于身份认证
- SEO
  - HTTP：浏览器标记为不安全
  - HTTPS：显示小锁图标，有利于 SEO 排名


## 八股速记

**Q：HTTP vs HTTPS / TLS 握手**

- **HTTPS = HTTP + TLS/SSL**，在传输层之上加密。解决明文传输的**窃听、篡改、冒充**三大问题。
- **加密方式**：**非对称加密协商出对称密钥**（RSA/ECDHE），之后用**对称加密**传数据（快）。
- **证书**：服务端出示 CA 签发的证书证明身份，客户端用 CA 公钥验签，防中间人。
- **TLS 握手（简化）**：Client Hello（支持的加密套件+随机数）→ Server Hello（选定套件+证书+随机数）→ 客户端验证证书、生成 pre-master、用服务端公钥加密发回 → 双方用三个随机数算出对称密钥 → 加密通信。

⭐ **加分/易错**：默认端口 HTTP 80、HTTPS 443；HTTPS 只保证**传输链路**安全，服务端存储、日志泄漏等它管不了。

## 一句话总结

> HTTPS在HTTP基础上增加TLS加密和CA证书认证，端口443，更安全但握手开销更大。

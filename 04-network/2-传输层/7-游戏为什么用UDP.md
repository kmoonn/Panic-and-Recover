# 游戏为什么用 UDP

## 一句话总结

> 游戏（尤其 FPS/MOBA 等实时对战）用 UDP，是因为**实时性 > 可靠性**：晚到的状态包已经过期，TCP 的重传和队头阻塞只会让游戏更卡；UDP 丢包就丢，由应用层做「只补关键数据、旧包直接丢弃」的可靠性策略。

## 哪些游戏场景用 UDP

| 游戏类型 | 传输 | 说明 |
| --- | --- | --- |
| FPS 射击（CS、吃鸡） | UDP | 位置/朝向高频同步，丢一帧无所谓，延迟致命 |
| MOBA（LOL、王者） | UDP | 帧同步/状态同步，要求低延迟 |
| 实时竞速、体育 | UDP | 位置插值，允许丢包 |
| MMORPG | UDP 为主 + TCP 辅 | 战斗走 UDP，登录/交易/聊天走 TCP |
| 回合制、卡牌、棋牌 | TCP | 不要求实时，要求可靠有序，直接用 TCP |

> 结论：**实时对战用 UDP，回合制/交易类用 TCP**。同一款游戏也常「实时状态走 UDP、关键事务走 TCP」双通道。

## 为什么不用 TCP

| 问题 | TCP 的表现 | 对游戏的影响 |
| --- | --- | --- |
| 队头阻塞 | 前一个包没到，后面的包在缓冲区排队 | 一个旧位置包丢失，卡住所有后续位置更新 |
| 强制重传 | 丢包必重传，等待 RTO | 重传到达时该状态早已过期，纯属浪费 |
| 拥塞控制 | 丢包就降速（慢启动/退避） | 网络抖动时画面突然卡顿、延迟飙升 |
| 累积延迟 | 有序交付导致延迟越积越大 | 玩家操作与画面不同步，手感变差 |

**核心**：游戏要的是「**最新状态**」，不是「**完整历史**」。位置 t=1 的包丢了，t=2 的新位置一到就该立即用，重传 t=1 毫无意义。

## UDP 丢包了怎么办（应用层可靠性）

UDP 不可靠，游戏在应用层按需补：

- **状态同步**：只发最新快照，旧包直接丢弃（不重传）——丢了下一帧就覆盖。
- **客户端预测 + 插值/回滚**：本地先按输入预测移动，服务器权威状态到达后做插值平滑或回滚纠正。
- **关键操作可靠化**：开枪、释放技能、扣血等「一次性关键事件」加序列号 + ACK + 选择性重传（只重传关键包，不重传位置包）。
- **冗余发送**：把最近几帧输入打包在一个包里发，丢一个包也能从下一个包恢复（KCP、QUIC 思路）。

> 可靠 UDP 库/协议：**KCP**、**ENet**、**RakNet**、**QUIC**——本质都是「UDP + 应用层选择性可靠」。

## 八股速记

**Q：游戏为什么用 UDP？⭐⭐**

- 实时对战 **低延迟 > 可靠性**，TCP 的**队头阻塞 + 强制重传 + 拥塞降速**会让游戏更卡。
- 游戏要「最新状态」不要「完整历史」，旧包过期就该丢，重传无意义。
- 丢包由应用层处理：状态同步只发最新快照、客户端预测/回滚、关键事件才做选择性重传。

**⭐ 加分/易错**：
- 不是所有游戏都用 UDP——**回合制/棋牌/交易系统用 TCP**（要可靠有序，不要求实时）。
- 可靠 UDP 方案：KCP / ENet / QUIC，思路同[TCP与UDP的区别](3-TCP与UDP的区别.md)里 QUIC「UDP 基础 + 应用层可靠」。
- 和视频会议同理（[视频会议用什么协议](6-视频会议用什么协议.md)）：晚到的帧/状态已过期，低延迟优先。

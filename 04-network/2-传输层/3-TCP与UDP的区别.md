# TCP vs UDP

## 核心区别

| 维度 | TCP | UDP |
|---|---|---|
| 是否面向连接 | 面向连接（三次握手、四次挥手） | 无连接 |
| 可靠性 | 可靠：ACK 确认、重传、排序 | 不可靠，尽最大努力交付 |
| 有序性 | 保证顺序 | 不保证 |
| 流量/拥塞控制 | 有（滑动窗口、慢启动） | 无 |
| 是否有状态 | 有状态，维护连接信息 | 无状态，开销小 |
| 传输形式 | 面向字节流 | 面向报文 |
| 首部大小 | 最少 20 字节 | 固定 8 字节 |
| 通信方式 | 仅单播 | 单播、多播、广播 |
| 传输效率 | 开销大、较慢 | 开销小、快 |

> 一句话：TCP 可靠但复杂，UDP 简单但不可靠。

## TCP 一定比 UDP 慢吗？

**不一定。** TCP 变慢只发生在**丢包、拥塞、抖动**时——此时要重传、降速。

网络质量极好时（无丢包、无拥塞、带宽充足、滑动窗口 `min(rwnd, cwnd)` 拉满），TCP 速度 ≈ 物理带宽极限，和 UDP 几乎一样快。

- TCP 下载快慢由**滑动窗口 `min(rwnd, cwnd)`** 决定，本质取决于是否拥塞、是否丢包、窗口大小。
- 文件传输必须用 TCP：要的是可靠，而非低延迟。

## 应用场景

| 场景 | 用 TCP | 用 UDP | 原因 |
|---|---|---|---|
| 网页浏览（HTTP/HTTPS） | ✅ | | 必须可靠，数据不能丢 |
| 文件传输（FTP） | ✅ | | 文件必须完整，丢包重传 |
| 邮件（SMTP/IMAP） | ✅ | | 邮件不能丢 |
| SSH | ✅ | | 命令执行必须准确 |
| 视频直播 | | ✅ | 允许丢帧，延迟敏感 |
| 语音通话（VoIP） | | ✅ | 实时性 > 可靠性，丢包只短暂卡顿 |
| 在线游戏 | | ✅ | 位置同步允许少量丢包，不能卡 |
| DNS 查询 | | ✅ | 查询小、要求快（可靠性由应用层重试保证） |
| QUIC（HTTP/3） | | ✅ | UDP 基础 + 应用层可靠，兼顾速度与可靠 |


## 八股速记

**Q：TCP vs UDP**

| 维度 | TCP | UDP |
|---|---|---|
| 连接 | 面向连接（握手） | 无连接 |
| 可靠性 | 可靠（确认+重传+排序） | 不可靠，尽力交付 |
| 有序性 | 保证顺序 | 不保证 |
| 头开销 | 20 字节起 | 8 字节 |
| 速度 | 较慢 | 快 |
| 场景 | HTTP、文件传输、邮件 | DNS、视频/音频、直播、游戏 |

⭐ **加分/易错**：QUIC（HTTP/3 底层）是**基于 UDP 自己实现的可靠传输**，兼顾 UDP 的低延迟和 TCP 的可靠性，还解决了 TCP 队头阻塞。

## 一句话总结

> TCP可靠有序面向连接适合要求数据完整的场景，UDP轻量快速无连接适合容忍丢包但要求实时的场景。

# 拦截器与过滤器的区别

Filter 在 Servlet 层最外围，Interceptor 在 Spring MVC 层，AOP 在方法级最细；执行顺序 Filter → Interceptor → AOP → Controller。

## Filter（过滤器）

Servlet 规范级，最外层，能拿到原始 `request/response`，脱离 Spring 也能用。

## Interceptor（拦截器）

Spring MVC 级，在进 Controller 前后拦，能拿到 handler 信息。

## AOP

方法级，最细，能拦任意 Spring Bean 的方法（不止 Controller）。

## 三者对比

| 维度 | Filter | Interceptor | AOP |
|------|--------|-------------|-----|
| 层级 | Servlet 规范 | Spring MVC | 方法级 |
| 范围 | 最外层，所有请求 | Controller 前后 | 任意 Bean 方法 |
| 依赖 | 不依赖 Spring | 依赖 Spring MVC | 依赖 Spring AOP |

## ⭐ 加分/易错

执行顺序 **Filter → Interceptor → AOP → Controller**。鉴权/登录常放 Interceptor（如 Sa-Token 拦截，回 `whut/01-contest-sso.md`），日志/事务常用 AOP。

## 一句话总结

> Filter(Servlet) → Interceptor(SpringMVC) → AOP(方法级) → Controller，鉴权放 Interceptor，日志/事务放 AOP。

# SQL 表连接方式

## 面试Q&A

### Q1: SQL 有哪些 JOIN 类型？

假设有表 A（左表）和表 B（右表）：

| A.id | A.name | B.id | B.score |
|------|--------|------|---------|
| 1 | Alice | 1 | 90 |
| 2 | Bob | 2 | 85 |
| 3 | Carol | 4 | 70 |

---

#### 1. INNER JOIN（内连接）— 只返回匹配的行

```sql
SELECT A.name, B.score
FROM A INNER JOIN B ON A.id = B.id;
```

| name | score |
|------|-------|
| Alice | 90 |
| Bob | 85 |

> 韦恩图：两个圆的**交集**

---

#### 2. LEFT JOIN（左连接）— 左表全部 + 右表匹配（不匹配填NULL）

```sql
SELECT A.name, B.score
FROM A LEFT JOIN B ON A.id = B.id;
```

| name | score |
|------|-------|
| Alice | 90 |
| Bob | 85 |
| Carol | NULL |

> 韦恩图：左圆**完整**，与右圆重叠部分取右表值

---

#### 3. RIGHT JOIN（右连接）— 右表全部 + 左表匹配（不匹配填NULL）

```sql
SELECT A.name, B.score
FROM A RIGHT JOIN B ON A.id = B.id;
```

| name | score |
|------|-------|
| Alice | 90 |
| Bob | 85 |
| NULL | 70 |

> 韦恩图：右圆**完整**，与左圆重叠部分取左表值

---

#### 4. FULL JOIN（全连接）— 两表所有行（不匹配填NULL）

```sql
SELECT A.name, B.score
FROM A FULL JOIN B ON A.id = B.id;
```

| name | score |
|------|-------|
| Alice | 90 |
| Bob | 85 |
| Carol | NULL |
| NULL | 70 |

> 韦恩图：两个圆的**并集**

> 注意：MySQL 不直接支持 FULL JOIN，可用 `LEFT JOIN UNION RIGHT JOIN` 实现。

---

#### 5. CROSS JOIN（交叉连接）— 笛卡尔积

```sql
SELECT A.name, B.score
FROM A CROSS JOIN B;
-- 等价于: FROM A, B
```

> 结果行数 = A的行数 × B的行数 = 3 × 3 = 9 行

### Q3: "A表存在但B表不存在" 的实现

**需求**：找出 A 表中有但 B 表中没有的记录（A - B）

#### 方法1: LEFT JOIN + IS NULL

```sql
SELECT A.*
FROM A LEFT JOIN B ON A.id = B.id
WHERE B.id IS NULL;
```

| id | name |
|----|------|
| 3 | Carol |

**原理**：LEFT JOIN 后，B 表不匹配的行会填 NULL，过滤 `B.id IS NULL` 即可。

#### 方法2: NOT IN

```sql
SELECT A.*
FROM A
WHERE A.id NOT IN (SELECT B.id FROM B);
```

> 注意：如果子查询结果含 NULL，`NOT IN` 会返回空集！需排除 NULL：
> `WHERE A.id NOT IN (SELECT B.id FROM B WHERE B.id IS NOT NULL)`

#### 方法3: NOT EXISTS

```sql
SELECT A.*
FROM A
WHERE NOT EXISTS (
    SELECT 1 FROM B WHERE B.id = A.id
);
```

#### 三种方法对比

| 方法 | NULL 安全 | 性能 | 可读性 |
|------|----------|------|--------|
| LEFT JOIN + IS NULL | 安全 | 好 | 好 |
| NOT IN | **不安全**（子查询含NULL时结果为空） | 一般 | 好 |
| NOT EXISTS | 安全 | 好 | 一般 |

> **推荐**：LEFT JOIN + IS NULL 或 NOT EXISTS，避免 NOT IN 的 NULL 陷阱。

### Q4: 除了 JOIN，还有哪些多表查询方式？

#### 1. 子查询（Subquery）

```sql
-- WHERE IN
SELECT * FROM A WHERE A.id IN (SELECT B.id FROM B);

-- WHERE EXISTS
SELECT * FROM A WHERE EXISTS (SELECT 1 FROM B WHERE B.id = A.id);

-- 标量子查询（在SELECT中使用）
SELECT A.name, (SELECT B.score FROM B WHERE B.id = A.id) AS score FROM A;
```

#### 2. UNION / UNION ALL

```sql
-- UNION：合并去重
SELECT name FROM A
UNION
SELECT name FROM C;

-- UNION ALL：合并不去重（更快）
SELECT name FROM A
UNION ALL
SELECT name FROM C;
```

#### 3. 自然连接（NATURAL JOIN）

```sql
-- 自动用两表同名列做等值连接
SELECT * FROM A NATURAL JOIN B;
-- 等价于: SELECT * FROM A INNER JOIN B ON A.id = B.id (假设同名列是id)
```

> 不推荐使用：隐式连接条件，可读性差，容易出错。

### Q5: JOIN vs 子查询，性能谁更好？

| 对比维度 | JOIN | 子查询 |
|---------|------|--------|
| 执行方式 | 优化器可选择多种 JOIN 策略（NL/Hash/Sort-Merge） | 优化器可能先执行子查询再关联 |
| 索引利用 | 好优化器可利用两表索引 | 相关子查询每次外层行都要执行一次 |
| 可读性 | 多表时较复杂 | 逻辑清晰，分步思考 |
| 优化器改写 | — | 现代优化器常将子查询改写为 JOIN |

```sql
-- 子查询
SELECT * FROM A WHERE A.id IN (SELECT B.id FROM B WHERE B.score > 80);

-- 优化器可能改写为等价 JOIN
SELECT DISTINCT A.*
FROM A INNER JOIN B ON A.id = B.id WHERE B.score > 80;
```

**结论**：
- **通常 JOIN 性能更好**，优化器选择空间更大
- **现代数据库（MySQL 8+, PostgreSQL）优化器会自动改写简单子查询为 JOIN**
- 复杂相关子查询仍可能性能差，建议手动改写为 JOIN
- **以可读性为主，然后用 EXPLAIN 验证**，性能问题具体分析

### Q6: JOIN 的执行算法（面试进阶）

| 算法 | 原理 | 时间复杂度 | 适用场景 |
|------|------|-----------|---------|
| **Nested-Loop Join (NLJ)** | 双层循环，外表每行匹配内表所有行 | O(M × N) | 无索引，小表 |
| **Index Nested-Loop Join (INLJ)** | 内表用索引查找 | O(M × logN) | 内表有索引 |
| **Block Nested-Loop Join (BNLJ)** | 外表分块加载到 Join Buffer，减少内表扫描次数 | O(M × N / Buffer) | 无索引，有Join Buffer |
| **Hash Join** | 构建小表哈希表，大表探测 | O(M + N) | 等值连接，无索引 |

```sql
-- MySQL 8.0+ 默认使用 Hash Join 替代 BNLJ
-- 查看执行计划
EXPLAIN FORMAT=TREE SELECT * FROM A JOIN B ON A.id = B.id;

-- 输出可能包含:
-- | -> Inner hash join (B.id = A.id)
--      -> Table scan on B
--      -> Hash
--           -> Table scan on A
```

---

## 一句话总结

**INNER JOIN取交集，LEFT JOIN左表全保留，RIGHT JOIN右表全保留，FULL JOIN两表全保留，"A有B无"用LEFT JOIN+IS NULL或NOT EXISTS，通常JOIN性能优于子查询，MySQL 8+用Hash Join优化无索引等值连接。**

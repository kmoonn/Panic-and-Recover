# 排序（ORDER BY）

## ORDER BY 是什么？

ORDER BY 用于对查询结果集按照一个或多个列进行**排序**，默认升序（ASC），可指定降序（DESC）。

## 基本语法

```sql
-- 升序（默认）
SELECT * FROM employee ORDER BY salary ASC;
SELECT * FROM employee ORDER BY salary;       -- 等价

-- 降序
SELECT * FROM employee ORDER BY salary DESC;

-- 多列排序
SELECT * FROM employee ORDER BY department ASC, salary DESC;
-- 先按部门升序，部门相同再按薪资降序
```

## 升序（ASC）与降序（DESC）

| 关键字 | 含义 | 默认 | NULL 处理 |
|---|---|---|---|
| ASC | 升序（从小到大） | 默认 | NULL 排最前 |
| DESC | 降序（从大到小） | 需显式指定 | NULL 排最后 |

> MySQL 中 ASC/DESC 是每列独立指定的，不能全局设置一个方向。

## 多列排序

```sql
-- 先按 department 升序，相同 department 按 salary 降序
SELECT name, department, salary
FROM employee
ORDER BY department ASC, salary DESC;

/*
  name  | department | salary
  ------|------------|-------
  张三  | 财务部     | 15000
  李四  | 财务部     | 10000
  王五  | 技术部     | 20000
  赵六  | 技术部     | 12000
*/
```

## ORDER BY 与 GROUP BY 的区别

| 对比项 | ORDER BY | GROUP BY |
|---|---|---|
| 作用 | 对结果集排序 | 对数据分组聚合 |
| 是否改变数据内容 | 不改变，只改变顺序 | 改变，合并为分组 |
| 是否能配聚合函数 | 不常用（但可排序聚合结果） | 必须配合聚合函数 |
| 执行顺序 | 在 GROUP BY 之后 | 在 ORDER BY 之前 |

```sql
-- ORDER BY：排序结果
SELECT * FROM employee ORDER BY salary DESC;

-- GROUP BY：分组聚合
SELECT department, AVG(salary) FROM employee GROUP BY department;

-- 配合使用：分组后排序
SELECT department, AVG(salary) AS avg_sal
FROM employee
GROUP BY department
ORDER BY avg_sal DESC;
```

## ORDER BY 与索引

### Using index（索引排序）

当 ORDER BY 的列有索引且排序方向与索引一致时，MySQL 可以直接利用索引的有序性，**无需额外排序**。

```sql
-- 假设有 INDEX(salary)
EXPLAIN SELECT * FROM employee ORDER BY salary;
-- Extra: Using index  ← 直接利用索引顺序，无需 filesort
```

### Using filesort（文件排序）

当 ORDER BY 无法利用索引时，MySQL 需要在内存或磁盘中额外排序，称为**filesort**。

```sql
-- 无索引或排序方向与索引不一致
EXPLAIN SELECT * FROM employee ORDER BY salary DESC;
-- 如果索引是 ASC，而查询是 DESC，可能需要 filesort

-- 多列排序方向不一致
EXPLAIN SELECT * FROM employee ORDER BY department ASC, salary DESC;
-- 即使两列都有索引，方向不一致也无法利用索引排序
```

### filesort 的两种算法

| 算法 | 说明 | 特点 |
|---|---|---|
| 双路排序（Two-Pass） | 先读排序字段排序，再回表取完整数据 | I/O 次数多，旧版默认 |
| 单路排序（Single-Pass） | 一次性读取所有需要的列到排序缓冲区 | 内存消耗大，但 I/O 少 |

## ORDER BY 优化

| 优化策略 | 说明 |
|---|---|
| 利用索引 | ORDER BY 列建立索引，避免 filesort |
| 联合索引 | ORDER BY a, b 建联合索引 (a, b) |
| 覆盖索引 | SELECT + ORDER BY 列都在索引中，Using index |
| 避免混合方向 | ORDER BY a ASC, b DESC 无法用索引排序 |
| 增大 sort_buffer | `sort_buffer_size` 调大，减少磁盘排序 |
| 减少返回列 | 避免 SELECT *，减少排序数据量 |

```sql
-- 优化前：filesort
SELECT * FROM employee ORDER BY salary;

-- 优化后：利用索引
ALTER TABLE employee ADD INDEX idx_salary(salary);
SELECT id, salary FROM employee ORDER BY salary;
-- Extra: Using index（覆盖索引 + 索引排序）
```

## 面试高频问题

### Q: ORDER BY 怎么优化？

1. 在 ORDER BY 的列上建立索引，利用索引有序性避免 filesort
2. 使用覆盖索引（SELECT + ORDER BY 列都在索引中）
3. 避免混合排序方向（如 ORDER BY a ASC, b DESC 无法用索引）
4. 增大 `sort_buffer_size` 减少磁盘排序
5. 避免 SELECT *，减少排序数据量

### Q: Using filesort 是什么？怎么避免？

Using filesort 表示 MySQL 无法利用索引排序，需要在内存或磁盘中额外排序。避免方法：
- 为 ORDER BY 列建立合适的索引
- 确保排序方向与索引方向一致
- 使用覆盖索引

### Q: ORDER BY 和 GROUP BY 的区别？

ORDER BY 是对结果集排序，不改变数据内容；GROUP BY 是对数据分组聚合，改变数据粒度。执行顺序上 GROUP BY 在 ORDER BY 之前。

## 一句话总结

ORDER BY 对结果集排序，默认 ASC 升序，支持多列排序；优化排序的核心是利用索引避免 Using filesort，关键策略包括建立索引、使用覆盖索引、避免混合排序方向。

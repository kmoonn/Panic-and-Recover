## 0. 一句话定位

文档进知识库要经过"取文件→解析→切块→增强→建索引"一串步骤。我没把它写死在代码里，而是做成**配置驱动的流水线**：每步是一个节点、节点间连线、还能配条件（满足才执行）。**不改代码就能重排步骤、加新节点**，非开发也能编排。

## 0.5 我的边界

**独立设计实现**：PipelineDefinition（JSON 存 DB）、IngestionEngine（建图/查环/找起点/链式执行）、ConditionEvaluator（条件 DSL）、标准节点与两种分块策略都是我写的。embed 复用本地 bge-m3（维度 1024，选型见索引 §选型）。

## 深挖 Q&A ⭐

**💡 大白话（自己理解用，不用背）**
> 文档进知识库要经过"取文件→解析→切块→增强→建索引"一串步骤。我没把这串写死在代码里，而是做成**配置驱动的流水线**：每个步骤是一个节点、节点之间用连线串起来、还能配条件（满足才执行）。这样**不改代码就能重排步骤、加新节点**，非开发也能编排。

**✅ 打磨版答法（背这套）**
> "摄入我做成**数据/配置驱动的流水线引擎**：
> - **PipelineDefinition**：以 JSON 存 DB，里面是一串 node，节点间用 `nextNodeId` 链式串联，运行时可改。
> - **IngestionEngine**：加载 definition 后做**建图 → 查环 → 找起点 → 链式执行**，每个节点执行完按条件决定下一个节点。
> - **ConditionEvaluator**：支持 `all/any/not` + 字段规则的条件 DSL，实现**条件执行**（比如某类文档才走 OCR 增强节点）。
> - 标准节点：`fetch（取文件）→ parse（解析）→ chunk（切块，内联 embed）→ index（写 Qdrant）`。分块策略两种：**FIXED_SIZE(512/128 重叠)** 和 **STRUCTURE_AWARE（按标题/段落结构切）**。embed 用**本地 bge-m3，维度 1024**。
> - '异步执行'当前用 FastAPI `BackgroundTasks`，**没上 MQ**——规模没到，不为演示背不需要的组件。
> 简历里'新节点接入成本 -50%'就来自这个可编排框架：加一种文档处理只要实现节点接口、在配置里连线，不动引擎（体感/自测口径）。"

**⭐ 加分锚点**：主动区分"我的配置化流水线 vs LangGraph 代码定义图"（见索引 §1.3 陷阱2）——**配置驱动、运行时可改、非开发可编排** 是它存在的理由，不是重复造轮子。

**追问预案**
- **Q：既然有 LangGraph 这个图引擎了，摄入为什么不复用它？** → "见索引 §1.3 陷阱2：LangGraph 的图**写死在代码里**，我的摄入图是**JSON 配置、运行时可改、带条件 DSL**，目标是产品化的可编排（让非开发重排节点）。两个层面的东西，摄入这条我坚持轻量自研引擎。"
- **Q：切块 512/128 怎么定的？为什么要重叠？** → "512 token 是**语义完整性和检索粒度**的折中：太大 chunk 内噪声多、检索命中不精，太小上下文不足。128 重叠是**防止答案正好被切在边界**——相邻 chunk 有重叠能保证跨边界的句子不丢。结构化文档优先走 STRUCTURE_AWARE，按标题层级切更贴语义。"
- **Q：摄入失败/重复摄入怎么处理？** → "🔲 按实核对——设计上每个 doc 有唯一标识，重复摄入按标识覆盖对应 Qdrant 向量（幂等）；节点失败记进 trace 并可从失败节点重试。具体幂等键和重试策略面试前对齐真实实现。"

## 0. 一句话定位

前面四块是"发动机舱"，这块是"大脑"。一次问答不是"检索完直接答"，而是**有状态、能回环**：检索 → **评召回好不好** → 不好就**改写问题重检索** → 够好才生成 → 生成后**自检有没有幻觉** → 有嫌疑回去重写/重生成。LangGraph 负责这个"带分支和回路的控制流"，每一步仍调我自研的引擎。

## 0.5 我的边界

**关键分层（必答，别混）**：LangGraph 只做**查询级控制流这一层**（我用它编排状态图）；`retrieve`/`generate` 节点内部调的是我自研的多路检索引擎、模型路由层，全程被我的追踪包住。**LangGraph 是调度者，四块引擎的核心机制仍是我写的**——不揽框架的功，也不把自己的活说成"调框架"。

## 深挖 Q&A ⭐⭐

**💡 大白话（自己理解用，不用背）**
> 前面四块是"发动机舱"，这块是"大脑"。一次问答不是"检索完就直接答"，而是一个**有状态、能回环**的流程：检索 → **评一下召回好不好** → 不好就**改写问题重新检索** → 够好才生成答案 → 生成完**自检有没有幻觉** → 有嫌疑就回去重写/重生成。LangGraph 就负责这个"带分支和回路的控制流"，具体每一步还是调我自研的引擎。

**✅ 打磨版答法（背这套）**
> "问答主控制流我用 **LangGraph 状态图**做，因为 agentic RAG 需要**有状态、可分支、可回路**：
> - 节点：`retrieve（检索）→ grade（评召回质量）→ (召回差) rewrite（重写 query）回到 retrieve / (召回好) generate（生成）→ self_check（自检幻觉）→ (疑似幻觉) 回 generate 或 rewrite`。
> - 关键分层（**必答，别混**）：**LangGraph 只做查询级控制流这一层**；`retrieve` 节点内部调的是我 bullet1 的**多路并行检索引擎**、`generate` 节点调的是 bullet2 的**模型路由 + 熔断**、全程被 bullet3 的**追踪**包住。LangGraph 只当"调度者"，**不感知这些引擎内部**——每块的核心机制仍是我写的。
> - 为什么选它不用 Agent Executor / 纯 Chain：状态图**可测试、可复现、可观测**——每个节点输入输出明确、回环有最大次数限制，出问题能定位到是哪个节点、哪一轮。**这点特别契合我测开的视角：控制流本身是可断言、可回放的。**"

**⭐ 加分锚点**：从**测开视角**收尾——"状态图让 agentic 流程变得可断言、可复现、能定位到具体节点和轮次"，把 RAG 项目和测开岗位诉求扣上；再强调"LangGraph 是调度者、四块引擎是我的"守住不揽框架功的红线。

**追问预案**
- **Q：grade（评召回质量）具体怎么评？** → "用一个轻量 LLM 打分 prompt 判断召回 chunk 与 query 的相关性/是否足以回答，输出一个分数或 yes/no。低于阈值就触发 rewrite。这一步本质是**让模型当召回质量的裁判**，是 corrective-RAG 的思路。"
- **Q：rewrite 回环会不会死循环？** → "有**最大重写次数**上限（比如 2 次），到顶还不行就带着现有上下文直接 generate 并在答案里标注'资料可能不足'，不无限打转。self_check 回环同理有次数上限。"
- **Q：self_check 怎么判断幻觉？** → "让模型对照**检索到的原文**核对答案里的关键论断是否有出处支撑（groundedness 检查），没出处的判为疑似幻觉、触发回环或降级。是自检不是外部真值校验，所以只能降低幻觉、不能保证零幻觉——这点我会诚实说。"
- **Q：这套控制流上线了吗？** → "Python 重写版里**核心问答链路（含这个状态图）已跑通、能本地演示**；生产最初跑的是 Java 云 API 版。部署规模我不夸大——诚实说是重写版可演示、还没大规模生产压测。"

## 0. 定位

字节这段实习有**两条主线**，简历「实习内容」一句话点了题：
1. **后端 SDT 规范驱动测试**（SDT = **Spec-Driven Testing，规格驱动测试**）——常规质量保障主线，以 PRD/IDL 等规格为权威来源设计测试；
2. **AI Testing 工具链的探索与实践**——三个亮点项目所在（AI 提效侧）。

面试官读到这句，最可能问三件事：**「SDT 是什么、你怎么做的」「AI Testing 工具链具体指什么」「这几个项目什么关系」**。本页把这三问的开场稿备好。

## 1. 实习内容 30 秒总述（被问"在字节做什么"时开场）

> "我在字节国际商业化的创意与生态部做测试开发，业务是 **TikTok One 三方创意**。我的工作有两块：一块是**后端的 SDT（Spec-Driven Testing，规格驱动测试）**——以 PRD、接口 IDL 这些规格为权威来源来设计测试，保障三方创意业务需求的质量；另一块是**探索 AI Testing 工具链**，用 AI 提效测试流程——这块沉淀了三个项目：**AI Data Gen（造数）、Skills Pulse（造数体系的可观测）、API Testing Agent（用例生成到执行闭环）**，三者正好串成'造数据—看数据—用数据测'的闭环。"

## 2. "SDT 规范驱动测试是什么？你具体怎么做的？" ⭐

> ✅ 已确认：**SDT = Spec-Driven Testing（规格/规范驱动测试）**。

**💡 大白话（自己理解用）**：Spec-Driven Testing = **让"规格/规范"来驱动测试怎么做**。这里的"spec"就是需求规格（PRD）、接口契约（IDL/接口文档）、设计规范这些**权威文档**——测什么、怎么测、断言依据，都从 spec 推导出来，而不是靠个人拍脑袋或凭经验测。它是我 AI Testing 那几个项目的**底座**：正因为测试该由 spec 驱动、流程可标准化，才值得也才能用 AI 去自动化提效。

**✅ 打磨版答法（背这套）**：
> "SDT 就是 **Spec-Driven Testing，规格驱动测试**——核心是**以需求规格和接口契约（PRD、IDL/接口文档、设计规范）作为测试设计的权威来源**：该测哪些点、用什么数据、断言拿什么做依据，都从 spec 推导，而不是各凭经验。好处是测试覆盖有据可依、可追溯、不同人做出来的用例一致。**我在字节的具体工作就是简历上写的那三块——AI Data Gen、Skills Pulse、API Testing Agent**，它们本质都是把 Spec-Driven Testing 用 AI 落地和提效：
> - **API Testing Agent** 最直接——把'从 PRD/MR 这些 spec 生成用例 checklist、再基于 IDL/PRD 生成断言'这条链路自动化（回 `03-api-testing-agent.md`），就是 AI 版的 spec→用例→断言；
> - **AI Data Gen** 解决 spec 驱动测试里'测试数据怎么来'（回 `01-ai-data-gen.md`）；
> - **Skills Pulse** 给这套体系做可观测（回 `02-skills-pulse.md`）。
> 所以'SDT 规范驱动'是方法、这三个项目是我用 AI 把这套方法落地的实践。"

**⭐ 加分锚点**：
- 能把 **SDT（spec 驱动）和三个项目讲成"方法→落地"**——面试官会看出你不是零散做工具，而是**先有方法论、再用 AI 落地方法论**，尤其 API Testing Agent 就是 AI 版 spec→用例→断言。这是本段最强的加分点。
- 断言三来源"IDL / PRD / 业务代码"（`03` Q8）正是 spec-driven 的体现——用例和断言都锚定在权威 spec 上。

**追问预案**：
- **"Spec 具体指哪些？"** → "主要是 **PRD（需求规格）+ 接口 IDL/接口文档（接口契约）+ 设计规范**；提测后 MR 的代码改动也作为增量 spec 来查漏（回 `03` 的 PRD+MR 双驱动）。"
- **"你在 SDT 流程里具体 own 什么？"** → "就是简历那三个项目——AI Data Gen / Skills Pulse / API Testing Agent，都是我把 spec-driven testing 用 AI 落地做的。深挖走对应笔记，讲清哪些是我独立设计、哪些是复用团队基建编排（如 API Testing Agent 的执行复用 ATE 平台）。"
- **"SDT 和 SDET 是一回事吗？"** → "不是。**SDET 是岗位**（Software Development Engineer in Test，测试开发工程师）；**SDT 是方法**（Spec-Driven Testing，规格驱动测试）。我是 SDET 岗位，工作方法上采用 SDT。"
- **"和 TDD/BDD 什么区别？"** → "TDD 是**先写测试再写实现**（开发侧驱动设计）；BDD 用自然语言行为规格（Given-When-Then）驱动；**SDT 强调以既有的需求/接口规格为权威来源来设计测试**，三者都是'让规格/测试来引导'，侧重点不同。"

## 3. 三项目闭环（"这几个项目什么关系"必问）⭐⭐

> 这是字节这段经历最强的叙事——三个项目不是孤立的，是一条**质量数据闭环**。全局红线也强调"三者能互相带出"。

```
                   ┌─────────────────────────────────────────┐
                   │        AI Testing 工具链（我的三个项目）      │
                   └─────────────────────────────────────────┘

   [AI Data Gen]  ──造出测试数据──▶  [API Testing Agent]  ──跑接口测试──▶ 出报告
    造数 Skill 体系      │  （造数 Skill 是它三种           
    (01)                │    数据来源之一)  (03)          
        │               │                                  
        └──被埋点采集──▶ [Skills Pulse] ◀──也采集────────────┘
                         调用量/成功率/耗时/报错 (02)
```

**串讲话术（约 25 秒）**：
> "三个项目是一条闭环：**AI Data Gen** 解决'测试数据怎么来'——把长链路造数沉淀成原子 Skill；**Skills Pulse** 给这套造数体系做**可观测**，采集调用量、成功率、耗时、报错；**API Testing Agent** 是'用数据来测'——它生成用例 checklist、自主补数据时，**造数 Skill 就是它的数据来源之一**。所以是'**造数据—看数据—用数据测**'一条线，我在这条线上做的是把重复劳动 AI 化、并保证结果可信可观测。"

**⭐ 加分锚点**：能主动画出/讲清这条闭环，面试官会觉得你**有全局视角**，而不是做了三个不相干的小工具。

## 4. "AI Testing 工具链具体指什么？"（顺带备）

> "指的是我们探索用 AI/大模型给测试流程提效的一套工具，落到我手上是三个方向：**智能造数（AI Data Gen）、可观测（Skills Pulse）、智能用例生成与执行（API Testing Agent）**。核心思路都是**复用现有基建 + 补上 AI 编排这层**，不重造轮子（比如 API Testing Agent 的执行就是复用团队 ATE 平台）。"

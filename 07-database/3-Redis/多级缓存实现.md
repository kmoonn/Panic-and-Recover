# 多级缓存实现

## 架构

本地缓存（Caffeine/Guava）+ 分布式缓存（Redis）+ DB，读取时逐层查找：

```
先查本地缓存
  → 没有：查 Redis
    → 没有：查 DB
回写 Redis → 回写本地缓存
```

## 优点

- **速度最快**：热点数据命中进程内本地缓存，无网络开销
- **减轻 Redis 压力**：本地缓存挡住大部分热点请求
- **高可用**：逐层兜底，Redis 故障时本地缓存仍可扛一部分流量

## 一句话总结

> 本地缓存+Redis+DB多级缓存架构，读时回写本地减轻Redis压力，逐层穿透保证高可用。

## 八股速记

**问：本地缓存 vs 分布式缓存 ⭐ B**

**答（要点式）**：
- **本地缓存**（Caffeine/Guava）：进程内、**最快**，但**多机不共享**、有一致性问题、占应用内存。
- **分布式缓存**（Redis）：多机共享、容量大，但有**网络开销**。
- **多级缓存**：本地缓存（挡热点）+ Redis（共享）+ DB，逐层兜底，抗高并发常用。

**⭐ 加分/易错**：本地缓存更新难同步（各机独立），常配短过期或消息广播失效；不是所有场景都该上分布式缓存，热点小数据本地缓存反而更优。

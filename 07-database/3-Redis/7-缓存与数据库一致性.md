标准方案：先更新数据库，再删除缓存。

1）先删缓存，再更新 DB（有问题！）
请求 A：删缓存 → 更新 DB请求 B：查缓存不存在 → 读旧 DB → 把旧数据写回缓存→ 缓存是旧的，DB 是新的，长期不一致！
结论：绝对不能用。
2）先更新 DB，再删缓存（正确方案）
极大概率一致
极端场景才会短暂不一致（秒级）
业务可接受

## 一句话总结

> 推荐先更新DB再删缓存方案，绝不能用先删缓存再更新DB（旁路缓存模式）。

## 八股速记

**问：缓存一致性 / 双写问题 ⭐⭐**

**答（要点式）**：
- **主流方案**：**Cache Aside（旁路缓存）**——读时先读缓存、没有再读 DB 回填；写时**更新 DB + 删除缓存**（不是更新缓存）。
- **为什么删不是改**：删除更简单、避免并发写导致缓存脏数据；下次读自然回填最新值。
- **删缓存时机**：推荐**先更新 DB 再删缓存**；仍有极端并发不一致，用**延迟双删**或**订阅 binlog（Canal）**兜底。

**⭐ 加分/易错**：缓存一致性只能做到**最终一致**，别答"强一致"。要强一致代价极高（分布式锁/串行化），通常业务不需要。

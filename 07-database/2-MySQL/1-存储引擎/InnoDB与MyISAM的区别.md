# InnoDB 与 MyISAM 的区别

## 对比总览

| 维度 | InnoDB | MyISAM |
|---|---|---|
| **文件结构** | 每表一个 `.ibd`（数据即索引，聚簇索引） | 每表两个文件：`.MYD`（数据）+ `.MYI`（索引），索引数据分离 |
| **事务** | 支持（提交/回滚/XA/savepoint 部分回滚） | 不支持 |
| **锁粒度** | 行级锁（默认）+ 表级锁 | 仅表级锁 |
| **外键** | 支持 | 不支持 |
| **MVCC** | 支持 | 不支持 |
| **崩溃恢复** | 支持（依赖 redo log） | 不支持 |
| **缓存** | 缓冲池（Buffer Pool）缓存数据页 + 索引页 | 键缓存（Key Cache）仅缓存索引页 |
| **隔离级别** | 默认可重复读（解决幻读） | — |

## InnoDB

- 每个表一个文件 `.ibd`（数据文件本身就是索引文件）
- 支持事务，具备提交、回滚能力；支持 XA 事务与 savepoints（部分回滚）
- 默认使用可重复读隔离级别（解决幻读问题）
- 支持外键、行级锁（默认）、表级锁、MVCC
- 支持数据库异常崩溃后的安全恢复（依赖 redo log）
- 使用缓冲池（Buffer Pool）缓存数据页和索引页
- 综合性能比 MyISAM 更强

## MyISAM

- 每个表两个文件：数据文件 `.MYD` + 索引文件 `.MYI`（索引与数据分离）
- 不支持事务
- 不支持行级锁，只有表级锁
- 使用键缓存（Key Cache）仅缓存索引页而不缓存数据页

## 一句话总结

> InnoDB支持事务行锁外键MVCC崩溃恢复，MyISAM仅表锁无事务，InnoDB性能更优

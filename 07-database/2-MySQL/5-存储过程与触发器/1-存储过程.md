# 存储过程

## Q：什么是存储过程？

存储过程(Stored Procedure)是一组**预编译并存储在数据库中的 SQL 语句集合**，通过指定名称和参数调用执行。

- 首次编译后缓存在内存中，后续调用直接执行，无需重新解析
- 可以包含变量声明、流程控制、异常处理等逻辑
- 存储在服务器端，客户端只需调用名称即可

---

## Q：存储过程的创建和调用语法？

### 创建

```sql
DELIMITER //

CREATE PROCEDURE proc_name([参数列表])
BEGIN
    -- SQL 语句
END //

DELIMITER ;
```

- `DELIMITER //` 临时改变结束符，避免 BEGIN...END 中的分号提前结束定义
- 创建完成后用 `DELIMITER ;` 恢复默认结束符

### 调用

```sql
CALL proc_name([参数值]);
```

### 删除

```sql
DROP PROCEDURE IF EXISTS proc_name;
```

### 完整示例

```sql
DELIMITER //

CREATE PROCEDURE get_user_by_age(IN p_age INT)
BEGIN
    SELECT * FROM users WHERE age > p_age;
END //

DELIMITER ;

-- 调用
CALL get_user_by_age(18);
```

---

## Q：存储过程的参数类型有哪些？

| 参数类型 | 关键字 | 说明 | 示例 |
|---|---|---|---|
| 输入参数 | `IN` | 调用时传入，存储过程内只读（默认类型） | `IN p_age INT` |
| 输出参数 | `OUT` | 存储过程内赋值，调用后可获取返回值 | `OUT p_count INT` |
| 输入输出参数 | `INOUT` | 既可传入又可传出 | `INOUT p_num INT` |

```sql
DELIMITER //

CREATE PROCEDURE count_by_age(IN p_age INT, OUT p_count INT)
BEGIN
    SELECT COUNT(*) INTO p_count FROM users WHERE age > p_age;
END //

DELIMITER ;

-- 调用
CALL count_by_age(18, @total);
SELECT @total;
```

## Q：存储过程中的变量声明与流程控制？

### 变量声明与赋值

```sql
-- 局部变量
DECLARE v_name VARCHAR(50) DEFAULT 'unknown';
SET v_name = '张三';

-- 用户变量（会话级）
SET @v_age = 25;
```

### IF 条件判断

```sql
IF p_age > 60 THEN
    SELECT '老年';
ELSEIF p_age > 18 THEN
    SELECT '成年';
ELSE
    SELECT '未成年';
END IF;
```

### CASE 语句

```sql
CASE p_level
    WHEN 1 THEN UPDATE users SET score = score + 10;
    WHEN 2 THEN UPDATE users SET score = score + 5;
    ELSE UPDATE users SET score = score + 1;
END CASE;
```

### WHILE 循环

```sql
WHILE i <= 10 DO
    INSERT INTO nums(val) VALUES(i);
    SET i = i + 1;
END WHILE;
```

### REPEAT 循环（先执行后判断，类似 do-while）

```sql
REPEAT
    SET i = i + 1;
UNTIL i > 10
END REPEAT;
```

### LOOP 循环（需配合 LEAVE 退出）

```sql
my_loop: LOOP
    SET i = i + 1;
    IF i > 10 THEN
        LEAVE my_loop;
    END IF;
END LOOP my_loop;
```

## Q：存储过程的优缺点？

### 优点

| 优点 | 说明 |
|---|---|
| **封装复用** | 将复杂业务逻辑封装为存储过程，多个应用可复用 |
| **减少网络传输** | 客户端只需发送调用命令，无需传输大量 SQL |
| **预编译执行** | 首次编译后缓存执行计划，执行效率高 |
| **安全控制** | 可通过权限控制只允许调用存储过程，不直接暴露表 |

### 缺点

| 缺点 | 说明 |
|---|---|
| **调试困难** | 缺乏完善的调试工具，排查问题不便 |
| **不可移植** | 不同数据库存储过程语法差异大，迁移成本高 |
| **业务逻辑耦合** | 将业务逻辑放到数据库层，与应用层逻辑混杂 |
| **版本控制不便** | 存储过程在数据库中，难以纳入代码版本管理 |
| **扩展性差** | 存储过程在数据库端执行，难以像应用层一样水平扩展 |

## Q：存储过程与函数的区别？

| 对比维度 | 存储过程(Procedure) | 函数(Function) |
|---|---|---|
| 返回值 | 可有 0 或多个（通过 OUT/INOUT 参数） | 必须有且仅有一个返回值 |
| 调用方式 | `CALL proc_name()` | 嵌入 SQL 中使用，如 `SELECT func_name()` |
| 参数类型 | IN / OUT / INOUT | 只有 IN（默认） |
| DML 语句 | 可包含 SELECT/INSERT/UPDATE/DELETE | 通常只允许 SELECT，不允许修改数据 |
| 使用场景 | 封装业务逻辑 | 封装计算逻辑，返回标量值 |

## 八股速记

> ⚠️ 简历数据库行列了"存储过程"，属"理解 + 会用"层级——能讲清是什么、怎么写/调、执行原理，以及现在为什么少用即可，不必背复杂语法。

- **存储过程（Stored Procedure）**：预先写好、**存在数据库里的一段 SQL 程序**（可含变量、条件、循环），应用直接 `CALL` 调用。优点是**减少网络往返、逻辑靠近数据**；缺点是**难维护、难版本管理、难调试、绑定特定数据库**。
- **怎么用（会写会调即可）**：
  ```sql
  DELIMITER $$                          -- 临时改结束符，避免过程体里的 ; 提前结束
  CREATE PROCEDURE add_score(IN uid INT, IN delta INT)
  BEGIN
    UPDATE user SET score = score + delta WHERE id = uid;
  END $$
  DELIMITER ;
  CALL add_score(1001, 5);               -- 调用
  ```
  - 参数三种模式：`IN`（传入，默认）、`OUT`（传出结果）、`INOUT`（既传入又传出）。
  - 过程体里可用变量（`DECLARE`）、条件（`IF/CASE`）、循环（`WHILE/LOOP`）、游标（`CURSOR` 逐行处理）。
- **执行原理**：创建时数据库把过程**编译并存进系统表**；`CALL` 时直接执行已编译逻辑，省去 SQL 每次传输 + 硬解析的开销——这正是"减少网络往返、性能好"的来源。
- **触发器（Trigger）**：绑定在表上、在 `INSERT/UPDATE/DELETE` 时**自动执行**的逻辑（`BEFORE/AFTER` + 用 `NEW`/`OLD` 拿新旧行），如自动写审计日志。优点是自动；缺点是**隐蔽**——业务逻辑藏在库里，排查问题时容易忽略。

**⭐ 加分/易错**：
- **主流趋势是把业务逻辑放应用层、不放存储过程/触发器**——原因是可维护、可测试、可版本控制、方便水平扩展（数据库难扩、应用易扩）。能说出这个"权衡"比背语法加分。
- **存储过程 vs 函数（Function）**：函数必须有返回值、可嵌在 SQL 里（`SELECT f(x)`）；存储过程靠 `OUT` 参数返回、只能 `CALL`。
- 测开视角：有存储过程/触发器的系统要特别注意——**部分逻辑不在应用代码里**，测试和排查时别漏了库里这层（是"隐藏逻辑"的常见来源）。

> 一句话总结：存储过程是预编译的 SQL 语句集合，支持参数传递和流程控制，优点是封装复用和减少网络传输，缺点是调试困难、不可移植、业务逻辑耦合数据库，面试中常与函数对比考查。

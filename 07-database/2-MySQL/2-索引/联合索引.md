# 联合索引

## 什么是联合索引？

联合索引（又称组合索引、复合索引）是基于**多个列**组合创建的索引，如 `INDEX idx_abc(a, b, c)`。

```sql
-- 创建联合索引
ALTER TABLE user ADD INDEX idx_name_age_email(name, age, email);
```

## 最左前缀匹配原则

联合索引遵循**最左前缀匹配原则**：查询条件必须从索引的最左列开始，且不能跳过中间列。

索引 `INDEX(a, b, c)` 的匹配规则：

| 查询条件 | 是否命中索引 | 说明 |
|---|---|---|
| WHERE a = ? | 命中 | 匹配最左列 |
| WHERE a = ? AND b = ? | 命中 | 匹配最左两列 |
| WHERE a = ? AND b = ? AND c = ? | 命中 | 匹配全部三列 |
| WHERE b = ? | **不命中** | 跳过最左列 a |
| WHERE c = ? | **不命中** | 跳过最左列 a |
| WHERE b = ? AND c = ? | **不命中** | 跳过最左列 a |
| WHERE a = ? AND c = ? | 部分命中 | 只命中 a 列，c 无法利用索引 |

> **注意**：MySQL 优化器会自动调整 WHERE 条件的顺序，所以 `WHERE b = ? AND a = ?` 等价于 `WHERE a = ? AND b = ?`，可以命中索引。

## 索引排序规则

联合索引的 B+Tree 按**从左到右的列顺序**排序：

1. 先按第一列排序
2. 第一列相同时，按第二列排序
3. 第二列相同时，按第三列排序
4. 以此类推

```
联合索引 (a, b, c) 的排序示例：

 a  | b  | c
----|----|----
 1  | 10 | 100
 1  | 10 | 200
 1  | 20 | 50
 2  | 5  | 80
 2  | 15 | 60
 3  | 8  | 90

先按 a 排序 → a 相同按 b 排序 → b 相同按 c 排序
```

### 范围查询后的列无法使用索引

```sql
INDEX(a, b, c)

-- 范围查询后的列无法用索引
WHERE a > 1 AND b = 10 AND c = 50
-- 只有 a 能用索引，b 和 c 无法利用索引

-- 等值查询 + 范围查询
WHERE a = 1 AND b > 10 AND c = 50
-- a 和 b 能用索引，c 无法利用索引（b 是范围查询）
```

## 列顺序选择原则

联合索引的列顺序至关重要，选择原则：

1. **选择性高的列放前面**：区分度大的列（如 user_id）放最左，能更快缩小范围
2. **等值查询列放前面**：范围查询列放后面
3. **考虑覆盖索引**：将 SELECT 需要的列也加入联合索引

```sql
-- 选择性：COUNT(DISTINCT col) / COUNT(*)
-- 选择性越高，区分度越大，越适合放前面

-- 例：name 选择性高，age 选择性低
-- 好：INDEX(name, age)  ← 先用 name 快速定位
-- 差：INDEX(age, name)  ← 先用 age 定位范围大
```

## 联合索引与覆盖索引的关系

联合索引是实现覆盖索引的常见手段：

```sql
-- 联合索引覆盖查询
INDEX idx_name_age(name, age)

-- 覆盖索引：SELECT 列都在联合索引中
SELECT name, age FROM user WHERE name = '张三';
-- Extra: Using index

-- 非覆盖：SELECT 中有索引外的列
SELECT name, age, email FROM user WHERE name = '张三';
-- 需要回表
```

通过把查询需要的列都加入联合索引，可以使查询成为覆盖索引，避免回表。

## 面试高频问题

### Q: INDEX(a, b, c) 能命中 WHERE b = ? 吗？

**不能。** 跳过了最左列 a，违反最左前缀匹配原则，无法使用索引。只有从最左列开始匹配才能使用联合索引。

### Q: WHERE a = ? AND c = ? 能用联合索引 INDEX(a, b, c) 吗？

**部分命中。** 只有 a 列能使用索引，c 列无法利用索引（因为跳过了 b 列）。在 MySQL 5.6+ 中，索引下推（ICP）可以在索引层面先过滤 c 列，但仍需要回表。

### Q: 联合索引的列顺序怎么选？

1. 选择性高的列放前面（区分度大，快速缩小范围）
2. 等值查询列优先于范围查询列
3. 考虑覆盖索引的需求

## 一句话总结

联合索引是基于多列的索引，遵循最左前缀匹配原则，列顺序按选择性从高到低排列，跳过最左列则无法命中索引，常与覆盖索引配合实现无需回表的高效查询。

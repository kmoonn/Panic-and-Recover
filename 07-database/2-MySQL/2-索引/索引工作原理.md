# 索引工作原理

MySQL 索引本质是 **B+ 树**，作用是把"全表扫描"变成"树查找"，从 O(n) 降到 O(log n)。

## 1. 为什么不用哈希、二叉树、红黑树？

| 结构 | 问题 |
|---|---|
| 哈希 | 等值查询快，但不能范围查询（`>` `<` `between`） |
| 普通二叉树 | 可能退化成链表，等于没用 |
| 红黑树 | 树太高，磁盘 I/O 太多，慢 |
| **B+ 树** | 矮胖、多叉、磁盘 I/O 少、支持范围查询，完美适配数据库 |

## 2. B+ 树长什么样？

- 只有**叶子节点**存真实数据
- 非叶子节点只存索引键 + 指针，用来"指路"
- 叶子节点之间用链表串起来（利于范围查询）
- 树很矮，一般 3～4 层就能存千万级数据

查一条数据只需 3～4 次磁盘 I/O，极快。

## 一句话总结

> B+树3~4层存千万级数据，非叶子只存键做指路牌，叶子存真实数据且链表相连，单次查询仅需3~4次磁盘I/O。

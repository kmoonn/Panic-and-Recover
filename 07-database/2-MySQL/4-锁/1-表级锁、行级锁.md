# 表级锁与行级锁

## 什么是锁？

锁是数据库在多线程/多事务并发访问时，保证数据一致性的机制。MySQL 中按锁粒度可分为**表级锁**和**行级锁**。

## 表级锁

锁整张表，加锁开销小、加锁快，但并发性能低。

### 表级锁的类型

| 类型 | 说明 | 场景 |
|---|---|---|
| 表锁（LOCK TABLES） | 显式加锁，READ LOCK（共享读锁）/ WRITE LOCK（独占写锁） | MyISAM 手动加锁、数据导入等 |
| 元数据锁（MDL） | 自动加锁，防止 DDL 与 DML 冲突 | 执行 DML 时自动加 MDL 读锁，DDL 时加 MDL 写锁 |
| 意向锁（IS/IX） | InnoDB 自动加，表示事务打算加行锁，用于快速判断表中是否有行锁 | 加行锁前自动加意向锁 |

```sql
-- 表锁
LOCK TABLES t1 READ;          -- 共享读锁，其他会话可读不可写
LOCK TABLES t1 WRITE;         -- 独占写锁，其他会话不可读写
UNLOCK TABLES;

-- 意向锁（自动加，无需手动）
-- 事务要对某行加共享锁 → 先对表加意向共享锁(IS)
-- 事务要对某行加排他锁 → 先对表加意向排他锁(IX)
```

### 意向锁的作用

意向锁是**表级锁**，其核心目的是让表级锁与行级锁**快速兼容性判断**：

- 加表级锁时，不需要逐行检查是否有行锁，只需检查是否有冲突的意向锁
- 意向锁之间互相兼容（IS 与 IS/IX 兼容，IX 与 IS/IX 兼容）
- 意向锁与表锁的兼容关系：

|  | IS | IX | 表共享锁 | 表排他锁 |
|---|---|---|---|---|
| IS | 兼容 | 兼容 | 兼容 | 不兼容 |
| IX | 兼容 | 兼容 | 不兼容 | 不兼容 |
| 表共享锁 | 兼容 | 不兼容 | 兼容 | 不兼容 |
| 表排他锁 | 不兼容 | 不兼容 | 不兼容 | 不兼容 |

## 行级锁

锁一行或几行记录，加锁开销大、加锁慢，但并发性能高。InnoDB 支持行级锁，MyISAM 不支持。

### 行级锁的类型

| 锁类型 | 锁定范围 | 说明 |
|---|---|---|
| 记录锁（Record Lock） | 单条索引记录 | 锁住索引上一条记录，防止其他事务修改/删除该行 |
| 间隙锁（Gap Lock） | 索引记录之间的间隙 | 锁住范围，不含记录本身，防止其他事务在间隙中插入新记录 |
| 临键锁（Next-Key Lock） | 记录锁 + 间隙锁 | 左开右闭区间，既锁记录又锁间隙，InnoDB 默认加锁方式 |

```
索引记录：  10    20    30    40
           ↑     ↑     ↑     ↑
间隙锁：  (−∞,10) (10,20) (20,30) (30,40) (40,+∞)
临键锁：  (−∞,10] (10,20] (20,30] (30,40] (40,+∞)
```

### 关键点：InnoDB 的行锁是锁索引项

> **InnoDB 的行级锁实际上是锁索引项，不是锁数据行。**

- 如果 SQL 通过索引条件检索，InnoDB 在索引上加锁 → 行级锁
- 如果 SQL **不走索引**，InnoDB 会在每一条索引记录上加锁 → **退化为表级锁**

```sql
-- name 列有索引：行级锁，只锁匹配行
SELECT * FROM user WHERE name = '张三' FOR UPDATE;

-- name 列无索引：退化为表级锁，所有行都被锁住！
SELECT * FROM user WHERE name = '张三' FOR UPDATE;
```

## 表级锁 vs 行级锁对比

| 对比项 | 表级锁 | 行级锁 |
|---|---|---|
| 锁粒度 | 整张表 | 一行/几行 |
| 加锁开销 | 小 | 大 |
| 加锁速度 | 快 | 慢 |
| 并发性能 | 低（写互斥） | 高（只锁相关行） |
| 死锁概率 | 低（锁粒度大，不会循环等待） | 较高（不同事务锁不同行可能循环等待） |
| 适用引擎 | MyISAM、InnoDB | InnoDB |
| 适用场景 | 读多写少、并发低 | 高并发读写 |

## 面试高频问题

### Q: InnoDB 什么情况下行级锁会退化为表级锁？

**不走索引时退化为表级锁。** 当 UPDATE/DELETE 的 WHERE 条件没有命中任何索引时，InnoDB 无法定位到具体的行，只能对所有索引记录加锁，效果等同于表级锁。

```sql
-- 假设 age 列没有索引
UPDATE user SET name = '李四' WHERE age = 25;
-- 退化为表级锁：所有行都被锁住！

-- 解决方案：给 age 列加索引
ALTER TABLE user ADD INDEX idx_age (age);
```

### Q: 间隙锁有什么用？

间隙锁的目的是**防止幻读**。在可重复读（RR）隔离级别下，InnoDB 通过临键锁（记录锁 + 间隙锁）防止其他事务在间隙中插入新记录，从而避免幻读。

## 八股速记

- **粒度**：表锁（开销小、冲突多）、行锁（开销大、并发高，InnoDB 支持）。
- **行锁类型**：共享锁 S（读）、排他锁 X（写）。
- **间隙锁（Gap Lock）**：锁住索引记录之间的**间隙**，防插入 → 防幻读。
- **Next-Key Lock**：行锁 + 间隙锁，RR 下默认加，锁住记录及其前面的间隙。
- **意向锁**：表级，标记"表里有行锁"，加表锁时快速判断冲突。

**⭐ 易错**：InnoDB 行锁是**加在索引上的**，如果查询没走索引 → 退化成表锁。

## 一句话总结

表级锁锁整张表、开销小并发低，行级锁锁索引项、开销大并发高；InnoDB 的行锁实际锁索引而非数据行，当查询不走索引时会退化为表级锁，这是面试高频考点。

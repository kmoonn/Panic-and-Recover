# MongoDB 基础

## Q：MongoDB 是什么？

MongoDB 是一个**开源的文档型 NoSQL 数据库**，使用 BSON（Binary JSON）格式存储数据，由 C++ 编写。它介于关系型数据库和键值存储之间，兼具丰富的查询能力和灵活的数据模型。

---

## Q：MongoDB 的核心概念有哪些？

| 关系型数据库 | MongoDB | 说明 |
|---|---|---|
| Database | Database | 数据库，一个 MongoDB 实例可承载多个数据库 |
| Table | Collection | 集合，类似于表，但无需预定义 Schema |
| Row | Document | 文档，以 BSON 格式存储，类似 JSON 对象 |
| Column | Field | 字段，文档中的键值对 |
| Primary Key | `_id` | 每个文档必须有 `_id` 字段作为主键 |
| Join | `$lookup` | 聚合管道中的关联操作 |

### 文档(Document)

- MongoDB 中数据的基本单元，本质是一个 BSON 对象
- 示例：

```json
{
  "_id": ObjectId("6507f..."),
  "name": "张三",
  "age": 25,
  "address": {
    "city": "北京",
    "street": "中关村大街"
  },
  "tags": ["Java", "后端"]
}
```

- 支持嵌套文档和数组，天然适合层次化数据

### 集合(Collection)

- 文档的容器，类似于关系型数据库中的表
- 同一集合中的文档结构可以不同（Schema-Free）
- 集合无需事先创建，插入文档时自动创建

### 数据库(Database)

- 集合的容器，一个 MongoDB 实例可承载多个数据库
- 系统保留数据库：`admin`（管理）、`local`（复制）、`config`（分片配置）

---

## Q：BSON 是什么？

BSON（Binary JSON）是 MongoDB 的数据存储格式，是 JSON 的二进制扩展：

| 特性 | JSON | BSON |
|---|---|---|
| 编码 | 文本 | 二进制 |
| 数据类型 | 6 种（string, number, boolean, null, array, object） | 丰富（Date, ObjectId, Int32, Int64, Decimal128, Regex 等） |
| 遍历速度 | 需逐字符解析 | 每个元素有长度前缀，可快速跳过 |
| 体积 | 紧凑 | 因包含类型和长度信息，通常略大 |

---

## Q：MongoDB 的主要特点？

| 特点 | 说明 |
|---|---|
| **Schema-Free** | 文档结构灵活，同一集合中文档可包含不同字段，适合快速迭代 |
| **水平扩展** | 通过分片(Sharding)实现水平扩展，将数据分布到多台机器 |
| **高可用** | 通过副本集(Replica Set)实现自动故障转移，主节点挂掉自动选举新主 |
| **丰富的查询语法** | 支持条件查询、正则、范围、聚合管道、地理空间查询等 |
| **索引支持** | 支持单字段、复合、文本、地理空间、哈希等多种索引 |

---

## Q：聚合管道(Aggregation Pipeline) 是什么？

聚合管道是 MongoDB 的数据处理框架，将数据通过多个阶段(Stage)依次处理，类似于 Linux 管道。

### 常用阶段

| 阶段 | 作用 | 类比 SQL |
|---|---|---|
| `$match` | 过滤文档 | WHERE |
| `$group` | 分组聚合 | GROUP BY |
| `$sort` | 排序 | ORDER BY |
| `$project` | 字段投影/重塑 | SELECT |
| `$limit` | 限制条数 | LIMIT |
| `$skip` | 跳过条数 | OFFSET |
| `$lookup` | 关联查询 | LEFT JOIN |
| `$unwind` | 展开数组 | — |

### 示例

```javascript
db.orders.aggregate([
  { $match: { status: "completed" } },
  { $group: { _id: "$userId", total: { $sum: "$amount" } } },
  { $sort: { total: -1 } },
  { $limit: 10 }
]);
```

## Q：MongoDB 的索引类型有哪些？

| 索引类型 | 说明 |
|---|---|
| **单字段索引** | 对单个字段建索引，默认 `_id` 索引 |
| **复合索引** | 对多个字段组合建索引，遵循最左前缀匹配 |
| **多键索引(Multikey)** | 对数组字段自动创建，为数组中每个元素建一条索引 |
| **文本索引** | 支持全文检索 |
| **地理空间索引** | 2dsphere（球面）、2d（平面），支持附近查询 |
| **哈希索引** | 对字段值的哈希建索引，常用于分片键 |
| **唯一索引** | 保证索引字段值唯一 |

## Q：MongoDB 适用场景与不适用场景？

### 适用场景

- 数据结构不固定、快速迭代的业务（如内容管理系统、用户画像）
- 高写入吞吐（日志、物联网数据、实时分析）
- 需要水平扩展的大数据量场景
- 文档型数据天然嵌套（如订单含商品列表，避免 JOIN）
- 地理位置相关应用（LBS）

### 不适用场景

- 需要复杂多表关联和事务的业务（如银行核心系统）
- 对数据一致性要求极高的场景（强 ACID）
- 数据模型非常稳定且关系复杂的传统 OLTP

## 八股速记

> ⚠️ 简历数据库行写了"熟悉 MySQL、MongoDB、Redis"，MongoDB 会被追"你用它做过什么、和 MySQL 怎么选"，务必能答（🔲 若实际项目未真正用过，如实说"了解模型、做过 demo/学习"，别吹成生产深用）。

- **是什么**：**面向文档的 NoSQL 数据库**，数据以类 JSON 的 **BSON 文档**存储，一条记录 = 一个文档，多个文档组成 **集合（collection，类比表）**。
- **核心特点**：① **Schema 灵活**——同一集合里文档字段可不同，加字段不用改表结构；② **嵌套文档/数组**——一对多可直接内嵌，省 join；③ **水平扩展**——原生支持分片（Sharding）。
- **术语对照 MySQL**：库→库、表→**集合**、行→**文档**、列→**字段**、join→`$lookup`（弱、不推荐重度用）。
- **什么时候用**：数据结构多变/半结构化（日志、埋点、内容、配置）、读多写多要水平扩展、不需要强事务和复杂多表关联的场景。

**⭐ 加分/易错**：
- **别说"MongoDB 不支持事务"**——4.0 起支持**多文档 ACID 事务**，但用它就说明你的模型可能没设计好（该内嵌的没内嵌）。MongoDB 的哲学是**用内嵌文档替代 join**。
- **MySQL vs MongoDB 怎么选**（高频）：要**强事务、复杂关联查询、数据结构稳定**→ MySQL；要**灵活 schema、海量半结构化、快速迭代**→ MongoDB。不是谁取代谁，是**按数据形态和一致性要求选**。
- 索引也走 **B 树**、也支持复合/唯一索引，慢查询排查思路（看是否走索引）和 MySQL 相通（呼应 Q8）。

> 一句话总结：MongoDB 是文档型 NoSQL 数据库，以 BSON 格式存储灵活的文档结构，支持分片水平扩展和副本集高可用，适合数据模型多变、高写入、需水平扩展的场景，但不适合复杂关联和强事务场景。

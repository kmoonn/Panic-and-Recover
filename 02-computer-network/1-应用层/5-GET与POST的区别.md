# GET 与 POST 的区别

## 核心区别

| 维度 | GET | POST |
|---|---|---|
| **语义** | 获取资源 | 提交/创建资源 |
| **参数位置** | URL 查询字符串 `?key=value` | 请求体（Body） |
| **参数长度** | 受 URL 长度限制（浏览器约 2KB~8KB） | 无限制（受服务器配置约束） |
| **安全性** | 参数暴露在 URL 中，不安全 | 参数在 Body 中，相对安全（但 HTTPS 下才真正安全） |
| **缓存** | 浏览器默认缓存 | 浏览器默认不缓存 |
| **历史记录** | 参数保留在浏览器历史中 | 不保留 |
| **书签** | 可收藏为书签 | 不可 |
| **幂等性** | ✅ 幂等（多次请求结果相同） | ❌ 非幂等（每次可能创建新资源） |
| **回退/刷新** | 无副作用 | 浏览器会提示"重新提交" |
| **TCP 包** | 通常 1 个（header + data 一起发） | 通常 2 个（先发 header，再发 body） |

## 安全性澄清

> **POST 并不比 GET 更安全**——两者都是明文传输，抓包都能看到。

| | GET | POST |
|---|---|---|
| 参数可见性 | URL 中可见 | Body 中可见，抓包同样可见 |
| HTTPS 加密 | ✅ 加密后安全 | ✅ 加密后安全 |
| XSS 风险 | 参数在 URL，易被注入 | 相对不易，但仍需转义 |

**真正安全的传输靠 HTTPS，不是靠 POST。**

## 幂等性详解

| 方法 | 幂等？ | 原因 |
|---|---|---|
| GET | ✅ | 查询不改变服务器状态，调 1 次和调 100 次结果一样 |
| POST | ❌ | 每次可能创建新资源（如提交订单） |
| PUT | ✅ | 整体替换，多次结果一样 |
| DELETE | ✅ | 删一次和删多次结果一样 |

## 应用场景

| 场景 | 用 GET | 用 POST | 原因 |
|---|---|---|---|
| 搜索查询 | ✅ | | 幂等、可缓存、可书签 |
| 分页列表 | ✅ | | 参数简单、可分享链接 |
| 用户登录 | | ✅ | 密码不能出现在 URL |
| 提交表单/创建订单 | | ✅ | 非幂等、数据量大 |
| 文件上传 | | ✅ | 数据在 Body，无长度限制 |
| 删除/更新 | DELETE/PUT | | 语义更准确 |
| API 查询 | ✅ | | RESTful 语义 |

## RESTful 语义

HTTP 方法即 CRUD 语义：

| 操作 | 方法 | 示例 |
|---|---|---|
| 查 | GET | `GET /users/1` |
| 增 | POST | `POST /users` |
| 改 | PUT / PATCH | `PUT /users/1` |
| 删 | DELETE | `DELETE /users/1` |

## 常见面试陷阱

| 陷阱 | 正解 |
|---|---|
| "POST 比 GET 安全" | 都明文，安全靠 HTTPS |
| "GET 只能传字符串" | 可以传任意 URL 编码的数据 |
| "POST 不能传 URL 参数" | 可以，POST 也能有 query string |
| "GET 请求没有 Body" | HTTP 规范不禁止，但浏览器/框架通常不支持 |
| "GET 和 POST 是 TCP 层面的区别" | TCP 层面无区别，差异在 HTTP 语义和浏览器约定 |

## 总结一句话

> GET 幂等可缓存，参数在 URL，用于获取；POST 非幂等不缓存，参数在 Body，用于提交。安全性靠 HTTPS 不靠方法，核心区别在**语义**。

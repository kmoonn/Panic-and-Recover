# 缓存穿透、缓存击穿、缓存雪崩

## 缓存穿透（Penetration）

### 是什么

请求的数据**在缓存和数据库中都不存在**，每次请求都穿透缓存直接打到数据库。

### 场景

- 恶意攻击：用大量不存在的 ID 查询（如 `id = -1`）
- 业务bug：查询了不存在的数据

### 解决

| 方案 | 原理 | 优缺点 |
|---|---|---|
| **缓存空值** | 查 DB 为空时，缓存 `null` 并设短 TTL | 简单，但可能缓存大量空 key |
| **布隆过滤器** | 请求先过布隆过滤器，不存在的直接拒绝 | 空间小、速度快，但有误判率（可能漏放） |

```python
# 缓存空值
result = cache.get(key)
if result is None:
    result = db.query(key)
    if result is None:
        cache.set(key, "NULL", ttl=60)  # 短 TTL
    else:
        cache.set(key, result, ttl=3600)
elif result == "NULL":
    return None
```

## 缓存击穿（Breakdown）

### 是什么

**某个热点 key 过期的瞬间**，大量并发请求同时打到数据库，像是缓存被"击穿"了一个洞。

### 与穿透的区别

- 穿透：数据**根本不存在**
- 击穿：数据**存在但过期了**，只是瞬时并发量大

### 解决

| 方案 | 原理 | 优缺点 |
|---|---|---|
| **互斥锁** | 只让一个请求查 DB，其他等待后读缓存 | 避免并发穿库，但有等待延迟 |
| **逻辑过期** | 缓存不设 TTL，数据中存逻辑过期时间，过期后异步线程更新 | 用户无感，但短暂返回旧数据 |

```python
# 互斥锁方案
def get_with_lock(key):
    result = cache.get(key)
    if result is None:
        if redis.setnx(f"lock:{key}", 1, ex=5):  # 获取锁
            try:
                result = db.query(key)
                cache.set(key, result, ttl=3600)
            finally:
                redis.delete(f"lock:{key}")
        else:
            time.sleep(0.1)
            return get_with_lock(key)  # 重试
    return result
```

## 缓存雪崩（Avalanche）

### 是什么

**大量 key 同一时间过期**，或**缓存节点宕机**，导致请求全部打到 DB，数据库压力暴增甚至崩溃。

### 场景

- 批量设置缓存时用了相同 TTL，到期后同时失效
- Redis 集群某个节点宕机

### 解决

| 方案 | 原理 | 适用场景 |
|---|---|---|
| **TTL 加随机值** | `TTL = 3600 + random(0, 300)`，打散过期时间 | 预防同时过期 |
| **缓存高可用** | Redis Sentinel / Cluster | 防节点宕机 |
| **限流降级** | DB 承受不了时直接降级返回 | 兜底保护 |
| **互斥锁** | 同击穿的锁方案 | 防并发穿库 |
| **永不过期 + 异步更新** | 缓存不设 TTL，后台定时刷新 | 核心热点数据 |

## 三者对比

| | 缓存穿透 | 缓存击穿 | 缓存雪崩 |
|---|---|---|---|
| **原因** | 数据不存在 | 热点 key 过期 | 大量 key 同时过期 / 缓存宕机 |
| **关键词** | 不存在 | 热点 + 并发 | 批量 + 同时 |
| **核心解决** | 布隆过滤器 / 缓存空值 | 互斥锁 / 逻辑过期 | TTL 加随机值 / 高可用 / 限流降级 |

## 一句话总结

> 穿透是数据不存在，击穿是热点key过期，雪崩是大量key同时失效；分别用布隆过滤器、互斥锁、TTL加随机值解决

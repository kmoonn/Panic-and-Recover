# 覆盖索引

## 什么是覆盖索引？

覆盖索引是指**查询所需的所有列都包含在索引中**，无需回表到聚簇索引查询数据，直接从索引树返回结果，大幅提升查询性能。

## 工作原理

### 普通查询（需要回表）

```
1. 在二级索引树查找 → 找到主键值
2. 回到聚簇索引树查找 → 获取完整行数据
3. 返回结果
```

### 覆盖索引查询（无需回表）

```
1. 在索引树查找 → 索引中已包含所有需要的列
2. 直接返回结果（无需回表）
```

```sql
-- 假设有联合索引 idx_name_age(name, age)

-- 需要回表：SELECT 中包含索引外的列
SELECT name, age, email FROM user WHERE name = '张三';
-- 索引中没有 email 列，需要回表查聚簇索引

-- 覆盖索引：SELECT 的列都在索引中
SELECT name, age FROM user WHERE name = '张三';
-- 索引中有 name 和 age，无需回表
```

## EXPLAIN 中的标识

使用覆盖索引时，EXPLAIN 的 Extra 列会显示 **Using index**：

```sql
EXPLAIN SELECT name, age FROM user WHERE name = '张三';
-- Extra: Using index  ← 表示使用了覆盖索引
```

| Extra 值 | 含义 |
|---|---|
| Using index | 使用了覆盖索引，无需回表 |
| NULL | 需要回表查询 |
| Using index condition | 使用了索引下推（ICP），但仍需回表 |

## 使用场景

1. **SELECT 列恰好是索引列**：查询的列全部包含在索引中
2. **联合索引覆盖查询**：联合索引包含 WHERE 条件列 + SELECT 列
3. **COUNT 查询**：`SELECT COUNT(*) FROM t WHERE name = ?`，如果 name 有索引则可覆盖

### 优化示例

```sql
-- 表结构：user(id, name, age, email)
-- 索引：INDEX idx_name_age(name, age)

-- 未覆盖：需要回表取 email
SELECT name, age, email FROM user WHERE name = '张三';

-- 方案1：修改查询，只查索引列
SELECT name, age FROM user WHERE name = '张三';

-- 方案2：建立覆盖索引
ALTER TABLE user ADD INDEX idx_name_age_email(name, age, email);
```

## 覆盖索引的优势

| 优势 | 说明 |
|---|---|
| 减少 I/O | 索引通常比数据行小得多，读取索引页更少 |
| 避免回表 | 省去聚簇索引查找步骤 |
| 利用索引顺序 | 索引有序，范围扫描效率高 |

## 面试高频问题

### Q: 覆盖索引是什么？为什么能提升性能？

覆盖索引是指查询的所有列都在索引中，无需回表。提升性能的原因：
1. **减少 I/O**：索引数据量远小于全表数据，扫描页数更少
2. **避免回表**：省去从二级索引到聚簇索引的查找过程
3. 索引是有序存储的，顺序读取效率更高

### Q: 怎么判断是否用了覆盖索引？

通过 `EXPLAIN` 查看 Extra 列是否显示 **Using index**。

## 一句话总结

覆盖索引是指查询的所有列都在索引中、无需回表直接返回结果的查询方式，EXPLAIN 中表现为 Using index，通过减少 I/O 和避免回表大幅提升查询性能。

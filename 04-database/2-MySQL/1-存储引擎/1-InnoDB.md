# InnoDB

## InnoDB 是什么？

InnoDB 是 MySQL 5.5+ 的**默认存储引擎**，是一个支持事务、行级锁、外键的高可靠性存储引擎，适用于对数据一致性要求高的场景。

## 核心特性

| 特性 | 说明 |
|---|---|
| 事务支持 | 支持 ACID 事务，通过 redo log + undo log 保证 |
| 行级锁 | 锁粒度细，并发性能高 |
| MVCC | 多版本并发控制，实现一致性非锁定读 |
| 外键 | 唯一支持外键约束的存储引擎 |
| 崩溃恢复 | Crash-Safe，通过 redo log 实现崩溃后自动恢复 |
| 聚簇索引 | 主键索引即数据，数据和主键索引存储在一起 |

## 底层结构：聚簇索引

InnoDB 采用**聚簇索引**（Clustered Index）组织数据：

- **主键索引即数据**：叶子节点直接存储完整的行数据，主键索引也称为聚簇索引
- **二级索引回表查询**：二级索引的叶子节点存储的是主键值，查询时需要先查二级索引拿到主键，再到聚簇索引查找完整数据，这个过程称为**回表**

```
聚簇索引结构（B+Tree）：
        [10|20|30]
       /    |     \
  [5|10] [15|20] [25|30]
    ↓       ↓       ↓
  行数据   行数据   行数据

二级索引结构：
  索引列值 → 主键值（需回表查聚簇索引）
```

## 事务支持机制

| 日志类型 | 作用 | 保证的特性 |
|---|---|---|
| redo log | 记录物理修改，崩溃时重做 | 持久性（Durability） |
| undo log | 记录数据修改前的旧值 | 原子性（Atomicity）+ MVCC |
| MVCC | 每行数据有隐藏列（trx_id, roll_pointer），实现快照读 | 一致性读（Consistent Read） |

- **redo log**：WAL（Write-Ahead Logging）策略，先写日志再写磁盘，保证崩溃后数据不丢
- **undo log**：事务回滚时用 undo log 恢复数据；MVCC 通过 undo log 版本链实现快照读
- **MVCC**：通过 ReadView + undo log 版本链，实现读写不冲突

## 锁机制

InnoDB 行级锁的三种类型：

| 锁类型 | 锁定范围 | 说明 |
|---|---|---|
| 记录锁（Record Lock） | 单条索引记录 | 锁住一行记录 |
| 间隙锁（Gap Lock） | 索引记录之间的间隙 | 防止幻读，锁住范围不含记录本身 |
| 临键锁（Next-Key Lock） | 记录 + 间隙 | 记录锁 + 间隙锁的组合，左开右闭区间 |

> 注意：InnoDB 的行锁实际上是**锁索引项**，不是锁数据行。如果查询没有走索引，则会退化为表级锁。

## InnoDB 与 MyISAM 对比

| 对比项 | InnoDB | MyISAM |
|---|---|---|
| 事务 | 支持 ACID | 不支持 |
| 锁粒度 | 行级锁 | 表级锁 |
| 外键 | 支持 | 不支持 |
| 崩溃恢复 | 支持（Crash-Safe） | 不支持，可能损坏 |
| MVCC | 支持 | 不支持 |
| 全文索引 | InnoDB 5.6+ 支持 | 支持 |
| 存储文件 | .ibd（数据+索引） | .MYD + .MYI（数据与索引分离） |
| COUNT(*) | 需要遍历 | 直接存储行数 |
| 适用场景 | 需要事务、高并发读写 | 读多写少、不需事务 |

## 适用场景

- 需要事务保证的业务（订单、支付、账户）
- 高并发读写场景
- 数据一致性要求高的场景
- 需要外键约束的场景

## 一句话总结

InnoDB 是 MySQL 默认的事务型存储引擎，通过聚簇索引组织数据，依赖 redo log（持久性）、undo log（原子性/MVCC）和行级锁实现高并发下的 ACID 事务保证，是绝大多数业务场景的首选引擎。

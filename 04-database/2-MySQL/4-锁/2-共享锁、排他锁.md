# 共享锁、排他锁

## Q：什么是共享锁和排他锁？

共享锁(Shared Lock)和排他锁(Exclusive Lock)是 InnoDB 中**行级锁**的两种基本类型，也称为**读锁(S锁)**和**写锁(X锁)**。

### 共享锁(S锁/读锁)

- 允许多个事务**同时**对同一行数据加共享锁
- 加了共享锁的行，**阻止**其他事务对其加排他锁
- 目的：保证多个事务可以同时读，但不能同时写

### 排他锁(X锁/写锁)

- 只允许**一个**事务对某行数据加排他锁
- 加了排他锁的行，**阻止**其他事务对其加任何锁（共享锁或排他锁）
- 目的：保证当前事务独占修改权

---

## Q：加锁语法？

### 加共享锁

```sql
SELECT * FROM user WHERE id = 1 LOCK IN SHARE MODE;
-- MySQL 8.0+ 也可用：
SELECT * FROM user WHERE id = 1 FOR SHARE;
```

### 加排他锁

```sql
SELECT * FROM user WHERE id = 1 FOR UPDATE;
```

### 隐式加锁

| 操作 | 自动加的锁 |
|---|---|
| `SELECT`（普通读/快照读） | 不加任何锁 |
| `SELECT ... LOCK IN SHARE MODE` | S 锁 |
| `SELECT ... FOR UPDATE` | X 锁 |
| `INSERT` | X 锁 |
| `UPDATE` | X 锁 |
| `DELETE` | X 锁 |

> 普通的 SELECT（快照读）不加锁，通过 MVCC 读取历史版本。

---

## Q：S锁与X锁的兼容性矩阵？

|  | 已有 S 锁 | 已有 X 锁 |
|---|---|---|
| **请求 S 锁** | 兼容 | 不兼容（阻塞） |
| **请求 X 锁** | 不兼容（阻塞） | 不兼容（阻塞） |

- S 与 S 兼容：多个事务可同时读
- S 与 X 互斥：读的时候不能写
- X 与 X 互斥：写的时候不能写

---

## Q：InnoDB 中 S/X 锁的粒度？

InnoDB 的 S 锁和 X 锁是**行级锁**，锁定的是索引记录（而非整张表）。

- 如果 SQL 没有走索引，则退化为**表级锁**（锁定所有行）
- 锁的是索引记录，不是数据行本身

---

## Q：什么是意向锁？

意向锁(Intention Lock)是**表级锁**，用于**快速判断表中是否存在行级锁**，避免逐行检查。

### 为什么需要意向锁？

如果没有意向锁：
- 事务 A 在某行加了 X 行锁
- 事务 B 想加表级 X 锁，需要逐行检查是否有行锁 → 效率极低

有了意向锁：
- 事务 A 加行级 X 锁前，先在表级加意向排他锁(IX)
- 事务 B 加表级 X 锁时，只需检查表级是否有 IX 锁 → 效率高

### 意向锁类型

| 类型 | 全称 | 说明 |
|---|---|---|
| **IS** | Intention Shared Lock（意向共享锁） | 事务打算对某行加 S 锁前，先在表级加 IS |
| **IX** | Intention Exclusive Lock（意向排他锁） | 事务打算对某行加 X 锁前，先在表级加 IX |

- 意向锁是**自动加的**，不需要手动声明
- 意向锁之间**互相兼容**（IS 与 IS、IS 与 IX、IX 与 IX 均兼容）
- 意向锁不与行级锁冲突，只与**表级锁**冲突

---

## Q：意向锁与 S/X 锁的兼容性矩阵？

|  | IS | IX | S（表级） | X（表级） |
|---|---|---|---|---|
| **IS** | 兼容 | 兼容 | 兼容 | 不兼容 |
| **IX** | 兼容 | 兼容 | 不兼容 | 不兼容 |
| **S（表级）** | 兼容 | 不兼容 | 兼容 | 不兼容 |
| **X（表级）** | 不兼容 | 不兼容 | 不兼容 | 不兼容 |

关键理解：
- IS/IX 之间互相兼容：意向只是"打算"加行锁，不冲突
- IX 与 S(表级) 不兼容：表级 S 锁要阻止任何行级 X 锁
- IS/IX 与 X(表级) 不兼容：表级 X 锁要独占整张表

---

## Q：意向锁的加锁流程示例？

```
事务A: SELECT * FROM user WHERE id=1 FOR UPDATE;
       1. 自动在 user 表加 IX 锁（表级）
       2. 在 id=1 的行加 X 锁（行级）

事务B: LOCK TABLES user READ;
       1. 请求在 user 表加 S 锁（表级）
       2. 检测到表上有 IX 锁 → 与 S(表级) 不兼容 → 阻塞等待
```

> 一句话总结：共享锁(S锁)允许多事务并发读但阻止写，排他锁(X锁)独占读写权限；意向锁(IS/IX)是表级锁，用于快速判断表中是否有行锁，避免逐行扫描，意向锁之间互相兼容，只与表级 S/X 锁冲突。

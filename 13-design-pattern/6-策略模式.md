# 策略模式

## 什么是策略模式

策略模式（Strategy Pattern）定义一系列算法，将每一个算法封装起来，并使它们可以互相替换。让算法的变化独立于使用算法的客户。

**核心思想**：将算法族分别封装，使算法之间可以互相替换，让算法的变化不会影响到使用算法的客户端。

```
┌──────────┐      ┌─────────────────┐
│ Context  │─────→│ <<interface>>   │
│ (上下文)  │      │   Strategy      │
└──────────┘      └────────┬────────┘
     │                      │
     │ 持有 Strategy 引用    │ 实现
     │               ┌──────┼──────┐
     ▼               ▼      ▼      ▼
              ┌──────┐ ┌──────┐ ┌──────┐
              │策略A │ │策略B │ │策略C │
              └──────┘ └──────┘ └──────┘
```

---

## 解决什么问题

| 问题 | 说明 |
|------|------|
| 大量 if-else / switch | 不同业务逻辑用条件分支硬编码，难以维护 |
| 算法需要动态切换 | 运行时根据条件选择不同算法 |
| 新算法频繁添加 | 每加一种算法就要改现有代码，违反开闭原则 |

**典型场景**：支付方式选择（微信/支付宝/银行卡）、折扣计算策略、排序算法切换。

---

## 如何消除 if-else

核心思路：**策略接口 + 枚举/Map 工厂注册**

```
Before：if-else 硬编码
  if (type == "VIP") price *= 0.8;
  else if (type == "SVIP") price *= 0.7;

After：策略模式 + 工厂
  DiscountStrategy strategy = DiscountFactory.getStrategy(type);
  price = strategy.calculate(price);
```

新增策略只需：添加一个实现类 + 注册到工厂，**不改现有代码**，符合开闭原则。

## 策略模式在源码中的应用

| 框架 | 应用 |
|------|------|
| **JDK** | `Comparator` 接口——不同的排序策略 |
| **JDK** | `RejectedExecutionHandler`——线程池 4 种拒绝策略 |
| **Spring** | `Resource` 接口——ClassPathResource / FileSystemResource / UrlResource |

### 线程池拒绝策略（4 个 Strategy）

| 策略 | 行为 |
|------|------|
| AbortPolicy | 抛出异常（默认） |
| CallerRunsPolicy | 调用者线程执行 |
| DiscardPolicy | 静默丢弃 |
| DiscardOldestPolicy | 丢弃最老任务 |

运行时可通过 `setRejectedExecutionHandler()` 动态切换策略。

## 面试高频

### 策略模式 vs 状态模式

| 维度 | 策略模式 | 状态模式 |
|------|---------|---------|
| 目的 | 算法切换 | 状态转换 |
| 切换方式 | 客户端主动切换 | 状态内部自动转换 |
| 关注点 | "怎么做"（选哪种算法） | "在什么状态"（当前状态的行为） |
| 类比 | 选支付方式 | 红绿灯状态变化 |

### 策略模式 vs 模板方法

| 维度 | 策略模式 | 模板方法 |
|------|---------|---------|
| 实现方式 | 组合（持有策略引用） | 继承（子类重写钩子方法） |
| 算法变化 | 运行时可切换 | 编译时由子类决定 |
| 耦合度 | 低（组合优于继承） | 较高（继承耦合） |

### 策略模式的缺点

| 缺点 | 说明 |
|------|------|
| 类数量膨胀 | 每个策略一个类，策略多时类很多 |
| 客户端必须了解策略 | 需要知道有哪些策略可选用 |
| 策略间通信困难 | 不同策略之间无法共享状态 |

---

## 一句话总结

策略模式将算法族分别封装为可互换的策略类，通过组合替代继承，让算法可以运行时动态切换，是消除 if-else/switch 的利器，典型应用如 JDK 的 Comparator 和线程池拒绝策略。

# 责任链模式

## 什么是责任链模式

责任链模式（Chain of Responsibility）是行为型设计模式，将请求的发送与接收解耦，让多个处理对象都有机会处理请求，请求沿链传递直到被处理为止。

**核心思想**：每个处理者判断自己能否处理——能则处理，不能则转发给下一个处理者。

**现实类比**：审批请假——你提交请假单→组长审批→经理审批→总监审批，每个节点可批准或向上转交。

```
Client → Handler1 → Handler2 → Handler3
           │            │           │
         处理?         处理?       处理?
         │             │           │
         否→           否→         是→ 处理完毕
```

| 角色 | 职责 |
|------|------|
| 抽象处理者（Handler） | 定义处理接口，持有下一个处理者引用 |
| 具体处理者 | 实现处理逻辑，判断是否处理或转发 |
| 客户端 | 组装链并提交请求，不关心谁处理 |

## 各框架中的实现

### Java: Servlet Filter

- 基于**回调机制**，`doFilter()` 中调用 `chain.doFilter()` 继续传递
- 请求先经过所有 Filter 再进入 Servlet，响应反向执行
- 典型用途：全局日志、字符编码、跨域、安全认证

### Java: Spring Interceptor

- **三阶段拦截**：
  - `preHandle()` — 请求前，返回 false 可**中断链**
  - `postHandle()` — 视图渲染前
  - `afterCompletion()` — 请求完成后
- 典型用途：权限校验、参数校验、请求耗时统计

### Python: Django 中间件

Django 中间件是责任链模式——每个中间件的 `process_request()` / `process_response()` 形成链式调用：

```
请求 → Middleware1.process_request → Middleware2.process_request → 视图函数
     ← Middleware2.process_response ← Middleware1.process_response ← 响应
```

### Go: net/http Handler 链

Go 标准库的 `http.Handler` 天然支持责任链：

```
func loggingMiddleware(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        log.Println(r.URL)          // 前置逻辑
        next.ServeHTTP(w, r)        // 传递给下一个 Handler
    })
}
```

### Netty ChannelPipeline

- **双向责任链**：入站（Inbound）和出站（Outbound）事件分别沿链传播
- 入站：IO 线程触发，Head → Tail
- 出站：业务线程触发，Tail → Head
- 支持运行时动态增删 Handler

### Kafka Interceptor / Dubbo Filter

消息队列和 RPC 框架也用责任链：Kafka 的 Producer/Consumer Interceptor 链、Dubbo 的 Filter 链（MonitorFilter → TimeoutFilter → ExceptionFilter → …）

---

## 执行顺序（Servlet + Spring）

```
请求进入：Servlet Filter → Spring Interceptor → Controller
响应返回：Controller → Spring Interceptor → Servlet Filter（反向）
```

## 适用场景

| 场景 | 说明 | 示例 |
|------|------|------|
| 框架拦截过滤 | 请求预处理链 | Servlet Filter、Django Middleware |
| 多级校验 | 参数→权限→风控链式校验 | 下单校验链 |
| 审批工作流 | 每级可通过/驳回/转交 | OA 审批流 |
| 报文处理 | 解密→脱敏→埋点→加密 | 消息中间件 |

## 面试高频

### 责任链 vs 装饰器模式

| 维度 | 责任链 | 装饰器 |
|------|--------|--------|
| 目的 | 多个处理者**选择处理** | 层层**增强功能** |
| 执行行为 | 可在任意节点**终止** | **所有**装饰器都会执行 |
| 处理者关系 | 独立判断，互不依赖 | 逐层包裹，层层委托 |
| 类比 | 审批流（组长→经理→总监） | Java IO 流套娃 |

### Filter 和 Interceptor 的区别

| 维度 | Servlet Filter | Spring Interceptor |
|------|---------------|-------------------|
| 所属层级 | Web 容器（Servlet 规范） | Spring MVC 框架 |
| 拦截范围 | 所有请求（包括静态资源） | 仅 Controller 请求 |
| 执行时机 | DispatcherServlet **之前** | DispatcherServlet **之后**、Controller **之前** |
| 典型用途 | 编码、跨域、全局处理 | 权限、参数校验、耗时统计 |

### 责任链的优缺点

| ✅ 优点 | ❌ 缺点 |
|---------|---------|
| 解耦发送者与接收者 | 链过长影响性能 |
| 动态调整链顺序和组成 | 调试困难（请求经过多个处理者） |
| 符合开闭原则 | 不保证请求一定被处理 |

---

## 一句话总结

责任链模式将请求发送与接收解耦，请求沿链传递直到被处理，Servlet Filter、Spring Interceptor、Django Middleware、Netty Pipeline 是经典实现，与装饰器的本质区别在于责任链可中途终止而装饰器层层执行。

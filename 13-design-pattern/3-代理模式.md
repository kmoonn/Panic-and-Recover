# 代理模式

## 什么是代理模式？

代理模式（Proxy Pattern）为其他对象提供代理以控制对这个对象的访问。属于结构型设计模式。

**核心思想**：客户端不直接访问目标对象，而是通过代理对象间接访问，代理对象可以在不修改目标对象的前提下增加额外功能（控制访问、增强逻辑等）。

**三要素**：
- **Subject（抽象主题）**：定义目标对象和代理对象的共同接口
- **RealSubject（真实主题）**：目标对象，实际执行业务逻辑
- **Proxy（代理）**：持有目标对象引用，控制访问并增强功能

```
Client → Proxy → RealSubject
           ↑
     增强逻辑（日志/权限/事务）
```

## 三种代理类型

### 1. 静态代理

手动编写代理类，编译期确定代理关系。

- **缺点**：每个目标类都需手动编写代理类，接口方法增加时代理类也要同步修改，维护成本高
- **实际使用**：几乎不用，仅教学用途

### 2. JDK 动态代理

基于接口，运行时动态生成代理类。核心 API：`Proxy` + `InvocationHandler`。

**原理**：
1. 运行时通过 `Proxy.newProxyInstance()` 生成实现了目标接口的代理类字节码
2. 代理类将方法调用转发给 `InvocationHandler.invoke()`
3. 在 `invoke()` 中实现增强逻辑

**限制**：目标类必须实现接口，无法代理没有接口的类。

### 3. CGLIB 动态代理

基于继承，运行时生成目标类的子类来实现代理。

**原理**：
1. 运行时生成目标类的子类
2. 子类重写所有非 final 方法
3. 方法调用转发给 `MethodInterceptor.intercept()`

**限制**：无法代理 `final` 类和 `final` 方法。

---

## JDK 动态代理 vs CGLIB 对比

| 特性 | JDK 动态代理 | CGLIB 动态代理 |
|------|-------------|---------------|
| 实现方式 | 基于接口 | 基于继承（生成子类） |
| 是否需要接口 | ✅ 目标类必须实现接口 | ❌ 可以代理普通类 |
| 无法代理的场景 | 无接口的类 | final 类、final 方法 |
| 性能（创建代理） | 较快 | 较慢（生成字节码更复杂） |
| 性能（方法调用） | 略慢（反射调用） | 较快（FastClass 机制） |
| 依赖 | JDK 内置 | 需要第三方库 |

## 应用场景

| 场景 | 说明 | 示例 |
|------|------|------|
| AOP | 不修改源码增强方法 | Spring 事务、日志、权限控制 |
| RPC 远程调用 | 本地代理屏蔽网络细节 | Dubbo Consumer 端代理 |
| 缓存代理 | 缓存方法返回值 | MyBatis Mapper 代理 |
| 防火墙代理 | 控制网络访问权限 | Nginx 反向代理 |
| 延迟加载 | 按需加载重量级对象 | Hibernate 懒加载代理 |

## 面试高频：Spring AOP 用哪种代理？

| 版本 | 默认代理方式 | 说明 |
|------|------------|------|
| Spring | 目标类有接口 → JDK 动态代理；无接口 → CGLIB | 按条件自动选择 |
| SpringBoot 2.x+ | **CGLIB**（`proxy-target-class=true`） | JDK 代理对象无法强转目标类类型，使用不便 |
| SpringBoot 3.x | **CGLIB** | 同上，无接口时只能用 CGLIB |

## 面试高频问题

**Q：JDK 动态代理和 CGLIB 的区别？**
A：JDK 基于接口，目标类必须实现接口，方法调用走反射，无需额外依赖；CGLIB 基于继承，生成目标类子类，不能代理 final 类/方法，方法调用用 FastClass 机制更快，需第三方库。

**Q：为什么 SpringBoot 2.x 默认改用 CGLIB？**
A：JDK 动态代理基于接口，生成的代理对象只能强转接口类型不能强转目标类类型，使用不便。CGLIB 生成子类，代理对象可以直接强转目标类，更灵活。

**Q：CGLIB 为什么不能代理 final 方法？**
A：CGLIB 通过生成子类重写方法实现代理，final 方法不可重写，因此无法拦截增强。final 类同理——无法被继承。

---

## 一句话总结

代理模式通过代理对象控制对目标对象的访问，JDK 动态代理基于接口、CGLIB 基于继承，Spring AOP 在 SpringBoot 2.x 后默认使用 CGLIB，核心应用场景是 AOP（事务、日志、权限等）。

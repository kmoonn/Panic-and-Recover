# 接口与抽象类的区别

## 核心对比

| 对比维度 | 接口（Interface） | 抽象类（Abstract Class） |
|---|---|---|
| 实例化 | 不能实例化 | 不能实例化 |
| 构造方法 | 无（Java 8+ 也不支持） | 有，子类实例化时调用 |
| 成员变量 | 只能是 `public static final`（常量） | 任意访问修饰符，可以有实例变量 |
| 普通方法 | Java 7：无；Java 8+：`default`/`static`；Java 9+：`private` | 可以有具体实现的方法 |
| 抽象方法 | `public abstract`（默认） | `protected abstract` 或 `public abstract` |
| 访问修饰符 | 方法默认 `public`，Java 9+ 支持 `private` | 任意（`public`/`protected`/`private`） |
| 多继承 | 支持，一个类可实现多个接口 | 不支持，一个类只能继承一个抽象类 |
| 设计意图 | 定义**行为契约**（能做什么） | 定义**共同属性和行为**（是什么） |
| 与类的关系 | `implements`（实现） | `extends`（继承） |
| 默认方法冲突 | 多接口有相同 default 方法时需显式重写 | 不存在此问题（单继承） |
| static 方法 | Java 8+ 支持 | 一直支持 |
| 内部类 | 支持 | 支持 |
| this/super | 无 `this`，无 `super` 构造调用 | 有 `this`，可调用 `super` 构造 |

## 接口（Interface）

接口定义的是**行为契约**，描述"能做什么"。

```java
public interface Flyable {
    // 常量（隐式 public static final）
    int MAX_HEIGHT = 10000;

    // 抽象方法（隐式 public abstract）
    void fly();

    // Java 8+: default 方法（提供默认实现）
    default void land() {
        System.out.println("Landing...");
    }

    // Java 8+: static 方法
    static void checkWeather() {
        System.out.println("Weather is fine");
    }

    // Java 9+: private 方法（供 default 方法复用）
    private void log(String msg) {
        System.out.println(msg);
    }
}
```

**Java 版本演进对接口的影响：**

| Java 版本 | 新增能力 |
|---|---|
| Java 7 及以前 | 只有常量和抽象方法 |
| Java 8 | `default` 方法、`static` 方法 |
| Java 9 | `private` 方法 |

## 抽象类（Abstract Class）

抽象类定义的是**共同属性和行为**，描述"是什么"，适合有 IS-A 关系的场景。

```java
public abstract class Animal {
    // 实例变量（有状态）
    protected String name;
    protected int age;

    // 构造方法
    public Animal(String name, int age) {
        this.name = name;
        this.age = age;
    }

    // 具体方法（子类可直接使用或重写）
    public void eat() {
        System.out.println(name + " is eating");
    }

    // 抽象方法（子类必须实现）
    public abstract void makeSound();
}
```

## 何时用接口、何时用抽象类

| 场景 | 选择 | 原因 |
|---|---|---|
| 定义能力/行为 | 接口 | 如 `Serializable`、`Comparable`、`Runnable` |
| 多个不相关的类有共同行为 | 接口 | 如鸟和飞机都能飞，实现 `Flyable` |
| 有共同状态和实现逻辑 | 抽象类 | 如 `Animal` 有 name/age 属性 |
| IS-A 关系 | 抽象类 | 如 Dog is an Animal |
| 需要构造方法或实例变量 | 抽象类 | 接口不支持 |
| 需要多继承 | 接口 | Java 单继承，但可多实现 |

## 面试高频

**Q：JDK 8 后接口有了 default 方法和 static 方法，接口和抽象类的边界变模糊了，怎么选？**

A：虽然语法上边界模糊了，但设计意图没变：
- **接口**仍是"行为契约"，侧重"能做什么"。default 方法是为了接口演进而设计（给已有实现类添加新方法而不破坏兼容性），不是为了替代抽象类
- **抽象类**仍是"本质定义"，侧重"是什么"，有状态（实例变量）和构造逻辑
- 核心判断：**需要状态/构造方法 → 抽象类；只定义行为 → 接口**

**Q：接口可以 new 吗？**

A：不能直接 `new`，但可以用匿名内部类的方式实现接口并实例化：`new Flyable() { @Override public void fly() { ... } }`，本质是创建了一个实现接口的匿名类对象。

## 一句话总结

接口定义行为契约（能做什么），支持多实现；抽象类定义共同属性和行为（是什么），支持状态和构造方法；JDK 8 后接口增强了默认方法能力，但两者设计意图不同，选择依据是"是否需要状态和 IS-A 关系"。

# 内存模型

## 概述

JVM 内存模型（运行时数据区，Runtime Data Area）是 JVM 在执行 Java 程序期间管理的内存区域。JVM 规范定义了五大区域，按线程共享性分为两类：

```
┌─────────────────────────────────────────────┐
│              JVM 运行时数据区                  │
│                                             │
│  线程私有                          线程共享    │
│  ┌──────────────┐         ┌──────────────┐  │
│  │  程序计数器    │         │     堆        │  │
│  ├──────────────┤         │  (Heap)       │  │
│  │  虚拟机栈     │         ├──────────────┤  │
│  │  (VM Stack)  │         │   方法区       │  │
│  ├──────────────┤         │ (Method Area) │  │
│  │ 本地方法栈    │         └──────────────┘  │
│  │(Native Stack)│                           │
│  └──────────────┘                           │
└─────────────────────────────────────────────┘
```

## 五大区域详解

### 1. 程序计数器（PC Register）

| 属性 | 说明 |
|---|---|
| 线程私有 | 每个线程一个 |
| 存储内容 | 当前线程执行的字节码行号 |
| 异常 | 唯一不会 OOM 的区域 |
| 用途 | 字节码解释器通过改变 PC 来选取下一条指令 |

> 如果执行的是 Native 方法，PC 值为 `undefined`。

### 2. 虚拟机栈（VM Stack）

| 属性 | 说明 |
|---|---|
| 线程私有 | 每个线程一个 |
| 存储内容 | 栈帧（Stack Frame） |
| 异常 | `StackOverflowError`（栈深度超限）、`OutOfMemoryError`（无法分配新栈） |

每个方法调用创建一个**栈帧**，包含：

```
┌──────────────────────┐
│       栈帧            │
│ ┌──────────────────┐ │
│ │  局部变量表        │ │  ← 基本类型、对象引用、returnAddress
│ ├──────────────────┤ │
│ │  操作数栈         │ │  ← 计算的中间结果
│ ├──────────────────┤ │
│ │  动态链接         │ │  ← 指向运行时常量池的方法引用
│ ├──────────────────┤ │
│ │  方法返回地址      │ │  ← 方法正常退出或异常退出后返回的地址
│ └──────────────────┘ │
└──────────────────────┘
```

### 3. 本地方法栈（Native Method Stack）

| 属性 | 说明 |
|---|---|
| 线程私有 | 每个线程一个 |
| 存储内容 | Native 方法的调用状态 |
| 异常 | `StackOverflowError`、`OutOfMemoryError` |
| 与 VM Stack 区别 | 服务对象不同：VM Stack 服务 Java 方法，Native Stack 服务 Native 方法 |

> HotSpot 将虚拟机栈和本地方法栈合二为一。

### 4. 堆（Heap）

| 属性 | 说明 |
|---|---|
| 线程共享 | 所有线程共享 |
| 存储内容 | 对象实例、数组 |
| 异常 | `OutOfMemoryError: Java heap space` |
| 大小 | JVM 启动时创建，最大可由 `-Xmx` 指定 |

**堆的分代结构：**

```
┌─────────────────────────────────────────────┐
│                    堆 (Heap)                  │
│ ┌───────────────────────┬──────────────────┐ │
│ │      新生代 (Young)     │   老年代 (Old)    │ │
│ │ ┌───────┬─────┬─────┐ │                  │ │
│ │ │ Eden  │ S0  │ S1  │ │                  │ │
│ │ │       │     │     │ │                  │ │
│ │ └───────┴─────┴─────┘ │                  │ │
│ │     8       1     1    │                  │ │
│ └───────────────────────┴──────────────────┘ │
│       默认比例 1:1:8          默认比例 2:1      │
└─────────────────────────────────────────────┘
```

- **新生代**：新创建的对象先分配在 Eden 区；Minor GC 时存活对象复制到 Survivor 区，年龄+1
- **老年代**：长期存活的对象（默认年龄 ≥ 15）晋升到老年代；大对象直接进入老年代（`-XX:PretenureSizeThreshold`）
- **GC 类型**：Minor GC（新生代）、Major GC（老年代）、Full GC（整个堆 + 方法区）

### 5. 方法区（Method Area）

| 属性 | 说明 |
|---|---|
| 线程共享 | 所有线程共享 |
| 存储内容 | 类信息、常量、静态变量、JIT 编译后的代码 |
| 异常 | `OutOfMemoryError: Metaspace`（JDK 8+） |

**方法区 vs 元空间（Metaspace）：**

| 维度 | JDK 7 及以前 | JDK 8+ |
|---|---|---|
| 名称 | 永久代（PermGen） | 元空间（Metaspace） |
| 位置 | JVM 堆内存中 | 本地内存（Native Memory） |
| 大小限制 | 固定上限（`-XX:MaxPermSize`） | 默认无上限（受限于物理内存） |
| OOM 风险 | 容易 `PermGen space` | 不易 OOM，但仍可能 `Metaspace` |
| 字符串常量池 | 在永久代中 | 移至堆中 |

> **为什么要从永久代改为元空间？** 永久代大小固定，容易 OOM；元空间使用本地内存，自动扩容，且 JRockit 虚拟机本就没有永久代，统一 HotSpot 和 JRockit 的设计。

## 对比总表

| 区域 | 线程共享/私有 | 存储内容 | 可能异常 |
|---|---|---|---|
| 程序计数器 | 私有 | 字节码行号 | 无（唯一不会 OOM） |
| 虚拟机栈 | 私有 | 栈帧（局部变量表、操作数栈等） | StackOverflowError / OOM |
| 本地方法栈 | 私有 | Native 方法调用状态 | StackOverflowError / OOM |
| 堆 | 共享 | 对象实例、数组 | OutOfMemoryError: Java heap space |
| 方法区 | 共享 | 类信息、常量、静态变量、JIT 代码 | OutOfMemoryError: Metaspace |

## 直接内存（Direct Memory）

不属于 JVM 运行时数据区，但也会导致 OOM：

- NIO 使用 `ByteBuffer.allocateDirect()` 分配直接内存
- 不受堆大小限制，但受物理内存限制
- 可通过 `-XX:MaxDirectMemorySize` 限制
- OOM 信息：`OutOfMemoryError: Direct buffer memory`

## 面试高频

**Q：堆和栈的区别？**

A：

| 维度 | 堆 | 栈 |
|---|---|---|
| 存储内容 | 对象实例、数组 | 基本类型、对象引用、栈帧 |
| 线程共享 | 共享 | 私有 |
| 生命周期 | GC 管理 | 方法调用结束自动释放 |
| 大小 | 较大（-Xms/-Xmx） | 较小（-Xss） |
| 异常 | OOM | StackOverflow |
| 速度 | 较慢（分配和回收需 GC） | 较快（指针移动即可） |

**Q：String 对象存放在哪里？**

A：
- **字面量**（`String s = "abc"`）：字符串常量池，JDK 7+ 在堆中
- **new String()**：堆上创建新对象
- **String 对象本身**：堆
- **String 引用**：栈（局部变量）或堆（作为其他对象的成员变量）

**Q：Metaspace OOM 的原因和排查？**

A：常见原因——(1) 动态生成大量类（如 CGLIB 代理、Groovy 脚本）；(2) 没有限制 Metaspace 大小导致物理内存耗尽。排查：`jstat -gcutil` 观察 Metaspace 使用率，`jmap -clstats` 查看类加载情况，`-XX:MaxMetaspaceSize` 限制大小。

**Q：什么情况下栈会 StackOverflowError？**

A：方法递归调用过深，栈帧数超过 `-Xss` 设定的栈大小。典型场景：无终止条件的递归。

## 一句话总结

JVM 运行时数据区分为线程私有（PC、VM 栈、本地方法栈）和线程共享（堆、方法区）两大类；堆存对象实例且分代管理，方法区在 JDK 8 后变为元空间使用本地内存，程序计数器是唯一不会 OOM 的区域。

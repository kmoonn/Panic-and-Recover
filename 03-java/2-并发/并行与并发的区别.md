# 并行与并发的区别

## Q1: 什么是并发（Concurrency）?

**并发是指多个任务在同一时间段内都在推进执行，但未必在同一时刻同时运行。**

- 本质：**交替执行**（时间片轮转）
- 核心机制：操作系统调度，CPU 在多个线程间快速切换
- 单核 CPU 也能实现并发：通过时间片分配，让多个任务"同时推进"

```
单核 CPU 上的并发（时间片轮转）：

时间 →  T1   T2   T1   T2   T1   T2
CPU    [█]  [█]  [█]  [█]  [█]  [█]
       任务A  任务B  任务A  任务B  任务A  任务B

→ 宏观上：A 和 B "同时" 在进行
→ 微观上：任意时刻只有一个任务在执行
```

| 特征 | 说明 |
|------|------|
| 核心能力 | **处理（Dealing with）** 多件事 |
| 执行方式 | 交替执行（时间片调度） |
| 是否需要多核 | 不需要，单核即可 |
| 目的 | 提高资源利用率，避免等待 |

---

## Q2: 什么是并行（Parallelism）?

**并行是指多个任务在同一时刻真正同时执行，每个任务由独立的 CPU 核心运行。**

- 本质：**同时执行**
- 核心机制：多核/多 CPU 硬件支持，每个核运行一个任务
- 必须有多核硬件才能实现真正的并行

```
多核 CPU 上的并行：

时间 →  T1  T2  T3  T4  T5  T6
CPU0   [████████████████████]  任务A
CPU1   [████████████████████]  任务B

→ 宏观上：A 和 B 同时进行
→ 微观上：每个时刻都有两个任务真正在执行
```

| 特征 | 说明 |
|------|------|
| 核心能力 | **执行（Doing）** 多件事 |
| 执行方式 | 真正同时执行 |
| 是否需要多核 | **必须多核** |
| 目的 | 提高执行速度，缩短总耗时 |

## Q3: 从 CPU 视角看区别

| 维度 | 并发 | 并行 |
|------|------|------|
| CPU 核心数 | 单核即可 | 必须多核 |
| 执行模型 | 时间片轮转，交替执行 | 多核同时执行 |
| 时刻视角 | 任意时刻只有 1 个任务在 CPU 上 | 同一时刻多个任务在不同核上 |
| 时间段视角 | 多个任务在推进 | 多个任务在推进 |
| 切换开销 | 有上下文切换开销 | 无额外切换开销 |

```
┌─────────────────────────────────────────┐
│  单核并发                                │
│  ┌──┐ ┌──┐ ┌──┐ ┌──┐ ┌──┐ ┌──┐        │
│  │A │ │B │ │A │ │B │ │A │ │B │  交替   │
│  └──┘ └──┘ └──┘ └──┘ └──┘ └──┘        │
├─────────────────────────────────────────┤
│  多核并行                                │
│  CPU0: ┌──────────────────────┐  A      │
│  CPU1: ┌──────────────────────┐  B      │
│         同时执行，无交替                  │
└─────────────────────────────────────────┘
```

## Q4: Rob Pike 经典定义

Go 语言之父 Rob Pike 的经典论述：

> **"Concurrency is about dealing with lots of things at once. Parallelism is about doing lots of things at once."**
>
> — Rob Pike, "Concurrency Is Not Parallelism" (2012)

| 概念 | 英文关键词 | 中文翻译 | 本质 |
|------|-----------|---------|------|
| 并发 | **Dealing with** | **处理** | 程序的**结构设计**——如何组织多个任务 |
| 并行 | **Doing** | **执行** | 程序的**运行方式**——如何同时执行多个任务 |

**关键洞察**：
- 并发是关于**程序结构**的：你如何把问题分解为多个可独立推进的部分
- 并行是关于**程序执行**的：你是否真的同时在跑多个部分
- **并发不依赖并行**：一个良好的并发程序在单核上也能正确运行（只是交替执行）
- **并行是并发的一种实现方式**：并发程序在多核上可获得并行加速

## Q5: 并发与并行的关系

| 关系 | 说明 |
|------|------|
| 并行 ⊂ 并发 | 并行是并发的一种特殊情况 |
| 并发 ⟹̸ 并行 | 并发程序不一定能并行执行（可能只有单核） |
| 并行 ⟹ 并发 | 能并行的程序一定是并发设计的 |
| 正交关系 | 两者关注不同层面：并发关注结构，并行关注执行 |

```
         ┌───────────────────┐
         │      并发         │
         │  (Concurrency)    │
         │                   │
         │   ┌───────────┐   │
         │   │   并行     │   │
         │   │(Parallelism)│  │
         │   └───────────┘   │
         └───────────────────┘

并发但不并行：单核多线程（交替执行）
并发且并行：多核多线程（同时执行）
既不并发也不并行：单线程顺序执行
```

## Q6: 生动的类比

### 厨师做菜类比

| 场景 | 类比 | 概念 |
|------|------|------|
| 1 个厨师做 2 道菜 | 厨师先切菜A → 起锅烧油 → 切菜B → 翻炒A → 翻炒B → 出锅 | **并发**（交替推进，1 人） |
| 2 个厨师各做 1 道菜 | 厨师1 做菜A，厨师2 做菜B，同时进行 | **并行**（同时执行，2 人） |

| 场景 | 类比 | 概念 |
|------|------|------|
| 1 个收银员交替服务 2 个顾客 | 收银员处理 A 的扫码 → 处理 B 的扫码 → A 付款 → B 付款 | **并发** |
| 2 个收银员各服务 1 个顾客 | 收银员1 服务 A，收银员2 服务 B，同时进行 | **并行** |

## Q7: Java 中的并发与并行

```java
// 并发（单线程交替执行，如 NIO 事件循环）
ExecutorService singleThread = Executors.newSingleThreadExecutor();
// 所有任务在一个线程上交替执行 → 并发但不并行

// 并行（多线程同时执行，如 ForkJoinPool）
ExecutorService forkJoin = Executors.newWorkStealingPool();
// 多核上多个线程同时执行 → 并发且并行

// Java 8 并行流（Parallel Stream）—— 并行
list.parallelStream().map(x -> heavyCompute(x)).collect(...);
// 底层使用 ForkJoinPool.commonPool()，多核并行执行
```

| Java 概念 | 并发 | 并行 | 说明 |
|----------|------|------|------|
| `Thread` / `Runnable` | ✅ | 取决于核数 | 多线程是并发编程模型 |
| `synchronized` | ✅ | - | 保证并发安全，不涉及并行 |
| `ForkJoinPool` | ✅ | ✅ | 工作窃取，多核并行 |
| `CompletableFuture` | ✅ | ✅ | 异步编排，多核并行 |
| `Virtual Thread` (JDK 21) | ✅ | - | 大量轻量线程实现高并发，挂载到少量载体线程上并行 |

## 一句话总结

并发是关于"处理"多件事的程序结构设计（交替推进，单核即可），并行是关于"执行"多件事的运行方式（真正同时，需要多核），两者是不同维度的概念：并发关注结构，并行关注执行，并行是并发的子集。

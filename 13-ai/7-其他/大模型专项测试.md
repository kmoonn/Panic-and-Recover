# 大模型专项测试

> AI 测开岗的命题作文——LLM 输出非确定，测的不是"对不对"而是"稳不稳、安不安全、崩没崩"，从功能测试思维转向质量维度评测思维。

## 六大测试维度

按维度拆，每维度都要能说出"怎么测 + 拿什么当判据"。

| 维度 | 测什么 | 怎么测 / 判据 |
|---|---|---|
| **① 准确性/事实性** | 答案对不对、有没有幻觉 | 标注问答对做**评测集**跑，判据用**关键字段/语义相似度/LLM-as-Judge**，不做全文等值；事实性重点测"库里没有→是否老实说不知道" |
| **② 逻辑推理** | 多步推理、数学/因果对不对 | 用带**标准答案**的推理题集（可要 CoT 中间步骤），判最终答案 + 抽查推理链是否自洽 |
| **③ 多轮对话一致性** | 多轮里会不会前后矛盾、忘设定、被带偏 | 构造**多轮脚本**（含指代、修正、回溯），断言后轮是否守住前轮事实/人设；测"长对话遗忘"和"被诱导改口" |
| **④ 内容安全** | 涉黄涉暴涉政、偏见、越狱 | **红队/对抗用例** + 敏感词/分类器过滤；重点测**越狱（jailbreak）**——换马甲绕过安全限制是否还守得住 |
| **⑤ 鲁棒性** | 输入扰动/攻击下稳不稳 | **Prompt injection**（注入指令覆盖系统提示）、错别字/乱序/超长输入、边界空值；看是否崩溃或被劫持 |
| **⑥ 性能稳定性** | 延迟、吞吐、并发 | **TTFT（首 token 延迟）**、每秒 token 数、并发下 P99；流式场景重点测 TTFT（呼应 `ceec/03-rag-tracing.md` 埋 TTFT） |

## ⭐ 加分/易错

- **一句话框架**（被问"你会怎么测大模型"直接甩这套）：**"功能维度看准确性和推理、体验维度看多轮一致性和延迟、风险维度看内容安全和鲁棒性——每个维度配评测集 + 明确判据，非确定性靠语义断言 + 多次采样 + LLM-as-Judge，不用精确等值。"**
- **别只会说"测准确率"**——AI 测开的深度在**内容安全（越狱/红队）+ 鲁棒性（注入攻击）**，这是区别于普通功能测试的加分点。
- **扣回我的经验**：非确定性断言/评测集回归=我在 RAG 项目做的（`ceec/`）；对抗/边界数据构造能力=造数 Skill（`bytedance/01-ai-data-gen.md`）；故障注入测容错=`ceec/02-rag-model-routing.md`（可迁移到"模型故障下服务稳不稳"）。

## 一句话总结

> 大模型专项测试六维度：准确性/逻辑推理/多轮一致/内容安全/鲁棒性/性能稳定性——功能+体验+风险三类，配评测集+语义判据，不用精确等值。

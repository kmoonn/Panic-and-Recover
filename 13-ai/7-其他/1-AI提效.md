# AI 提效

## 提效的本质

AI 提效不是"让 AI 替你干"，而是**减少低价值时间的占比**，把时间释放给高价值工作：

```
工作时间 = 低价值时间（查文档、写模板、调试格式） + 高价值时间（设计、决策、审查）

AI 提效 = 减少 低价值时间 → 高价值时间占比上升
```

## 编码提效

### 1. 从 0 → 70 分：AI 生成初版

| 场景 | 提效方式 | 典型提效倍数 |
|---|---|---|
| CRUD 接口 | 描述数据模型 + 约束，AI 生成完整代码 | 3~5x |
| 单元测试 | 给函数签名 + 边界条件，AI 生成测试用例 | 2~4x |
| 配置文件 | Dockerfile / CI YAML / 正则表达式 | 3~10x |
| 类型定义 | API 响应 JSON → TypeScript interface / Pydantic model | 5~10x |
| 文档注释 | 函数 → docstring / JSDoc | 3~5x |

### 2. 从 70 → 90 分：人审改

AI 生成后人的动作：

1. **读一遍**：理解 AI 写了什么，不是盲信
2. **改边界**：补遗漏的异常处理、边界条件
3. **调风格**：统一命名、对齐团队规范
4. **加测试**：跑一遍，补 AI 没覆盖的路径

### 3. 调试提效

| 传统 | AI 辅助 |
|---|---|
| 读日志逐行排查 | 把报错贴给 AI，定位根因 + 修复建议 |
| 搜 StackOverflow | AI 直接给适配当前代码上下文的方案 |
| 手写正则试错 | AI 生成 + 在线测试一轮搞定 |

## 知识提效

### 文档/代码审读

- **读陌生代码库**：让 AI 先解释架构和模块关系，快速建立全局认知，再深入细节
- **读技术文档**：长文档先让 AI 提取要点，再按需精读关键章节
- **面试准备**：给 AI 你的目标岗位，让它出题并点评回答

### 知识整理

- 零散笔记 → 让 AI 归类、去重、补全 → 结构化知识库
- 会议记录 → 提取决策项 + 待办 + 负责人

## 工作流提效

### 日常高频场景

| 场景 | 提效方式 |
|---|---|
| Code Review | AI 先扫一遍，标记可疑点，人专注审查重点 |
| PR 描述 | AI 根据 diff 生成 PR summary |
| Commit Message | AI 根据改动生成规范 commit message |
| 技术方案评审 | AI 帮审：遗漏点？风险？替代方案？ |
| 周报/日报 | AI 根据 git log / 任务板生成初稿 |

### Agent 化编排

复杂任务用 Agent 工作流串联多步：

```
需求描述
  → AI 拆任务
  → AI 逐个实现
  → AI 跑测试
  → AI 修 bug（循环直到通过）
  → 人工最终审查
```

## 提效的误区

| 误区 | 真相 |
|---|---|
| "AI 写的不用看" | 必须审查，AI 会写出看似正确但有逻辑缺陷的代码 |
| "让 AI 一次写完整个模块" | 越大的任务幻觉率越高，拆小步逐段确认更可靠 |
| "AI 提效就是少写代码" | 提效 = 省时间 + 质量不降。跳过审查省了时间但降了质量，不是提效 |
| "所有任务都该用 AI" | 核心设计决策、安全敏感代码、对业务理解要求极高的逻辑——自己做更快更准 |

## 提效效果衡量

```
提效比 = （传统耗时） / （AI 辅助耗时）

- 重复性模板代码：5~10x
- 调试定位：2~5x
- 文档整理：3~5x
- 核心设计决策：1x（不提效，甚至更慢——因为要审 AI 的建议）
```

## 总结

| 层级 | 提效方式 | 适用 |
|---|---|---|
| **消除** | AI 完成，人不介入 | 模板代码、格式转换、配置生成 |
| **加速** | AI 出初版，人审改 | 业务代码、测试用例、文档 |
| **增强** | 人主导，AI 辅助检查/补全 | 方案设计、Code Review、调试 |
| **不适用** | 纯人完成 | 架构决策、安全敏感逻辑、核心业务判断 |

## 一句话总结

> AI提效本质是减少低价值时间占比，0→70分AI生成初版、70→90分人审改，核心决策不可外包。

# MCP通信生命周期

> 一句话总结：MCP 通信分三阶段——初始化（能力声明）→ 正常通信（发现+调用+读取）→ 关闭，核心是初始化时 Server 声明 capabilities 让 Client 决定暴露什么给 LLM。

---

## 三阶段流程

```
1. 初始化 (Initialize)
   Client → Server: initialize 请求
   Server → Client: 返回能力声明 (capabilities)

2. 正常通信
   - tools/list:    发现可用工具
   - tools/call:    调用工具
   - resources/list: 发现可用资源
   - resources/read: 读取资源
   - prompts/list:  发现可用提示
   - prompts/get:   获取提示内容

3. 关闭 (Shutdown)
   任一方发送关闭信号，清理连接
```

---

## 初始化阶段详解

初始化是 MCP 通信的关键——Server 通过 capabilities 告诉 Client "我能做什么"：

| Server 声明 | Client 行为 |
|------------|------------|
| 支持 tools | Client 将工具列表暴露给 LLM，LLM 可决定调用 |
| 支持 resources | Client 允许 LLM 请求读取资源 |
| 支持 prompts | Client 可获取提示模板供 LLM 使用 |
| 支持 sampling | Client 允许 Server 反向请求 LLM 推理 |

**Client 有最终控制权**：即使 Server 声明了某能力，Client 仍可选择不暴露给 LLM。

## 与简历项目的关联

| 阶段 | 项目关联 |
|------|---------|
| 能力声明 | Skills Pulse 适配 7+ 种 Coding Agent，各 Agent 的 capabilities 不同，需动态适配 |

## 面试高频问题

**Q：MCP 初始化阶段做什么？**
A：Client 发 initialize 请求，Server 返回能力声明（capabilities），包括支持哪些 tools/resources/prompts/sampling。Client 据此决定暴露哪些能力给 LLM。Client 有最终控制权，可选择不暴露 Server 声明的某些能力。

---

## 一句话总结

MCP 通信分初始化（能力声明）→ 正常通信（发现+调用+读取）→ 关闭，初始化是核心：Server 声明能做什么，Client 决定暴露什么。

# MCP核心概念

> 一句话总结：MCP Server 对外暴露三类能力——Tools（可调用函数）、Resources（可读取数据）、Prompts（可复用提示模板），三者共同构成能力声明。

---

## Tools（工具）

模型可调用的函数，类比 API 接口。

```
声明：name + description + inputSchema (JSON Schema)
调用：tools/call → 传入参数 → 返回结果
```

**示例**：

| 工具名 | 功能 | 输入 |
|--------|------|------|
| `read_file` | 读取文件内容 | `path: string` |
| `query_database` | 执行 SQL | `sql: string` |
| `git_commit` | Git 提交 | `message: string` |

---

## Resources（资源）

模型可读取的数据，类比数据源/文件。**只读**，模型不能修改。

```
声明：uri + name + mimeType
读取：resources/read → 返回内容
```

**示例**：

| URI | 名称 | 类型 |
|-----|------|------|
| `file:///project/README.md` | Project README | text/markdown |
| `db://tables/users` | 用户表结构 | application/json |

---

## Prompts（提示模板）

可复用的提示模板，类比模板引擎。带参数，可动态生成 Prompt。

```
声明：name + description + arguments
获取：prompts/get → 传入参数 → 返回完整 Prompt
```

**示例**：

| 模板名 | 用途 | 参数 |
|--------|------|------|
| `code_review` | 代码审查 | `code: string` |
| `summarize` | 文档摘要 | `document: string, max_length: int` |

---

## 三者对比

| 维度 | Tools | Resources | Prompts |
|------|-------|-----------|---------|
| 方向 | 模型→Server（调用） | 模型→Server（读取） | Server→模型（提供模板） |
| 副作用 | 可有（写文件、发请求） | 无（只读） | 无（纯文本） |
| 类比 | API 接口 | 数据源 | 模板引擎 |
| 核心方法 | `tools/call` | `resources/read` | `prompts/get` |

## 面试高频问题

**Q：MCP 的三大核心概念？**
A：Tools（模型可调用的函数，如 read_file）、Resources（模型可读取的只读数据，如文件内容）、Prompts（可复用的提示模板）。Tools 可有副作用，Resources 只读，Prompts 纯文本。三者共同构成 MCP Server 的能力声明。

**Q：Tools 和 Resources 的区别？**
A：Tools 是模型主动调用的函数，可有副作用（写文件、发请求）；Resources 是模型只读的数据源，无副作用。类比：Tools = API 接口，Resources = 数据库视图。

## 八股速记

### Q11. MCP / Skills：给 Agent 扩能力的两种方式 ⭐⭐

> 这张卡是简历 AI 行"RAG、MCP、Skills、Agent"的直接对应，也是字节实习的技术底座——**必须能讲清、且能扣回我做的造数 Skill**（`bytedance/01-ai-data-gen.md`）。

**答（要点式）**：
- **MCP（Model Context Protocol，模型上下文协议）**：Anthropic 提出的**开放标准协议**，用来统一"AI 应用 ↔ 外部工具/数据源"的连接方式。类比：**MCP 之于 AI 工具，就像 USB-C 之于外设**——以前每个模型/客户端接每个工具都要写一套私有对接，MCP 定义了统一接口，一次实现处处可用。
  - **架构**：MCP Host（如 Claude/IDE 客户端）内置 MCP Client，去连一个个 **MCP Server**；每个 Server 对外暴露三类能力——**Tools（可调用的函数）/ Resources（可读的数据）/ Prompts（预置提示模板）**。
- **Skills（技能）**：把**某个领域的能力 / 工作流**打包成可复用、可被 Agent 自主调用的单元。核心是"**把专家know-how固化成模型能直接用的模块**"——一个 Skill 通常含：触发描述（什么时候用）、参数规范、执行逻辑。
- **两者关系**：不是二选一。**MCP 是"连接协议"（怎么把能力接进来），Skill 是"能力封装"（把一类任务打包好）**；Skill 可以通过 MCP 暴露给 Agent，也可用其他机制加载。共同目标都是**扩展 LLM 单靠文本生成做不到的事**。

**⭐ 加分/易错**：
- 别把 **MCP 和 Function Calling 混为一谈**（高频追问）：**Function Calling 是"模型层能力"**——模型按 schema 吐出"要调哪个函数、传什么参"；**MCP 是"系统层协议"**——规范工具/数据源怎么被发现、连接、调用。二者互补：Agent 用 Function Calling 决定调什么，MCP 负责把那些工具标准化地接进来。
- **扣回我的实践**：字节的造数 Skill 就是"把 5 大业务模块的长链路造数能力固化成 40+ 原子 Skill、让 coding agent 按描述自主匹配调用"——正是 Skill 思想的落地（三级参数机制 = Skill 的参数规范，回 `bytedance/01-ai-data-gen.md`）。
- 🔲 **待核实**：字节内部 Skill 体系与标准 MCP Server 的具体对接形式（是否走 MCP 协议 / 私有加载机制），面试如被深挖按实际实现说，别硬套开源 MCP 架构。

---

## 一句话总结

MCP Server 暴露三类能力：Tools（可调用函数）、Resources（只读数据）、Prompts（提示模板），三者方向和副作用不同，共同构成能力声明。

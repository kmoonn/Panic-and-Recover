# MCP传输方式

> 一句话总结：MCP 支持两种传输——stdio 适合本地单机（进程隔离），Streamable HTTP 适合远程共享（无状态水平扩展），选型看部署场景。

---

## 两种传输方式对比

| 维度 | stdio | Streamable HTTP |
|------|-------|-----------------|
| 适用场景 | 本地工具、单机部署 | 远程服务、共享服务器 |
| 连接方式 | Host 启动 Server 子进程，stdin/stdout 通信 | Client POST 到远程 `/mcp` 端点 |
| 响应方式 | 从 Server 的 stdout 读取 | 按需返回 JSON 或升级为 SSE 流 |
| 安全性 | 本地进程隔离，较安全 | 需网络鉴权 (OAuth 2.0 / API Key) |
| 水平扩展 | 不支持（单进程） | 天然支持（无状态设计） |
| 网关友好 | 不涉及 | HTTP 头透传 JSON-RPC 字段，网关可路由监控 |
| 典型用途 | 文件系统、本地数据库、Git 操作 | 云端 API、共享工具服务、企业网关后 |

---

## stdio 模式

Host 启动 Server 作为子进程，通过 stdin 写入请求、stdout 读取响应。

```
Host 进程
  │
  ├── 启动 Server 子进程
  │     stdin  ←── Host 写入 JSON-RPC 请求
  │     stdout ──→ Host 读取 JSON-RPC 响应
  │
  └── 进程生命周期由 Host 管理
```

**优势**：最简单、最安全（进程隔离）、零网络依赖
**局限**：只能本地、无法共享、Host 崩溃则 Server 也崩溃

---

## Streamable HTTP 模式

Client 向远程 Server 的单一 `/mcp` 端点发 POST 请求，无状态设计。

详见 [StreamableHTTP](StreamableHTTP.md)

---

## 选型决策

| 场景 | 选 |
|------|----|
| Claude Desktop 本地用文件系统 | stdio |
| 团队共享的数据库查询服务 | Streamable HTTP |
| 企业网关后的统一工具服务 | Streamable HTTP |
| 本地开发调试 MCP Server | stdio |
| 需要水平扩展+负载均衡 | Streamable HTTP |

## 面试高频问题

**Q：MCP 两种传输方式怎么选？**
A：本地单机用 stdio（简单安全、进程隔离）；远程共享用 Streamable HTTP（无状态、可水平扩展、网关友好）。核心判断：Server 部署在哪——本机选 stdio，远端选 HTTP。

---

## 一句话总结

stdio 适合本地单机（进程隔离、零网络），Streamable HTTP 适合远程共享（无状态、水平扩展），选型看部署场景。

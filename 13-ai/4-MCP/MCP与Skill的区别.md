# MCP与Skills的区别

> 一句话总结：Skills 是给自己人用的，MCP 是给全世界用的——定位不同层级，互补而非替代。

---

## 核心对比

| 维度 | MCP | Skills |
|------|-----|--------|
| **定位** | 通用工具的标准协议 | 团队内部的做事流程 |
| **目标用户** | 面向公众/全公司 | 面向个人/小团队 |
| **分发方式** | 网络协议，URL 即可接入 | 本地文件，复制到特定目录 |
| **设计假设** | "把工具摆出来让 AI 挑选" | "编码团队特定的做事流程" |
| **复杂度** | 独立服务部署、鉴权、网关 | 单文件即可，零运维 |
| **适用场景** | 通用服务（数据库、Git、搜索） | 项目规范、团队工作流 |
| **类比** | USB-C 接口标准 | 个人电脑上的快捷键配置 |

## 面试高频问题

**Q：MCP 和 Skills 的区别？**
A：定位不同层级。MCP 是面向公众的通用工具协议（网络分发，URL 接入），Skills 是面向团队的内部工作流（本地文件，零运维）。互补而非替代。

**Q：什么时候用 Skills 什么时候用 MCP？**
A：团队内部流程用 Skills（零运维、单文件部署）；需要跨团队/跨组织共享的通用工具服务用 MCP（标准协议、网络分发）。两者可并存——Skills 可以调用 MCP 的工具。

---

## 一句话总结

Skills 是给自己人用的（本地流程、零运维），MCP 是给全世界用的（标准协议、网络分发），互补而非替代。

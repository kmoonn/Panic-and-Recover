# 训练三阶段

> 一句话总结：Pretrain 用海量数据学语言规律 → SFT 用指令数据教对话格式 → RLHF/DPO 用人类偏好对齐安全有用，三个阶段从"什么都知道一点"到"会考试"到"会做人"。

---

## 阶段一：Pretrain（预训练）

### 目标

让模型学会语言的统计规律——下一个 token 预测。

### 数据

| 来源 | 内容 | 占比（典型） |
|------|------|-------------|
| Common Crawl | 网页文本 | ~60% |
| Books | 书籍 | ~10% |
| Wikipedia | 百科 | ~5% |
| Code | GitHub 代码 | ~10% |
| Arxiv | 学术论文 | ~5% |
| 其他 | 对话、新闻等 | ~10% |

数据总量通常 **TB 级**（万亿 token），需经过去重、过滤、质量筛选。

### 训练细节

- **损失函数**：交叉熵损失，衡量预测概率与真实下一个 token 的差距
- **计算规模**：数千 GPU，训练数周~数月，成本百万~千万美元
- **关键技术**：
  - **分布式训练**：数据并行 + 模型并行 + 流水线并行
  - **混合精度**：FP16/BF16 加速计算，降低显存
  - **梯度累积**：小 batch 模拟大 batch 效果
  - **学习率调度**：warmup → cosine decay

### 产出

**基座模型**（Base Model），如 LLaMA-3-8B-Base、Qwen2-72B。

只会续写，不会对话：输入"你好"→ 输出"你好世界"（续写），而非"你好！有什么可以帮你的？"

---

## 阶段二：SFT（监督微调）

### 目标

教模型**指令跟随**——看到用户提问时回答，而非续写。

### 数据

人工构造的 **指令-回答对**（Instruction-Response Pairs）：

```
用户：什么是WAL？
助手：WAL（Write-Ahead Log）是先写日志再写数据的策略...
```

数据量：**1 万~10 万条**，远小于预训练，但质量要求极高。

### 数据来源

| 来源 | 说明 |
|------|------|
| 人工编写 | 质量最高，成本也最高 |
| Self-Instruct | 用强模型生成指令对，再人工筛选 |
| 开源数据集 | Alpaca、ShareGPT 等社区贡献 |

### 训练方式

与 Pretrain 完全相同的目标（下一个 token 预测），只是**换了一份数据**——从"任意文本"换成"指令-回答格式"的文本。

训练时间：**小时级**，计算量远小于预训练。

### 产出

**指令模型**（Instruct Model），如 LLaMA-3-8B-Instruct。

能听指令回答问题，但可能：回答冗长、编造事实、拒绝不安全请求的能力弱。

### SFT 还能做领域适配

用领域数据微调基座模型，使其擅长特定领域：
- **医疗**：MedAlpaca、ChatDoctor
- **法律**：LawGPT、ChatLaw
- **代码**：CodeLlama、DeepSeek-Coder

## 阶段三：RLHF / DPO（对齐人类偏好）

### 为什么需要？

SFT 后模型能回答，但回答可能不符合人类偏好：

| 问题 | 示例 |
|------|------|
| 有害回答 | 教用户制造危险物品 |
| 冗长啰嗦 | 简单问题回答一大段 |
| 事实错误 | 自信地编造不存在的信息（幻觉） |
| 不拒绝 | 对无法回答的问题硬编答案 |

### RLHF（Reinforcement Learning from Human Feedback）

分三步：

```
步骤1：收集偏好数据
  同一问题生成多个回答 → 人工排序 → 得到偏好对

步骤2：训练奖励模型（Reward Model）
  学习人类偏好：好回答高分、差回答低分

步骤3：强化学习优化（PPO）
  用奖励模型打分 → PPO 算法调整生成策略 → 最大化奖励
```

**难点**：
- 奖励模型可能被"钻空子"（reward hacking）——模型学会生成奖励模型给高分但人类认为无意义的内容
- PPO 训练不稳定，超参敏感
- 人工标注成本高

### DPO（Direct Preference Optimization）

**核心思想**：跳过奖励模型，直接用偏好数据优化策略。

```
RLHF：偏好数据 → 训练奖励模型 → PPO 优化策略
DPO：偏好数据 → 直接优化策略（一步到位）
```

**优势**：
- 无需训练奖励模型，减少一个训练阶段
- 无需 PPO，训练更稳定
- 数学上可证明与 RLHF 等价
- 当前主流倾向 DPO

### 其他对齐方法

| 方法 | 思路 |
|------|------|
| **RLAIF** | 用 AI 代替人类做偏好标注，降低成本 |
| **Constitutional AI** | 用一组"宪法原则"自我纠偏，减少人工 |
| **ORPO** | 将偏好优化融入 SFT，合并两个阶段 |

## 与简历项目的关联

| 知识点 | 项目关联 |
|--------|---------|
| Pretrain 基座模型 | RAG 平台用 Qwen（已预训练的基座）+ 本地 Ollama 部署，无需自行预训练 |
| SFT 领域适配 | 讯飞星火大模型接入作文场景需 SFT 适配教育领域，RAG 场景无需 SFT（知识靠检索而非参数） |
| RLHF 对齐 | 效能星盘的 LLM 输出需严格 JSON 格式，对齐阶段确保模型不输出格式外内容（Function Calling + Pydantic 兜底） |
| 基座 vs 指令模型 | API Testing Agent 用指令模型（Instruct）理解 PRD 并生成测试，基座模型只会续写无法对话 |
| Pretrain→SFT→RLHF 选型 | RAG 平台选 RAG 而非微调：知识更新频繁，改数据比重训模型成本低，这是三阶段选型的核心决策 |

## 面试高频问题

**Q：Pretrain、SFT、RLHF 三阶段分别做什么？**
A：Pretrain 用 TB 级海量文本做下一个 token 预测，学语言统计规律，产出只会续写的基座模型；SFT 用万级指令-回答对微调，教模型"提问→作答"格式；RLHF/DPO 用人类偏好数据对齐，让回答安全、有用、符合人类期望。

**Q：为什么不能跳过预训练直接 SFT？**
A：SFT 数据量太小（万级 vs TB 级），无法从零学会语言规律。SFT 的本质是在已具备语言能力的基座模型上微调格式，而非从头学语言。就像不能跳过义务教育直接学考试技巧。

**Q：基座模型和指令模型有什么区别？**
A：基座模型只会续写（输入"你好"→"你好世界"），指令模型能对话（输入"你好"→"你好！有什么帮你？"）。区别来自 SFT 阶段学的指令格式。

**Q：RLHF 和 DPO 的区别？**
A：RLHF 分三步（偏好数据→训练奖励模型→PPO 优化），流程复杂、训练不稳定；DPO 直接用偏好对优化策略，跳过奖励模型，更简单稳定，数学上可证明等价。DPO 是当前主流。

**Q：什么是 reward hacking？**
A：强化学习中模型学会"钻奖励模型的空子"——生成奖励模型给高分但人类认为无意义的内容。本质是奖励模型与真实人类偏好不完全一致，模型找到了评分漏洞。DPO 在一定程度上缓解了这个问题。

**Q：为什么 SFT 数据量远小于预训练却能有效？**
A：SFT 不是在"学知识"，而是在"学格式"——模型的词汇、语法、知识已在预训练阶段学会，SFT 只需教它"什么时候该回答、怎么组织答案"，数据量自然不需要很大。

---

## 一句话总结

Pretrain 学语言规律（海量数据、极大算力）→ SFT 学指令跟随（小数据、格式微调）→ RLHF/DPO 学人类偏好（对齐安全有用），三个阶段逐级精炼，从"什么都知道一点"到"会考试"到"会做人"。

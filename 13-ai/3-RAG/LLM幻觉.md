# LLM 幻觉（Hallucination）

## Q: 什么是 LLM 幻觉？

**LLM 幻觉**：大语言模型生成**看似合理但实际错误**的内容，且表达时**语气自信**，让人难以辨别真伪。

```
用户: 请介绍一下《量子纠缠与意识》这本书的作者
LLM:  《量子纠缠与意识》是由著名物理学家罗杰·彭罗斯和
      麻省理工学院教授塞斯·劳埃德合著的...  ← 完全编造的

用户: Python的list.sort()方法的时间复杂度是多少？
LLM:  list.sort()的时间复杂度是O(n)，因为它使用
      计数排序算法...  ← 错误，实际是O(n log n)的Timsort
```

---

## Q: 幻觉的类型与成因

#### 幻觉类型

| 类型 | 说明 | 示例 |
|------|------|------|
| **事实性幻觉（Factual）** | 生成与客观事实不符的内容 | 编造不存在的论文、书籍、人物 |
| **忠实性幻觉（Faithfulness）** | 生成与给定上下文/源文矛盾的内容 | 摘要中添加原文未提及的结论 |
| **推理幻觉（Reasoning）** | 推理链条中出现逻辑错误 | 数学推导中步骤正确但结论错误 |

#### 幻觉成因

| 成因 | 说明 |
|------|------|
| **训练数据噪声** | 训练数据含错误信息，模型学到了错误知识 |
| **知识缺失** | 模型对某些领域/时间点缺乏知识，但倾向"编"而非说"不知道" |
| **Prompt 歧义** | 用户问题模糊，模型按自己理解"创造"答案 |
| **过度自信** | 模型训练目标鼓励"给出答案"而非"承认不确定" |
| **长尾知识稀疏** | 低频知识训练样本少，模型学不牢靠 |
| **上下文遗忘** | 长对话中忘记之前的约束，产生矛盾输出 |

## Q: 如何缓解 LLM 幻觉？

#### 1. RAG（Retrieval-Augmented Generation）— 最有效

```
用户提问 → 检索相关文档 → 将文档作为上下文 + 用户提问 → LLM 基于事实生成

                   ┌──────────┐
  用户提问 ──────→ │ 向量检索  │ ──→ 相关文档片段
                   └──────────┘
                                    ↓
              ┌─────────────────────────────────┐
              │ Prompt:                          │
              │   根据以下资料回答问题：            │
              │   [检索到的文档1]                  │
              │   [检索到的文档2]                  │
              │   问题：用户原始问题               │
              │   如果资料中没有答案，请说"不知道"  │
              └─────────────────────────────────┘
                          ↓
                       LLM 生成
                          ↓
                    基于事实的回答
```

**RAG 核心流程**：
1. **索引阶段**：文档切分 → 向量化 → 存入向量数据库
2. **检索阶段**：用户问题向量化 → Top-K 相似文档 → 重排序（Rerank）
3. **生成阶段**：检索结果 + Prompt → LLM 生成答案

#### 2. Chain-of-Thought（思维链）

```
请一步一步思考：
1. 先分析问题要求
2. 列出已知条件
3. 逐步推导
4. 验证结论
```

> 让模型"慢思考"，减少跳步导致的推理错误。

#### 3. Self-Consistency（自我一致性）

```
同一问题生成多个回答 → 统计最常见的答案 → 选择多数一致的
```

> 多次采样取共识，减少随机性导致的幻觉。

#### 4. 事实性锚定指令（Factual Grounding）

```
系统提示词:
- 只根据提供的参考资料回答
- 如果资料中没有相关信息，明确说"根据现有资料无法回答"
- 不要编造具体数字、日期、人名
- 回答时引用来源
```

#### 5. Temperature 调整

```python
# 降低 temperature 减少随机性
response = openai.ChatCompletion.create(
    model="gpt-4",
    messages=[...],
    temperature=0.0  # 最确定性输出，减少"创造性"幻觉
)
```

#### 6. 其他方法

| 方法 | 说明 |
|------|------|
| **RLHF** | 通过人类反馈强化学习，惩罚幻觉输出 |
| **知识编辑** | 直接修改模型中的错误知识（ROME/MEMIT） |
| **工具调用** | 让模型调用计算器/搜索引擎/数据库，用工具结果替代编造 |
| **输出校验** | 用另一个模型/NLI模型检验生成内容与源文是否矛盾 |
| **不确定性量化** | 让模型输出置信度，低于阈值则拒绝回答 |

## Q: RAG 的局限性

| 局限 | 说明 |
|------|------|
| **检索质量瓶颈** | 检索不到相关文档 → RAG 退化为普通生成 |
| **上下文窗口限制** | 塞入过多文档 → 超出窗口或模型注意力分散 |
| **文档切分粒度** | 切分太粗→噪声多，切分太细→语义不完整 |
| **并非万能** | 模型仍可能忽略检索结果而"自说自话" |
| **实时性** | 知识库更新延迟，最新信息可能缺失 |

## 八股速记

### Q6. 大模型幻觉 / 怎么缓解 ⭐⭐

**答（要点式）**：
- **幻觉（Hallucination）**：模型一本正经地**编造**不存在的事实/引用，因为它本质是"预测下一个最可能的 token"，不是查数据库。
- **缓解手段**：① **RAG**（给资料、让它基于资料答，最有效）；② **prompt 约束**（"资料没有就说不知道，别编"）；③ 降低**温度**让输出更确定；④ 输出**附引用/出处**供核对；⑤ 加**校验/评测**环节兜底。

**⭐ 加分/易错**：RAG 能大幅减少幻觉但**不能根除**——检索没命中、或模型无视资料仍会编。所以生产上要**引用溯源 + 人工/规则校验**双保险。测开视角这就是重点测试项。

---

## 一句话总结

**LLM 幻觉是模型自信地生成错误信息，RAG（检索增强生成）通过将生成锚定在检索到的事实上是最有效的缓解手段，配合思维链、低 temperature 和事实性指令进一步降低幻觉率。**

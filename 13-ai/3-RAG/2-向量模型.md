# 向量模型（Embedding Model）

## 面试Q&A

### Q1: 什么是向量/嵌入模型（Embedding Model）？

**向量模型**将文本转化为**固定维度的稠密向量**（Dense Vector），使语义相近的文本在向量空间中距离相近。

```
"手机"     → [0.12, -0.34, 0.56, ..., 0.78]  ← 768维/1536维向量
"移动电话"  → [0.11, -0.33, 0.55, ..., 0.77]  ← 语义相近，向量距离近
"苹果"     → [-0.45, 0.23, -0.67, ..., 0.12]  ← 语义不同，向量距离远
```

**核心价值**：**语义理解**，超越关键词匹配。

| 搜索方式 | 查询"手机" | 能否匹配"移动电话" |
|---------|-----------|-----------------|
| 关键词搜索 | 精确匹配"手机" | **否**（字面不同） |
| 向量搜索 | 向量相似度计算 | **是**（语义相近） |

### Q3: 向量相似度计算方法

给定两个向量 A 和 B：

#### 1. 余弦相似度（Cosine Similarity）— 最常用

$$\text{cosine}(A, B) = \frac{A \cdot B}{\|A\| \times \|B\|}$$

- 范围：[-1, 1]，1 表示方向完全相同
- **只关注方向，不关注大小**，适合文本语义

#### 2. 点积（Dot Product / Inner Product）

$$\text{dot}(A, B) = \sum_{i=1}^{n} A_i \times B_i$$

- 向量归一化后，点积 = 余弦相似度
- 计算最快（无需除法）

#### 3. 欧氏距离（Euclidean Distance / L2）

$$\text{L2}(A, B) = \sqrt{\sum_{i=1}^{n} (A_i - B_i)^2}$$

- 值越小越相似
- 同时考虑方向和大小

| 方法 | 归一化后等价 | 计算速度 | 适合场景 |
|------|------------|---------|---------|
| 余弦相似度 | — | 中 | 文本语义（最常用） |
| 点积 | 等于余弦 | 最快 | 归一化向量、追求速度 |
| 欧氏距离 | 单调等价于余弦 | 慢 | 需要考虑大小 |

### Q4: 向量数据库

| 数据库 | 类型 | 特点 | 适用场景 |
|--------|------|------|---------|
| **FAISS** | 本地库（非服务） | Meta开源，GPU加速，纯ANN搜索 | 本地/单机、大规模索引 |
| **Milvus** | 分布式数据库 | 云原生，支持多种索引（IVF/HNSW/SCANN），高可用 | 生产环境、大规模 |
| **Pinecone** | 全托管SaaS | 零运维，自动扩缩容 | 快速上线、不想运维 |
| **Weaviate** | 向量+图数据库 | 内置向量模型，支持混合搜索（向量+关键词） | 需要混合搜索 |
| **Qdrant** | 分布式数据库 | Rust实现，高性能，过滤+向量联合查询 | 高性能、需要过滤 |
| **Chroma** | 轻量级 | Python原生，开发友好 | 原型开发、小规模 |
| **pgvector** | PostgreSQL扩展 | SQL+向量，复用PG生态 | 已有PG、不想新引入组件 |
| **Elasticsearch 8.x** | 搜索引擎 | 向量+全文+结构化，混合搜索 | 已有ES集群 |

```python
# FAISS 使用示例
import faiss
import numpy as np

# 构建索引
dimension = 768
index = faiss.IndexFlatIP(dimension)  # 内积（点积）索引

# 添加向量
vectors = np.random.rand(10000, dimension).astype('float32')
faiss.normalize_L2(vectors)  # 归一化后，点积=余弦相似度
index.add(vectors)

# 搜索
query = np.random.rand(1, dimension).astype('float32')
faiss.normalize_L2(query)
distances, ids = index.search(query, k=10)  # 返回Top10最相似
```

### Q5: 为什么需要向量搜索？关键词搜索不够吗？

**关键词搜索的局限**：

| 问题 | 示例 |
|------|------|
| 同义词无法匹配 | 查"手机"找不到"移动电话" |
| 多义词混淆 | "苹果"是水果还是公司？ |
| 拼写错误 | 查"iphon"找不到"iPhone" |
| 跨语言 | 查"人工智能"找不到"Artificial Intelligence" |
| 语义理解 | 查"如何提速"找不到"性能优化方法" |

**向量搜索的优势**：通过语义编码，以上问题都能较好处理。

**最佳实践：混合搜索（Hybrid Search）**

```python
# 混合搜索 = 关键词搜索(BM25) + 向量搜索
# 两路召回 → 融合排序（RRF / 加权融合）

# Milvus / Weaviate / Elasticsearch 8.x 都支持混合搜索
# Elasticsearch 示例
{
  "query": {
    "bool": {
      "should": [
        { "match": { "content": "手机" } },           # 关键词搜索
        { "knn": { "field": "embedding",              # 向量搜索
                   "query_vector": [...],
                   "k": 10 } }
      ]
    }
  }
}
```

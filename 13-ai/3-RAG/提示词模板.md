# 提示词模板

## 基本结构

一个 RAG 提示词模板通常包含四部分：

```
[角色定义] + [指令] + [上下文/检索结果] + [约束/输出格式]
```

## 模板示例

### 基础版

```
你是一个专业的技术助手。请根据以下参考内容回答用户问题。
如果参考内容中没有相关信息，请回答"根据已有信息无法回答"，不要编造内容。

参考内容：
{context}

用户问题：{question}

回答：
```

### 进阶版（带引用来源）

```
你是一个准确、严谨的技术助手。

## 指令
1. 根据下方【参考内容】回答用户问题
2. 回答时标注信息来源，格式：[来源编号]
3. 如果参考内容不足以回答，明确说明缺少什么信息，不要编造

## 参考内容
{numbered_context}

## 用户问题
{question}

## 输出格式
回答：[你的回答，引用处标注来源编号]
置信度：高/中/低（根据参考内容的充分程度）
```

## 关键设计原则

| 原则 | 说明 |
|---|---|
| **防幻觉** | 明确要求"无法回答时不要编造"，这是 RAG 提示词最重要的约束 |
| **引用溯源** | 要求标注来源编号，便于验证答案可信度 |
| **上下文编号** | 给每个 chunk 编号（`[1]`, `[2]`...），方便引用定位 |
| **指令先于上下文** | 指令放前面，避免模型被长上下文淹没后遗忘指令 |
| **结构化输出** | 指定输出格式（置信度、分点列出等），减少格式不一致 |

## 上下文拼接方式

```python
# 带编号拼接
numbered_context = "\n\n".join(
    f"[{i+1}] {chunk.page_content}" for i, chunk in enumerate(retrieved_chunks)
)
```

## 进阶：多轮对话模板

```
你是一个技术助手，根据参考内容回答问题，无法回答时不要编造。

## 参考内容
{context}

## 对话历史
{chat_history}

## 当前问题
{question}

回答：
```

## 进阶：自问自答模板（Step-Back Prompting）

让模型先抽象出高层次问题，检索更广的上下文，再回答具体问题：

```
## 第一步：抽象问题
请将以下具体问题改写为一个更通用的概念性问题，以获取更广泛的背景知识。

具体问题：{question}
通用问题：

## 第二步：回答具体问题
参考内容（基于通用问题检索）：
{context}

请结合参考内容，回答原始具体问题：{question}
```

---

## 一句话总结

> RAG 提示词模板核心：防幻觉是第一约束，指令先于上下文，编号引用溯源，结构化输出格式。

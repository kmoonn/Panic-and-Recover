# Agent 评测方法

> Agent 评测 ≠ 大模型评测。大模型评测关注"单轮生成质量"，Agent 评测关注"多步决策 + 工具调用 + 任务完成"——维度完全不同。

---

## 一、分层评测框架

Agent 的错误会跨步累积，只看最终结果无法定位问题。评测必须分层：

```text
第 1 层：工具调用正确性    — 该调对工具没？参数填对没？
第 2 层：单步决策质量      — 给定状态，这步推理对不对？
第 3 层：端到端任务成功率  — 最终有没有达成目标？
第 4 层：鲁棒性与安全性    — 异常输入/越权场景下崩不崩？
```

| 层级 | 测什么 | 评测方式 | 失败典型 |
|------|--------|---------|---------|
| **工具调用** | 选对工具 + 参数正确 | Mock 工具，对比 ground truth 调用序列 | 选错工具、参数格式错误、漏调必需工具 |
| **单步决策** | 中间推理是否合理 | 给定状态快照，评估 Thought/Plan 质量 | 推理跳步、忽略关键 Observation |
| **端到端** | 最终任务是否完成 | 预设任务 + 预期结果，判断是否达成 | 目标未完成、完成但绕路、完成但结果不完整 |
| **鲁棒性** | 边界/对抗/异常 | 注入错误工具返回、越权指令、超长输入 | 崩溃、死循环、越权调用、幻觉蔓延 |

> **核心原则**：低层级通过是高层级有意义的前提——工具调用都错，端到端成功率不可能高。

---

## 二、评测方式对比

| 方式 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| **静态评测集** | 预构建任务集 + 预期轨迹，批量跑分 | 可复现、可回归 | 覆盖面有限，构造成本高 |
| **在线评测** | 线上真实请求 + 旁路评估 | 接近真实分布 | 不可复现、标注困难 |
| **人工评测** | 人工审视执行轨迹，逐步评分 | 判断最准 | 成本高、不可扩展 |
| **LLM-as-Judge** | 强模型评估弱模型的决策轨迹 | 可扩展、可自定义维度 | 有偏差、需校准 |

**实际组合**：静态评测集做回归基线 + LLM-as-Judge 做日常评估 + 人工抽检做校准兜底。

## 三、评测集构建

### 与大模型评测集的区别

| 维度 | 大模型评测集 | Agent 评测集 |
|------|------------|-------------|
| 输入 | 单轮 prompt | 多轮任务指令 + 初始状态 |
| 预期输出 | 参考文本/标签 | 任务完成判定 + 预期轨迹（工具调用序列） |
| 环境 | 无外部依赖 | 需要模拟工具/API/UI 环境 |
| 评判 | 文本匹配/语义相似 | 多维度：结果正确 + 过程合理 + 效率达标 |

### 构建步骤

```text
1. 场景定义    — 按 Agent 职责划分评测场景（如：信息查询型、操作执行型、多步推理型）
2. 任务编写    — 每个场景下编写具体任务 + 预期结果
3. 轨迹标注    — 标注"理想执行路径"：该调哪些工具、每步参数是什么
4. 环境准备    — Mock 工具返回值、准备测试数据、构造边界/对抗 case
5. 评判规则    — 定义"什么算通过"：精确匹配 / 语义等价 / 关键字段命中
```

### 防泄漏

与大模型评测同理：**评测集不能进入训练数据**，否则分数虚高。Agent 评测集还要额外注意——工具的 Mock 返回值也不能泄露到 prompt 里。

## 四、评测流程

```text
构建评测集
    ↓
跑基线（当前版本 Agent）
    ↓
记录各层级指标
    ↓
迭代优化（改 prompt / 加工具 / 调参数）
    ↓
回归评测（确认没退化）
    ↓
上线 + 在线监控
```

**关键**：每次迭代都要回归——Agent 的非确定性意味着"修了一个 case 可能坏了另一个 case"，必须全量回归。

---

## 五、与其他评测的区别

| 评测类型 | 关注点 | 典型指标 |
|---------|--------|---------|
| 大模型评测 | 单轮生成质量 | BLEU/ROUGE/Accuracy/MMLU |
| RAG 评测 | 检索+生成联合质量 | 召回率/忠实度/答案相关性 |
| **Agent 评测** | 多步决策+工具调用+任务完成 | 任务完成率/工具准确率/轨迹正确率 |
| 测试 Agent 评测 | 测试流程自动化质量 | 覆盖度/断言有效性/采纳率 |

> 交叉引用：RAG 评测详见 [RAG评测](../3-RAG/RAG评测.md)；大模型评测详见 [大模型评测指标](../1-基础/大模型评测指标.md)；测试 Agent 量化详见 [测试Agent量化指标](../../10-testing/1-基础/测试Agent量化指标.md)

## 六、面试高频

### Q: 怎么评一个 Agent 好不好？

> 分四层：先看工具调用对不对（最基础），再看单步推理合不合理，然后看端到端任务完没完成，最后看鲁棒性和安全性。评测方式上，静态评测集做回归基线，LLM-as-Judge 做日常评估，人工抽检做校准。

### Q: Agent 评测和普通大模型评测有什么区别？

> 核心区别在于 Agent 是**多步决策 + 工具调用**：大模型评测只需要 prompt + 参考答案，Agent 评测还需要模拟环境、标注预期轨迹、评判中间决策。错误也会跨步累积——第一步工具调用错了，后面全基于错误前提，所以必须分层评测。

### Q: 评测集怎么防泄漏？

> 评测集和训练数据必须隔离——这和大模型一样。Agent 评测还要额外注意工具 Mock 返回值不能泄露到 prompt，否则 Agent 只是"背答案"而不是真正在推理。

---

## 一句话总结

> Agent 评测必须分层：工具调用正确性 → 单步决策质量 → 端到端任务成功率 → 鲁棒性与安全性，评测方式用静态评测集+LLM-as-Judge+人工抽检组合，评测集要防泄漏，每次迭代必须全量回归。

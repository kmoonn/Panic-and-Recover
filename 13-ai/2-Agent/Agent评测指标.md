# Agent 评测指标

> 量化 Agent 质量的核心指标——从"感觉还行"到"数据说话"。

---

## 一、端到端指标

### 任务完成率（Task Completion Rate）

**定义**：在评测集中，Agent 最终达成任务目标的比例。

```text
任务完成率 = 成功完成任务数 ÷ 总任务数
```

| 细分 | 说明 |
|------|------|
| **严格完成率** | 结果必须与预期完全一致 |
| **语义完成率** | 结果语义等价即可（LLM-as-Judge 判定） |
| **部分完成率** | 多子任务场景，完成子任务的比例 |

> 这是最核心的指标，但**只有完成率不够**——完成了但绕路 20 步，和 3 步直达成，质量完全不同。

### 任务完成质量分（Quality Score）

完成不等于完美。对完成的任务再打质量分：

| 维度 | 评估内容 |
|------|---------|
| 完整性 | 是否遗漏了子任务 |
| 准确性 | 结果是否精确（不只是"差不多"） |
| 清晰度 | 输出是否清晰有条理 |

## 二、过程指标

### 工具调用准确率

**Agent 最常错的地方**——选错工具或参数填错。

```text
工具选择准确率 = 选对工具的次数 ÷ 总工具调用次数
参数填充准确率 = 参数完全正确的次数 ÷ 总工具调用次数
```

| 错误类型 | 示例 |
|---------|------|
| 选错工具 | 应调 search 却调了 calculator |
| 参数类型错误 | 应传 int 却传了 string |
| 参数值错误 | 日期格式不对、ID 不存在 |
| 漏调必需工具 | 应该先查询再下单，但跳过了查询 |
| 多调冗余工具 | 同一查询调了两次 |

> **面试话术**："Agent 评测的第一层就是看工具调用——这是 Agent 最常错的地方，比最终答案出错更频繁。"

### 轨迹正确率（Trajectory Accuracy）

不只看结果对不对，还要看**中间路径合不合理**。

```text
轨迹正确率 = 与预期轨迹一致的步骤数 ÷ 总步骤数
```

| 场景 | 轨迹判定 |
|------|---------|
| 完全一致 | 工具+参数+顺序都匹配 |
| 等价轨迹 | 工具不同但效果等价（如先查 A 再查 B，和先查 B 再查 A） |
| 绕路轨迹 | 最终对了但走了弯路（多调了冗余工具） |
| 错误轨迹 | 中间有根本性错误（即使最终碰巧对了） |

> 轨迹正确率比任务完成率更严格——碰巧对了不算真正好。

### 平均步数与效率

| 指标 | 计算 | 含义 |
|------|------|------|
| **平均步数** | 总步数 ÷ 任务数 | 越低越高效 |
| **步数偏差比** | Agent 步数 ÷ 最优步数 | >1 说明绕路，=1 最优 |
| **冗余调用率** | 冗余工具调用数 ÷ 总调用数 | 判断 Agent 是否"磨蹭" |

```text
步数偏差比 = Agent 实际步数 ÷ 最优路径步数

示例：
  最优路径：3 步
  Agent 实际：5 步（其中 2 步是重复查询）
  步数偏差比 = 5 / 3 ≈ 1.67（绕路 67%）
```

## 三、可靠性指标

### 死循环率

Agent 特有的故障——反复调用同一工具或在两个节点间跳转。

```text
死循环率 = 出现死循环的任务数 ÷ 总任务数
```

| 死循环类型 | 表现 |
|-----------|------|
| 重复调用 | 连续 3+ 次调用同一工具，参数几乎相同 |
| 往返跳转 | 在 A→B→A→B 之间循环 |
| 自我修正循环 | 修了又错、错了又修，始终无法收敛 |

### 超时率

```text
超时率 = 超过最大步数/时间的任务数 ÷ 总任务数
```

### 幻觉率

Agent 的幻觉比单轮 LLM 更危险——**单步幻觉会蔓延**：

```text
幻觉率 = 包含幻觉内容的步骤数 ÷ 总步骤数
幻觉蔓延率 = 因前置幻觉导致后续步骤也出错的次数 ÷ 幻觉总次数
```

## 四、成本指标

| 指标 | 计算 | 意义 |
|------|------|------|
| **平均 Token 消耗** | 总 Token 数 ÷ 任务数 | 每任务成本 |
| **平均工具调用次数** | 总工具调用数 ÷ 任务数 | API 调用成本 |
| **平均耗时** | 总耗时 ÷ 任务数 | 用户体验 |
| **P95/P99 耗时** | 长尾延迟 | SLA 保障 |

## 五、指标速查表

| 类别 | 指标 | 核心 | 方向 |
|------|------|------|------|
| 端到端 | 任务完成率 | 最核心 | ↑ 越高越好 |
| 端到端 | 质量分 | 完成不等于完美 | ↑ |
| 过程 | 工具选择准确率 | Agent 最常错处 | ↑ |
| 过程 | 参数填充准确率 | schema 守不守得住 | ↑ |
| 过程 | 轨迹正确率 | 过程合理比结果对更重要 | ↑ |
| 过程 | 步数偏差比 | 是否绕路 | ↓ 越接近 1 越好 |
| 可靠性 | 死循环率 | Agent 特有故障 | ↓ |
| 可靠性 | 超时率 | 兜底机制是否生效 | ↓ |
| 可靠性 | 幻觉蔓延率 | 单步错误传播程度 | ↓ |
| 成本 | 平均 Token 消耗 | 每任务费用 | ↓ |
| 成本 | 平均耗时 | 用户体验 | ↓ |

## 六、面试高频

### Q: 评测 Agent 最看哪个指标？

> **任务完成率是核心，但不够**。完成率高但步数偏差比大说明 Agent 绕路；完成率高但工具选择准确率低说明碰巧对了。**最关键的组合是：任务完成率 + 工具调用准确率 + 步数偏差比**——既看结果又看过程。

### Q: 为什么轨迹正确率比任务完成率更重要？

> 因为 Agent 有非确定性——同一个任务跑 10 次，可能 6 次对了但路径各不相同，其中 3 次是碰巧对了。轨迹正确率能区分"真正理解了任务"和"瞎猫碰上死耗子"。

### Q: Agent 指标和 RAG 指标有什么区别？

> RAG 指标关注单链路质量（检索召回率、生成忠实度、答案相关性），Agent 指标关注多步循环质量（工具调用准确率、轨迹正确率、死循环率）。RAG 的错误是单点传播，Agent 的错误是跨步累积——所以 Agent 更需要过程指标。

## 一句话总结

> Agent 评测指标三维度：端到端（任务完成率+质量分）、过程（工具准确率+轨迹正确率+步数偏差比）、可靠性（死循环率+幻觉蔓延率）——核心组合是完成率+工具准确率+步数偏差比，既看结果也看过程。

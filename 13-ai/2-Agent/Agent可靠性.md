# Agent 可靠性

> Agent 的可靠性问题比单轮 LLM 严重得多——错误会跨步累积，一步错步步错。

---

## 一、常见故障模式

### 1. 幻觉蔓延

单步幻觉不可怕，可怕的是**后续步骤基于错误前提继续推理**，错误像雪球一样越滚越大。

```text
第 1 步：Agent 幻觉出一个不存在的 API 返回值
第 2 步：基于错误返回值做推理（前提已错）
第 3 步：继续基于第 2 步的错误结论行动
    ...
最终：整条链路偏离目标，但 Agent 自认为逻辑自洽
```

| 特征 | 说明 |
|------|------|
| 隐蔽性 | 中间步骤看起来逻辑自洽，只是前提错了 |
| 传播性 | 一步幻觉可能污染后续所有步骤 |
| 难检测 | 只看最终结果很难发现是哪一步开始偏的 |

**缓解手段**：
- 关键步骤后加**事实校验**：工具返回值 vs Agent 推理是否一致
- 长链路中插入**中间检查点**：对比中间结果与预期
- 让 Agent 显式写"我依据的前提是……"，方便人工审查

---

### 2. 死循环

Agent 反复执行相同操作无法收敛，是最典型的 Agent 故障。

| 死循环类型 | 表现 | 根因 |
|-----------|------|------|
| **重复调用** | 连续调同一工具，参数几乎不变 | Agent 没理解工具返回，以为再调一次能不同 |
| **A-B 往返** | 在两个节点间反复跳转 | 条件边逻辑有缺陷，两个状态互为前置 |
| **修了又错** | 修正一个错误引入新错误，循环往复 | 自省能力不足，局部修正破坏全局一致性 |

**缓解手段**：
- 设置**最大步数/时间**硬限制（必须兜底）
- 检测**重复 Action**：连续 N 次相同工具+参数，强制退出
- 检测**往返模式**：A→B→A 模式出现时触发人工接管
- 改用 **Plan-and-Execute** 替代 ReAct，减少逐步试错

---

### 3. 越权调用

Agent 调了不该调的工具或访问了不该访问的数据。

| 越权类型 | 示例 |
|---------|------|
| 工具越权 | 客服 Agent 调了数据库删除接口 |
| 数据越权 | 普通用户身份却查询了管理员数据 |
| 操作越权 | 只该查询却执行了写入操作 |
| 横向越权 | 访问了同一用户其他业务线的敏感数据 |

**缓解手段**：
- **工具白名单**：每个 Agent 角色只能访问预定义的工具集
- **权限层级**：读/写/管理 分级授权
- **参数约束**：工具 schema 限制可传入的参数范围
- **操作审计**：所有工具调用记录日志，异常模式告警

---

### 4. 工具参数填充错误

模型没有严格遵循 schema，瞎填参数。

| 错误类型 | 示例 |
|---------|------|
| 类型错误 | `count` 应为 int 却传了 `"5"` |
| 格式错误 | 日期传了 `"2024/1/1"` 但接口要求 `"2024-01-01"` |
| 枚举越界 | `sort` 只允许 `asc/desc` 却传了 `"random"` |
| 必填遗漏 | 漏传了 `user_id` |
| 幻觉填充 | 编造了一个不存在的 `order_id` |

**缓解手段**：
- 工具调用前加**参数校验层**（JSON Schema validation）
- 对枚举/范围做硬约束，不让 LLM 自由发挥
- 调用失败时返回**结构化错误信息**而非模糊报错
- 高风险操作（删除/支付）加二次确认

---

### 5. 中途遗忘

长链路中丢失前文关键信息，导致后续决策偏离。

| 表现 | 根因 |
|------|------|
| 重复提问 | 忘了已经问过/查过 |
| 前后矛盾 | 前面确认 A，后面又当 B 处理 |
| 遗漏约束 | 用户说"不要 X"，中间忘了，最后还是输出了 X |
| 上下文溢出 | token 超限导致早期信息被截断 |

**缓解手段**：
- **摘要压缩**：定期将历史对话压缩为摘要，保留关键信息
- **状态显式化**：将关键约束写入状态对象，每步都能看到
- **检索增强**：长链路中按需检索关键历史片段
- **关键约束复述**：在每步 prompt 末尾重复用户核心约束

## 二、故障模式速查表

| 故障 | 一句话描述 | 最危险之处 | 核心缓解 |
|------|-----------|-----------|---------|
| 幻觉蔓延 | 错误前提→后续全偏 | 隐蔽且传播 | 中间检查点 + 事实校验 |
| 死循环 | 反复执行无法收敛 | 永不终止 | 最大步数 + 重复检测 |
| 越权调用 | 调了不该调的工具 | 安全事故 | 工具白名单 + 权限分级 |
| 参数填充错误 | schema 守不住 | 静默失败 | 参数校验层 + 结构化错误 |
| 中途遗忘 | 丢失前文关键信息 | 前后矛盾 | 状态显式化 + 摘要压缩 |

## 三、保障手段总览

### 执行前

| 手段 | 作用 |
|------|------|
| 工具白名单 | 限制可用工具范围 |
| 参数 schema 校验 | 拦截类型/格式/枚举错误 |
| 权限分级 | 读/写/管理分离 |

### 执行中

| 手段 | 作用 |
|------|------|
| 最大步数限制 | 防死循环兜底 |
| 重复 Action 检测 | 识别无进展循环 |
| 关键节点人工审批 | 高风险操作 human-in-the-loop |
| 中间检查点 | 防幻觉蔓延、及时发现偏离 |

### 执行后

| 手段 | 作用 |
|------|------|
| 执行轨迹审计 | 全链路可追溯 |
| 异常模式告警 | 死循环/越权/异常参数自动告警 |
| 回归评测 | 每次迭代全量回归，防止修 A 坏 B |

## 五、面试高频

### Q: Agent 最常见的故障是什么？怎么防？

> 最常见的是**幻觉蔓延**和**死循环**。幻觉蔓延是一步错步步错——Agent 基于幻觉出的工具返回继续推理，整条链路偏离但自洽。防法是关键步骤后加事实校验和中间检查点。死循环是 Agent 反复调同一工具或在两个节点间跳转，防法是最大步数兜底 + 重复 Action 检测。

### Q: 怎么防止 Agent 越权？

> 三层防线：第一层是**工具白名单**，每个 Agent 角色只能访问预定义的工具集；第二层是**权限分级**，读/写/管理分离，低权限不能调高权限接口；第三层是**操作审计**，所有工具调用记日志，异常模式自动告警。高风险操作（删除/支付）还要加 human-in-the-loop。

### Q: Agent 的幻觉和普通大模型幻觉有什么区别？

> 普通 LLM 幻觉是一次性的——输出错误就结束了。Agent 幻觉会**蔓延**：第 1 步幻觉出一个不存在的结果，第 2 步基于这个错误前提继续推理，第 3 步又基于第 2 步的错误结论行动……雪球越滚越大，但中间步骤看起来逻辑自洽，非常隐蔽。所以 Agent 更需要中间检查点来打断传播链。

---

## 一句话总结

> Agent 五大故障模式：幻觉蔓延（一步错步步错）、死循环（无法收敛）、越权调用（调了不该调的）、参数填充错误（schema 守不住）、中途遗忘（丢失前文约束）；保障靠三层防线——执行前（白名单+校验+权限）、执行中（步数限制+重复检测+人工审批+检查点）、执行后（审计+告警+回归）。

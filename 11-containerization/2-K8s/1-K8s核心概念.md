# K8s 核心概念

## Q：Kubernetes 是什么？

Kubernetes（简称 K8s）是一个开源的**容器编排平台**，用于自动化部署、扩缩和管理容器化应用。它将多个主机抽象为一个资源池，统一调度和管理容器，解决大规模容器运维的复杂性。

---

## 核心概念

### Pod — 最小调度单元

- K8s 中最小的部署和调度单元
- 一个 Pod 包含一个或多个紧密耦合的容器，共享网络命名空间和存储卷
- 同一 Pod 内容器通过 `localhost` 通信
- Pod 是临时性的，重启后 IP 可能变化

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: my-pod
spec:
  containers:
  - name: app
    image: nginx:latest
    ports:
    - containerPort: 80
```

### Deployment — 管理 Pod 副本集

- 管理 Pod 的副本数量，声明式更新
- 支持滚动更新（Rolling Update）和回滚（Rollback）
- 内部通过 ReplicaSet 控制 Pod 数量

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-deployment
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: app
        image: nginx:1.25
```

### Service — 为 Pod 提供稳定访问入口

Pod 的 IP 会变化，Service 为一组 Pod 提供固定的访问入口（ClusterIP）和负载均衡。

| 类型 | 说明 | 访问范围 |
|---|---|---|
| ClusterIP | 默认类型，集群内部 IP | 集群内部 |
| NodePort | 在每个节点上开放端口 | 集群外部（<节点IP>:<NodePort>） |
| LoadBalancer | 云厂商提供的外部负载均衡器 | 公网 |

```yaml
apiVersion: v1
kind: Service
metadata:
  name: my-service
spec:
  selector:
    app: my-app
  type: ClusterIP
  ports:
  - port: 80
    targetPort: 80
```

### Namespace — 资源隔离

- 将集群划分为多个虚拟集群，实现资源隔离和权限控制
- 默认命名空间：`default`、`kube-system`、`kube-public`
- 适合多团队/多环境（dev/staging/prod）隔离

### ConfigMap / Secret — 配置管理

| 类型 | 用途 | 存储方式 |
|---|---|---|
| ConfigMap | 存储非敏感配置（环境变量、配置文件） | 明文 |
| Secret | 存储敏感信息（密码、证书、Token） | Base64 编码 |

```yaml
# ConfigMap 示例
apiVersion: v1
kind: ConfigMap
metadata:
  name: app-config
data:
  DB_HOST: "mysql.default.svc.cluster.local"
  DB_PORT: "3306"
```

### Ingress — 集群入口路由

- 管理集群外部 HTTP/HTTPS 访问的路由规则
- 基于域名/路径将请求转发到对应 Service
- 需要部署 Ingress Controller（如 Nginx Ingress Controller）

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: my-ingress
spec:
  rules:
  - host: app.example.com
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: my-service
            port:
              number: 80
```

### PV / PVC — 持久化存储

| 概念 | 说明 |
|---|---|
| PV（PersistentVolume） | 集群级别的存储资源，由管理员创建或 StorageClass 动态供给 |
| PVC（PersistentVolumeClaim） | 用户对存储的申请，Pod 通过 PVC 挂载存储 |

## 架构与工作流程

### 控制面组件（Control Plane）

| 组件 | 职责 |
|---|---|
| API Server | 集群入口，所有操作都通过 REST API 与其交互 |
| etcd | 分布式键值存储，保存集群所有状态数据 |
| Scheduler | 根据资源和约束策略，将 Pod 调度到合适的节点 |
| Controller Manager | 运行各种控制器（Deployment Controller、ReplicaSet Controller 等），维护期望状态 |

### 节点组件（Node）

| 组件 | 职责 |
|---|---|
| Kubelet | 管理本节点上 Pod 的生命周期，向 API Server 汇报状态 |
| Kube-proxy | 维护网络规则，实现 Service 的负载均衡和服务发现 |
| 容器运行时 | 运行容器的软件（containerd、CRI-O 等） |

### 工作流程简述

```
kubectl apply → API Server → etcd（持久化）
                        ↓
              Controller Manager（检测到期望状态变化，创建 ReplicaSet/Pod）
                        ↓
              Scheduler（为 Pod 选择节点，写入 etcd）
                        ↓
              Kubelet（监听到本节点有新 Pod，拉取镜像、启动容器）
                        ↓
              容器运行时（实际运行容器）
```

## K8s 与 Docker Compose 的区别

| 对比维度 | Docker Compose | Kubernetes |
|---|---|---|
| 定位 | 单机容器编排 | 集群级容器编排 |
| 规模 | 单节点，适合开发/测试 | 多节点，适合生产环境 |
| 自愈能力 | 无（容器挂了不会自动重启） | 有（自动重启、替换失败 Pod） |
| 扩缩容 | 手动 | 支持 HPA 自动扩缩容 |
| 服务发现 | 容器名直接访问 | Service + DNS |
| 滚动更新 | 需手动 | 内置支持 |
| 配置管理 | environment / .env | ConfigMap / Secret |
| 学习成本 | 低 | 高 |

## 面试高频题

### Pod 的生命周期

| 阶段 | 说明 |
|---|---|
| Pending | Pod 已被接受，但容器镜像尚未拉取/创建 |
| Running | Pod 已绑定到节点，所有容器已创建，至少一个正在运行 |
| Succeeded | 所有容器成功执行并退出 |
| Failed | 所有容器退出，至少一个失败 |
| Unknown | 无法获取 Pod 状态（通常是与节点通信失败） |

### 健康检查（Probe）

| 类型 | 说明 | 用途 |
|---|---|---|
| Liveness Probe | 存活检查，失败则**重启容器** | 检测死锁等不可恢复状态 |
| Readiness Probe | 就绪检查，失败则**从 Service 移除** | 确保流量只打到就绪的 Pod |
| Startup Probe | 启动检查，成功后才进行上述两种检查 | 适用于慢启动应用 |

```yaml
livenessProbe:
  httpGet:
    path: /health
    port: 8080
  initialDelaySeconds: 30
  periodSeconds: 10
readinessProbe:
  httpGet:
    path: /ready
    port: 8080
  initialDelaySeconds: 5
  periodSeconds: 5
```

### 滚动更新策略

```yaml
spec:
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxUnavailable: 1    # 最多1个Pod不可用
      maxSurge: 1           # 最多多出1个Pod
```

- **RollingUpdate**（默认）：逐步替换旧 Pod，保证服务不中断
- **Recreate**：先删除所有旧 Pod，再创建新 Pod，有短暂不可用

回滚操作：
```bash
kubectl rollout history deployment/my-deployment   # 查看历史版本
kubectl rollout undo deployment/my-deployment       # 回滚到上一版本
kubectl rollout undo deployment/my-deployment --to-revision=2  # 回滚到指定版本
```

## 一句话总结

K8s 是容器编排的事实标准，核心概念包括 Pod（最小调度单元）、Deployment（副本管理）、Service（稳定访问入口）、Ingress（入口路由）、ConfigMap/Secret（配置管理）、PV/PVC（持久化存储），面试高频考点为 Pod 生命周期、健康检查和滚动更新策略。

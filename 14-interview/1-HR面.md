# HR 面

## Q：HR 面和技术面有什么区别？

| 维度 | 技术面 | HR 面 |
|------|--------|-------|
| 考察重点 | 专业能力、项目深度、解题思路 | 软技能、稳定性、价值观匹配 |
| 提问方式 | 场景题、原理追问、手写代码 | 行为面试、开放性问题 |
| 评判标准 | 对不对、深不深 | 合不合适、稳不稳定 |
| 常见话术 | "说说你的理解" "为什么这么设计" | "你怎么看待" "你期望什么" |
| 核心逻辑 | 你能不能干活 | 你能不能长干、好不好合作 |

HR 面不是走过场，很多技术面过了的人挂在 HR 面，原因通常是：表达不清晰、职业规划混乱、稳定性存疑、价值观不匹配。

## Q：自我介绍怎么说？

### 结构：3 分钟黄金模板

```text
1. 基本信息（15秒）：姓名 + 学校/专业 + 工作年限
2. 核心经历（90秒）：1-2 个最相关的项目，突出你的角色和成果
3. 个人亮点（30秒）：技术栈/方法论/特质，贴合岗位需求
4. 收尾（15秒）：表达对岗位的兴趣，过渡到面试
```

### 示例

> 你好，我是 XXX，XX 大学计算机专业毕业，有 X 年后端开发/测试经验。
>
> 上一段经历在 XX 公司负责 XX 系统的 XX 工作，其中我主导了 XX 项目的 XX 模块，通过 XX 方案将 XX 指标从 XX 提升到 XX，这个过程中我积累了 XX 方面的经验。
>
> 我的核心优势是 XX（如：系统设计能力 / 自动化测试体系搭建 / 问题定位效率），熟悉 XX 技术栈。
>
> 很感兴趣贵司的 XX 方向，希望能有机会加入团队。

### 要点

- **不要背简历**：HR 已经看过简历，自我介绍要讲"故事"而非罗列
- **量化成果**："提升了性能" 不如 "QPS 从 500 提升到 2000"
- **贴合岗位**：根据 JD 调整侧重点，投开发强调设计能力，投测试强调质量意识

## Q：为什么选择我们公司？

### 回答框架

```text
1. 行业/业务认同：公司所在赛道有前景 + 你认可其业务方向
2. 能力匹配：你的技能/经验与岗位需求高度契合
3. 成长空间：公司能提供你想要的发展平台
```

### 示例

> 我选择贵司主要有三点：一是贵司在 XX 领域处于领先地位，XX 产品的用户规模让我觉得这个方向很有价值；二是我的 XX 经验和这个岗位的要求很匹配，上手会比较快；三是了解到贵司的技术氛围/培养体系很好，能帮助我持续成长。

### 避坑

- **不要说**"因为工资高" / "因为离家近" / "因为没别的 offer"
- **不要空泛**"贵司很伟大" — 要说具体哪里吸引你（产品、技术、文化）
- 提前调研：公司官网、近期新闻、技术博客、脉脉评价

## Q：你的优点和缺点是什么？

### 优点：用具体事例支撑

| 错误说法 | 正确说法 |
|----------|----------|
| 我很努力 | 我在 XX 项目中连续两周攻坚，最终提前 3 天交付 |
| 我学习能力强 | 我用一周时间自学 XX 技术并应用到项目中，解决了 XX 问题 |
| 我负责任 | 我负责的模块上线后零 P0 故障，主动处理了 XX 遗留问题 |

### 缺点：说真实的 + 改进中的

**核心原则**：说一个真实的缺点，但必须是**正在改进且不影响核心能力**的。

```text
缺点公式：我之前在 XX 方面不够好 → 我意识到了 → 我采取了 XX 行动 → 目前已经 XX
```

| 不要说 | 可以说 |
|--------|--------|
| 我太追求完美（太假） | 我之前不太善于拒绝需求，导致排期紧张，现在学会了评估优先级 |
| 我没有缺点（太傲） | 我之前在技术分享上比较被动，现在每月主动做一次团队分享 |
| 我脾气不好（太实） | 我之前在跨团队沟通时容易只关注技术方案，忽略了对方诉求，现在会先理解业务背景 |
| 我代码写得很烂（致命） | 我之前对代码规范重视不够，后来引入了静态检查工具并养成了 Code Review 习惯 |

## Q：你的职业规划是什么？

### 回答原则

- **务实不画饼**：不谈"5 年当 CTO"，谈具体能力提升方向
- **短长期结合**：短期 1-2 年 + 长期 3-5 年
- **贴合岗位**：规划要和应聘岗位有逻辑关联

### 示例

> 短期 1-2 年，我希望在 XX 方向深入积累，成为团队在 XX 领域的骨干，能够独立负责核心模块的设计和交付。长期 3-5 年，我希望成长为技术专家/团队负责人，不仅能解决复杂技术问题，还能带动团队的技术提升。

### 避坑

- **不要说**"还没想好" — 显得没有目标感
- **不要说**"想转管理" — 除非岗位就是管理岗
- **不要说**"想创业" — HR 会觉得你不稳定

## Q：期望薪资怎么谈？

### 策略

| 情况 | 回答方式 |
|------|----------|
| 有其他 offer | "我的期望是 XX-XX，也综合考虑发展空间" |
| 无其他 offer | "我目前的薪资是 XX，期望有合理的涨幅，具体可以聊" |
| 完全没概念 | "我更看重平台和成长，薪资方面相信公司有合理的体系" |

### 要点

- **给区间，不给死数字**：区间下限是你能接受的最低值
- **了解市场行情**：提前查同岗位薪资范围（脉脉、Boss 直聘、offershow）
- **不先亮底牌**：尽量让对方先出价，再谈判
- **总包思维**：base + 年终奖 + 股票 + 补贴，不只看月薪

## Q：你还有什么想问的？

这是面试最后的常见问题，**不要说"没有"**，准备 2-3 个好问题：

### 推荐问题

| 类别 | 问题 |
|------|------|
| 团队 | 这个岗位所在团队的规模和分工是怎样的？ |
| 业务 | 团队目前最核心的业务挑战是什么？ |
| 成长 | 公司对新人/新员工有怎样的培养机制？ |
| 技术 | 团队目前在技术上的重点方向是什么？ |
| 流程 | 团队的研发/发布流程是怎样的？ |

### 不要问

- 薪资/加班 — 这些留到谈 offer 阶段
- 百度能查到的基础信息 — 显得没做功课
- 负面问题 — "你们是不是经常加班？"

## Q：离职原因怎么说？

### 核心原则：正面表述，不抱怨前司

| 不要说 | 可以说 |
|--------|--------|
| 公司太卷了 / 加班太多 | 我希望寻找更能发挥 XX 能力的平台 |
| 领导太坑了 | 我希望在技术深度/业务广度上有更多成长空间 |
| 工资太低了 | 我希望寻找职业发展的下一个阶段 |
| 没前途 | 我对 XX 方向更感兴趣，希望做更有挑战的事 |
| 被裁了（如实说） | 公司业务调整，XX 部门整体优化，我在此期间完成了 XX |

### 万能模板

> 在上家公司我积累了 XX 经验，但我觉得在 XX 方面遇到了瓶颈，所以希望到一个 XX 更强的平台继续发展。

## Q：回答所有 HR 问题的通用法则 — STAR 法则

| 字母 | 含义 | 说明 |
|------|------|------|
| **S** | Situation（情境） | 什么背景/场景下 |
| **T** | Task（任务） | 你面临什么挑战/目标 |
| **A** | Action（行动） | 你具体做了什么 |
| **R** | Result（结果） | 取得了什么成果，量化 |

### 示例

> **S**：项目上线前一周发现接口响应时间 P99 超过 3 秒
> **T**：需要在上线前优化到 500ms 以内
> **A**：我通过火焰图定位到热点方法是 DB 慢查询，添加了组合索引并引入了 Redis 缓存
> **R**：P99 从 3.2s 降到 420ms，项目按时上线

### 回答三原则

1. **真实**：不编造经历，细节经不起追问
2. **正面**：每段经历都要导向积极的结论
3. **量化**：用数字说话，"提升了 X%" 胜过 "优化了很多"

---

## 一句话总结

HR 面的核心不是证明你"多厉害"，而是证明你"靠谱、稳定、好合作"——用 STAR 法则讲故事，用数字量化成果，用正面态度回应一切问题。

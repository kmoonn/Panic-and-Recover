# 联表查询

## 七种 JOIN 图解

```
    ┌─────────────┐       ┌─────────────┐
    │   Table A    │       │   Table B    │
    │             │       │             │
    │   ┌───┐     │       │     ┌───┐   │
    │   │   │     │       │     │   │   │
    │   │ ◉───────┼───────┼─────┼◉  │   │
    │   │   │     │       │     │   │   │
    │   └───┘     │       │     └───┘   │
    └─────────────┘       └─────────────┘

    INNER JOIN：        ◉◉（交集）
    LEFT JOIN：    ◉◉ + ○（左表全部 + 交集）
    RIGHT JOIN：        ◉◉ + ○（交集 + 右表全部）
    FULL JOIN：    ○ + ◉◉ + ○（左表全部 + 交集 + 右表全部）
    CROSS JOIN：   笛卡尔积
```

## 各类 JOIN 详解

### 1. INNER JOIN（内连接）

返回两表中**匹配的行**，不匹配的行不返回。

```sql
SELECT a.name, b.order_id
FROM user a
INNER JOIN order b ON a.id = b.user_id;
-- 只返回有订单的用户
```

### 2. LEFT JOIN（左连接/左外连接）

返回**左表所有行**，右表没有匹配的用 NULL 填充。

```sql
SELECT a.name, b.order_id
FROM user a
LEFT JOIN order b ON a.id = b.user_id;
-- 返回所有用户，没有订单的用户 order_id 为 NULL
```

### 3. RIGHT JOIN（右连接/右外连接）

返回**右表所有行**，左表没有匹配的用 NULL 填充。

```sql
SELECT a.name, b.order_id
FROM user a
RIGHT JOIN order b ON a.id = b.user_id;
-- 返回所有订单，没有对应用户的 name 为 NULL
```

### 4. FULL JOIN（全连接/全外连接）

返回**两表所有行**，没有匹配的用 NULL 填充。MySQL 不直接支持，用 UNION 模拟。

```sql
-- MySQL 模拟 FULL JOIN
SELECT a.name, b.order_id FROM user a LEFT JOIN order b ON a.id = b.user_id
UNION
SELECT a.name, b.order_id FROM user a RIGHT JOIN order b ON a.id = b.user_id;
```

### 5. CROSS JOIN（交叉连接/笛卡尔积）

返回两表的**笛卡尔积**，每行组合，行数 = A行数 × B行数。

```sql
SELECT a.name, b.product
FROM user a
CROSS JOIN product b;
-- 每个 user 与每个 product 组合
```

### 6. 自连接

表与自身连接，用于层级关系等场景。

```sql
-- 查找每个员工及其上级
SELECT e.name AS employee, m.name AS manager
FROM employee e
LEFT JOIN employee m ON e.manager_id = m.id;
```

### 7. 子查询

查询嵌套在另一个查询中。

```sql
-- 标量子查询
SELECT * FROM user WHERE id = (SELECT user_id FROM order WHERE order_id = 100);

-- IN 子查询
SELECT * FROM user WHERE id IN (SELECT user_id FROM order WHERE amount > 1000);

-- EXISTS 子查询
SELECT * FROM user a WHERE EXISTS (SELECT 1 FROM order b WHERE b.user_id = a.id);
```

## 内连接 vs 外连接对比

| 对比项 | INNER JOIN | LEFT JOIN | RIGHT JOIN |
|---|---|---|---|
| 返回行 | 两表匹配的行 | 左表全部 + 右表匹配 | 右表全部 + 左表匹配 |
| 不匹配处理 | 丢弃 | 右表填 NULL | 左表填 NULL |
| 数据完整性 | 只看关联数据 | 保留左表完整 | 保留右表完整 |

## 子查询 vs JOIN 的性能对比

| 对比项 | 子查询 | JOIN |
|---|---|---|
| 可读性 | 逻辑清晰 | 关系明确 |
| 性能 | 可能执行多次 | 通常更优 |
| 优化 | MySQL 优化器会尝试改写为 JOIN | 优化器直接优化 |
| 适用场景 | 简单条件判断 | 多表关联查询 |

```sql
-- 子查询（可能效率低）
SELECT * FROM user WHERE id IN (SELECT user_id FROM order WHERE amount > 1000);

-- 等价 JOIN（通常更高效）
SELECT DISTINCT user.* FROM user
INNER JOIN order ON user.id = order.user_id
WHERE order.amount > 1000;

-- EXISTS 子查询（大数据量时可能更优）
SELECT * FROM user a
WHERE EXISTS (SELECT 1 FROM order b WHERE b.user_id = a.id AND b.amount > 1000);
```

> **经验**：MySQL 优化器通常会将相关子查询改写为半连接（Semi-Join），但显式 JOIN 的性能仍更稳定可控。大数据量时，EXISTS 子查询可能比 IN 子查询更高效。

## 面试高频问题

### Q: LEFT JOIN 和 INNER JOIN 的区别？

- INNER JOIN 只返回两表中能匹配的行，不匹配的丢弃
- LEFT JOIN 返回左表所有行，右表无匹配时填 NULL
- 如果只关心关联数据用 INNER JOIN，需要保留左表完整数据用 LEFT JOIN

### Q: 什么时候用 EXISTS，什么时候用 IN？

- **子查询结果集小**：用 IN（先执行子查询，再在主查询中过滤）
- **外表结果集小**：用 EXISTS（对外表逐行判断子查询是否有结果）
- NOT EXISTS 通常比 NOT IN 性能更好（NOT IN 遇到 NULL 会有问题）

## 一句话总结

联表查询通过 JOIN 关联多张表，INNER JOIN 返回交集、LEFT JOIN 保留左表全部、RIGHT JOIN 保留右表全部；JOIN 通常比子查询性能更优，EXISTS 和 IN 的选择取决于哪张表结果集更小。

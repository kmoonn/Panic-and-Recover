# 分组（GROUP BY）

## GROUP BY 是什么？

GROUP BY 用于**按一个或多个列对结果集进行分组**，常与聚合函数（COUNT、SUM、AVG、MAX、MIN）配合使用，对每个分组进行聚合计算。

## 基本语法

```sql
SELECT 列名, 聚合函数(列名)
FROM 表名
WHERE 条件
GROUP BY 列名
HAVING 分组后条件
ORDER BY 列名;
```

```sql
-- 示例：按部门分组，统计每个部门的平均薪资
SELECT department, AVG(salary) AS avg_salary
FROM employee
GROUP BY department;

-- 示例：按部门分组，筛选平均薪资大于 10000 的部门
SELECT department, AVG(salary) AS avg_salary
FROM employee
GROUP BY department
HAVING avg_salary > 10000;
```

## SQL 执行顺序

理解 GROUP BY 的关键在于掌握 SQL 的执行顺序：

| 顺序 | 子句 | 说明 |
|---|---|---|
| 1 | FROM | 确定数据来源（表/连接） |
| 2 | WHERE | 过滤原始行（分组前过滤） |
| 3 | GROUP BY | 对过滤后的数据分组 |
| 4 | HAVING | 过滤分组（分组后过滤） |
| 5 | SELECT | 选择输出列 |
| 6 | ORDER BY | 对结果排序 |
| 7 | LIMIT | 限制返回行数 |

```
FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT
```

## WHERE 与 HAVING 的区别

| 对比项 | WHERE | HAVING |
|---|---|---|
| 作用时机 | 分组前过滤 | 分组后过滤 |
| 过滤对象 | 原始行 | 分组后的聚合结果 |
| 是否能用聚合函数 | 不能 | 能 |
| 执行顺序 | 在 GROUP BY 之前 | 在 GROUP BY 之后 |

```sql
-- WHERE：分组前过滤，不能用聚合函数
SELECT department, AVG(salary)
FROM employee
WHERE salary > 3000    -- 先过滤薪资 > 3000 的员工
GROUP BY department;

-- HAVING：分组后过滤，用聚合函数
SELECT department, AVG(salary)
FROM employee
GROUP BY department
HAVING AVG(salary) > 10000;  -- 过滤平均薪资 > 10000 的部门
```

## SELECT 中非聚合列必须出现在 GROUP BY 中

SQL 标准要求：**SELECT 中出现的非聚合列必须出现在 GROUP BY 中**。

```sql
-- 合法：department 在 GROUP BY 中
SELECT department, COUNT(*)
FROM employee
GROUP BY department;

-- 非法（SQL 标准）：name 不在 GROUP BY 中
SELECT department, name, COUNT(*)
FROM employee
GROUP BY department;
-- name 属于哪个分组？不确定，SQL 标准不允许

-- MySQL 的宽松模式（only_full_group_by 关闭时）允许上述写法
-- 但会随机返回某个 name 值，结果不确定
```

```sql
-- 查看和设置 sql_mode
SELECT @@sql_mode;
-- 开启严格模式（推荐）
SET sql_mode = 'ONLY_FULL_GROUP_BY,...';
```

## GROUP BY 与 DISTINCT 的区别

| 对比项 | GROUP BY | DISTINCT |
|---|---|---|
| 作用 | 分组 + 聚合计算 | 去重 |
| 是否能配合聚合函数 | 是（COUNT、SUM 等） | 否 |
| 是否能使用 HAVING | 是 | 否 |
| 是否能排序分组 | 是 | 否 |
| 去重场景 | `GROUP BY col` 可去重 | `SELECT DISTINCT col` 去重 |

```sql
-- 去重：两者等价
SELECT DISTINCT department FROM employee;
SELECT department FROM employee GROUP BY department;

-- 聚合：只能用 GROUP BY
SELECT department, COUNT(*) FROM employee GROUP BY department;
```

## 面试高频问题

### Q: GROUP BY 和 WHERE/HAVING 的执行顺序？

**WHERE → GROUP BY → HAVING**。WHERE 在分组前过滤原始数据，GROUP BY 执行分组，HAVING 在分组后过滤聚合结果。

### Q: WHERE 和 HAVING 的区别？

WHERE 在分组前过滤行，不能用聚合函数；HAVING 在分组后过滤分组结果，能使用聚合函数。先 WHERE 缩小范围，再 GROUP BY 分组，最后 HAVING 过滤。

### Q: SELECT 中非聚合列不在 GROUP BY 中会怎样？

SQL 标准不允许。MySQL 默认的 `ONLY_FULL_GROUP_BY` 模式会报错；关闭该模式时可以执行，但非聚合列的值不确定。

## 一句话总结

GROUP BY 按列分组并结合聚合函数进行统计，SQL 执行顺序为 WHERE → GROUP BY → HAVING → SELECT → ORDER BY，其中 WHERE 用于分组前过滤行、HAVING 用于分组后过滤聚合结果，SELECT 中非聚合列必须出现在 GROUP BY 中。

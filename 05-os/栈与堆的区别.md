# 栈与堆的区别

程序的内存从逻辑上分为多个区域，其中**栈（Stack）**和**堆（Heap）**是最核心的两块，分别管理不同生命周期的数据。

## 栈

- 由编译器/操作系统自动分配和释放
- 存放**局部变量、函数参数、返回地址**
- 分配速度快（只需移动栈指针）
- 空间有限（Linux 默认主线程栈 8MB，`ulimit -s` 可查）
- 内存连续，访问局部性好，对 CPU 缓存友好

## 堆

- 由程序员手动申请/释放（C 的 `malloc/free`，Java 的 `new` + GC）
- 存放**动态分配的对象、大块数据**
- 分配较慢（需在空闲链表中查找合适大小的块）
- 空间大（受限于系统虚拟内存大小）
- 内存不连续，频繁分配释放易产生**外部碎片**

## 对比表

| | 栈 | 堆 |
|---|---|---|
| **分配方式** | 自动（编译器/OS） | 手动（程序员/GC） |
| **存储内容** | 局部变量、参数、返回地址 | 动态对象、大块数据 |
| **分配速度** | 快（移动栈指针） | 慢（查找空闲块） |
| **空间大小** | 小（~MB 级） | 大（~GB 级） |
| **生长方向** | 高地址→低地址（向下） | 低地址→高地址（向上） |
| **碎片问题** | 无（连续分配释放） | 外部碎片 |
| **线程关系** | 每线程独立栈 | 进程内所有线程共享堆 |
| **生命周期** | 函数返回即释放 | 显式释放或 GC 回收 |

## 面试追问

### 栈溢出是什么？怎么发生的？

递归调用过深或局部变量过大，超出栈空间上限 → `StackOverflowError`（Java）/ segment fault（C）。解决方案：改递归为迭代、增大栈大小（`-Xss`）、将大数组移到堆上。

### 为什么堆要手动管理而栈自动管理？

栈上的内存生命周期与函数调用严格绑定——函数返回时其栈帧必然失效，所以编译器可以安全地自动释放。堆上对象的生命周期与调用栈无关（可能被多处引用），编译器无法确定何时安全回收，必须由程序员或 GC 决定。

### Go / Rust 的栈和堆有什么不同？

- **Go**：编译器做**逃逸分析**，能放在栈上的绝不上堆；栈可自动扩缩容（连续栈），不会因递归溢出
- **Rust**：所有权系统在编译期决定分配位置，默认栈分配；需要堆时用 `Box<T>` 显式标注；无 GC，靠所有权自动释放

## 一句话总结

> 栈自动管理、快而小，存局部变量和调用信息；堆手动管理、慢而大，存动态对象；两者分工的核心是生命周期——函数级自动释放 vs 跨函数手动回收。

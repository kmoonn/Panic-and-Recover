# 线程同步与锁

线程共享进程地址空间，并发访问共享数据时必须同步，否则出现数据竞争。同步机制从悲观到乐观有多种选择。

## 同步机制对比

| 机制 | 特点 | 适用场景 |
|---|---|---|
| **互斥锁（Mutex）** | 保证同一时刻只有一个线程进临界区 | 保护共享变量 |
| **读写锁** | 读读共享、读写/写写互斥 | 读多写少（如缓存） |
| **信号量（Semaphore）** | 计数器，控制同时访问的线程数（=1 时退化为互斥锁） | 并发限流 |
| **条件变量** | 线程等待某条件成立（wait/notify），常配互斥锁用 | 生产者-消费者 |
| **自旋锁** | 忙等不睡眠，适合锁持有时间极短的场景 | 极短临界区 |

## 乐观锁 vs 悲观锁

| | 悲观锁 | 乐观锁 |
|---|---|---|
| **思路** | 先加锁，再操作 | 先操作，提交时检查冲突 |
| **代表** | synchronized / ReentrantLock | CAS（如 Java AtomicInteger） |
| **适用** | 写多、冲突频繁 | 读多、冲突少 |
| **CAS 问题** | — | ABA 问题（加版本号解决） |

## 一句话总结

> 线程同步核心：互斥锁独占、读写锁读共享、信号量限流、条件变量等待/通知、自旋锁忙等；乐观锁 CAS 适合低冲突场景但有 ABA 问题。

# 多进程与多线程

## 对比

| | 多进程 | 多线程 |
|---|---|---|
| **资源** | 每个进程独立内存空间，开销大 | 线程共享进程内存，开销小 |
| **通信** | IPC（管道、消息队列、共享内存、Socket） | 直接读写共享变量 |
| **同步** | IPC 自带隔离，冲突少 | 需要锁（mutex、spinlock）防竞态 |
| **稳定性** | 一个进程崩溃不影响其他进程 | 一个线程崩溃可能拖垮整个进程 |
| **创建开销** | fork 开销大（COW 缓解） | 创建快，约 1/10 进程开销 |
| **CPU 利用** | 天然多核并行 | 需 OS 调度到不同核 |

## 什么时候用多进程

- **需要隔离性**：Nginx worker 进程，一个挂了其他继续服务
- **避免 GIL**：Python CPU 密集型任务用多进程绕开 GIL
- **安全隔离**：浏览器每标签页一个进程（Chrome）、容器
- **跨语言/跨机器**：微服务进程间通信

## 什么时候用多线程

- **需要共享数据**：Web 服务器各线程共享连接池、缓存
- **轻量并发**：创建销毁频繁的场景（用线程池）
- **IO 密集型**：多线程等待 IO 不浪费 CPU
- **低延迟通信**：共享内存直接读写，无需 IPC 序列化

## 经典模型

### Nginx：多进程

```
Master 进程（管理）
├── Worker 进程 1（处理请求）
├── Worker 进程 2
└── Worker 进程 N（通常 = CPU 核数）
```

好处：Worker 崩溃不影响其他，Master 自动重启。

### Tomcat / Redis 6.0+：多线程

```
主线程（接收连接）
├── IO 线程 1（读请求）
├── IO 线程 2
└── IO 线程 N
    → 主线程（串行执行命令）
    → IO 线程（写响应）
```

Redis 6.0 仅网络 IO 多线程，命令执行仍串行（保证原子性）。

### Node.js / Nginx：单进程 + 事件循环

不靠多线程并发，而靠**非阻塞 IO + 事件循环**单线程处理大量连接。

## 混合模式：多进程 + 多线程

实际生产中常混合使用：

```
Master 进程
├── Worker 进程 1
│   ├── 线程 1（处理请求）
│   └── 线程 2
├── Worker 进程 2
│   ├── 线程 1
│   └── 线程 2
```

- 进程级隔离：不同 Worker 独立内存
- 线程级并发：Worker 内多线程共享内存高效处理

## 多进程通信方式（IPC）

| 方式 | 特点 |
|---|---|
| 管道（Pipe） | 半双工，父子进程间 |
| 命名管道（FIFO） | 无亲缘关系进程间 |
| 消息队列 | 内核维护，按消息类型读取 |
| 共享内存 | 最快，但需自行同步 |
| 信号量 | 配合共享内存做同步 |
| Socket | 跨机器通信，通用但开销大 |

## 总结一句话

> 需要隔离和稳定用多进程，需要轻量和共享用多线程，生产中常混合：进程做隔离、线程做并发。

# 模板方法

## 什么是模板方法模式

模板方法模式（Template Method Pattern）在父类中定义算法的骨架，将某些步骤延迟到子类实现。子类可以在不改变算法结构的情况下，重新定义算法中的某些步骤。

**核心思想**：父类定流程，子类定细节。

```
┌───────────────────────────┐
│     AbstractClass          │
│                            │
│  + templateMethod()        │ ← 固定流程（final）
│    step1()  ──  固定步骤   │
│    step2()  ──  抽象方法   │ ← 子类实现
│    step3()  ──  固定步骤   │
│    step4()  ──  钩子方法   │ ← 子类可选重写
│                            │
└────────────┬──────────────┘
             │ 继承
     ┌───────┴───────┐
     ▼               ▼
┌──────────┐  ┌──────────┐
│ConcreteA │  │ConcreteB │
│step2()   │  │step2()   │
│step4()   │  │(不重写)  │
└──────────┘  └──────────┘
```

---

## 解决什么问题

| 问题 | 说明 |
|------|------|
| 流程重复 | 多个子类有相同执行流程，只是某些步骤不同 |
| 流程不一致 | 不同开发人员实现同一流程时步骤顺序不统一 |
| 不易扩展 | 每新增一种实现就要重写整个流程 |

**典型场景**：数据导入流程（读取→解析→校验→入库）、HTTP 请求处理、JUnit 测试生命周期。

---

## 三种方法类型

| 类型 | 修饰符 | 说明 | 示例 |
|------|--------|------|------|
| **模板方法** | `final` | 定义算法骨架，子类不能重写 | `importData()` |
| **抽象方法** | `abstract` | 子类必须实现 | `parse()`, `validate()` |
| **钩子方法** | `protected` | 子类可选重写，有默认实现 | `needLog()` |

### 钩子方法的三个用途

1. **控制流程走向**：如 `needLog()` 决定是否执行某步骤
2. **提供扩展点**：如 `beforeSave()` / `afterSave()` 允许子类做额外处理
3. **默认行为**：提供合理默认值，子类可选择性覆盖

---

## 在源码中的应用

| 框架 | 应用 |
|------|------|
| **JUnit** | `setUp()` → `testXxx()` → `tearDown()` |
| **Spring** | `AbstractApplicationContext.refresh()` — 容器刷新模板 |
| **Servlet** | `HttpServlet.service()` → `doGet()` / `doPost()` |
| **Arrays** | `sort()` 流程固定，`compareTo()` 比较规则由子类定 |
| **InputStream** | `read()` 抽象方法，`skip()` / `available()` 基于 `read()` 构建 |

### Spring refresh() 流程

```
prepareRefresh()                    ← 固定步骤
obtainFreshBeanFactory()            ← 固定步骤
prepareBeanFactory()                ← 固定步骤
postProcessBeanFactory()            ← 钩子方法（子类可重写）
invokeBeanFactoryPostProcessors()   ← 固定步骤
...
finishRefresh()                     ← 固定步骤
```

## 面试高频

### 模板方法 vs 策略模式

| 维度 | 模板方法 | 策略模式 |
|------|---------|---------|
| 实现方式 | 继承 | 组合 |
| 变化点 | 部分步骤的实现 | 整个算法的替换 |
| 流程控制 | 父类控制（更严格） | 客户端控制（更灵活） |
| 耦合度 | 较高（继承） | 较低（组合） |
| 适用 | 流程固定、细节变化 | 算法整体替换 |

> **经验法则**：优先用策略模式（组合优于继承），只有当流程确实需要父类严格控制时才用模板方法。

### 模板方法的缺点

| 缺点 | 说明 |
|------|------|
| 继承耦合 | 子类依赖父类实现，父类修改影响所有子类 |
| 类数量膨胀 | 每种实现一个子类 |
| 违反里氏替换 | 子类可能破坏父类约束 |

---

## 一句话总结

模板方法在父类用 final 方法定义算法骨架，将可变步骤延迟到子类实现（抽象方法），通过钩子方法提供可选扩展点，是"流程复用、细节定制"的经典设计，典型应用如 JUnit 生命周期和 Spring 容器刷新流程。

## 八股速记

**问：模板方法模式？**

- **定义**：父类定义算法**骨架**（固定流程），把某些步骤**延迟到子类**实现。
- **场景**：流程固定、局部可变——如"连接→执行→关闭"里的执行步骤留给子类；JUnit 的 `@BeforeEach`/测试/`@AfterEach` 生命周期就是模板思想。

**⭐ 加分/易错**：模板方法用**继承 + 抽象方法**复用流程，体现"好莱坞原则"（别调用我、我会调用你）。测试框架的用例执行流程大多是模板方法。

# 消息可靠性

MQ 消息的三大可靠性问题：丢失、重复、顺序，各有对应解法。

## 消息不丢失（三段保障）

① 生产端确认机制（`confirm`/ack）；② Broker **持久化**；③ 消费端**手动 ack**（处理成功再确认）。

## 消息不重复（幂等）

网络重试必然可能重复，**消费端做幂等**——用唯一业务 ID + 去重表 / 状态机 / `Redis SETNX`。

## 消息顺序

全局有序难，通常做**分区/队列内有序**（同一业务 key 路由到同一分区，如按订单 ID 哈希）。

## ⭐ 加分/易错

核心心法——**不丢靠"持久化+双端确认"，不重靠"消费端幂等"**。"消息 100% 不重复"做不到，重点是**幂等消费**。

## 一句话总结

> 消息不丢靠"持久化+双端确认"，不重靠"消费端幂等"，顺序靠"分区/队列内有序"；100%不重复做不到，重点是幂等消费。

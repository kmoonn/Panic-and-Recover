# 深拷贝与浅拷贝

> 一句话：**赋值只增加别名；浅拷贝创建新外层但共享内部对象；深拷贝递归复制对象图，使嵌套可变对象与原对象隔离。**

## 核心前提

Python 变量保存的是**对象引用**。理解拷贝前，要先区分对象是否可变：

- **不可变对象**：`int`、`float`、`str`、`bytes`、`frozenset`，以及元素均可哈希时的 `tuple`；
- **可变对象**：`list`、`dict`、`set` 和多数自定义类实例。

深浅拷贝的差异在处理**嵌套对象，尤其是嵌套可变对象**时最明显。

## 赋值、浅拷贝与深拷贝

| 方式 | 外层对象 | 嵌套子对象 | 修改嵌套可变对象 |
|---|---|---|---|
| `b = a` | 与原对象相同 | 与原对象相同 | 会影响原对象 |
| `copy.copy(a)` | 通常创建新外层 | 仍引用原子对象 | 会影响原对象 |
| `copy.deepcopy(a)` | 创建独立副本 | 递归复制需复制的对象 | 通常不影响原对象 |

### 直接赋值

`b = a` 不是拷贝，只是让两个变量指向同一个对象：

```text
a ─┐
   ├──▶ 外层列表 ──▶ 内层列表
b ─┘
```

### 浅拷贝 `copy.copy()`

浅拷贝只复制最外层容器，容器中的元素引用被原样放入新容器：

```text
a ──▶ 外层列表 A ─┐
                   ├──▶ 同一个内层列表
c ──▶ 外层列表 C ─┘
```

因此，替换 `c` 的外层元素不影响 `a`；通过 `c` 修改共享的内层列表，则 `a` 也能看到变化。

### 深拷贝 `copy.deepcopy()`

深拷贝递归复制对象图中的可复制对象：

```text
a ──▶ 外层列表 A ──▶ 内层列表 A

d ──▶ 外层列表 D ──▶ 内层列表 D
```

修改副本中的嵌套列表，通常不会影响原对象。

## 最小示例

```python
import copy

a = [1, [2, 3]]
shallow = copy.copy(a)
deep = copy.deepcopy(a)

shallow[1].append(4)  # a 也变为 [1, [2, 3, 4]]
deep[1].append(5)     # a 不受影响
```

## 常见浅拷贝方式

以下操作都会创建新外层容器，但继续共享内部元素：

| 类型 | 常见写法 |
|---|---|
| 列表 | `lst.copy()`、`lst[:]`、`list(lst)`、`[x for x in lst]` |
| 字典 | `d.copy()`、`dict(d)` |
| 集合 | `s.copy()`、`set(s)` |

例如，浅拷贝字典后，替换某个键对应的值不会影响原字典；但如果该值是共享的列表，对列表做 `append` 仍会影响原字典。

## 元组为什么表现特殊？

`tuple` 本身不可变，因此浅拷贝通常可以直接复用原元组：

- 元组元素全为不可变对象时，`copy.copy()` 和 `copy.deepcopy()` 都可能返回原对象；
- 元组中包含列表等可变对象时，浅拷贝仍共享该对象，深拷贝会复制需要隔离的嵌套对象。

> “元组不可变”只表示不能替换元组保存的引用，不代表引用指向的列表也不可变。

## `deepcopy` 并非机械地让所有对象换地址

“所有层级全部新建”便于入门记忆，但不完全准确：

- `int`、`str` 等不可变对象通常可安全复用；
- 函数、类等对象通常原样返回；
- `deepcopy` 使用 `memo` 记录已复制对象，既能处理循环引用，也会保留原对象图中的共享关系；
- 自定义类可以通过 `__copy__()` 和 `__deepcopy__()` 控制复制行为；
- 文件句柄、网络连接、锁等外部资源不适合依赖深拷贝获得独立副本。

所以，更准确的说法是：**深拷贝构造独立对象图，而不是保证每个对象的 `id` 都不同。**

## 常见坑点

### 1. 修改与重新绑定不同

```python
shallow[0] = 100       # 替换外层引用，不影响原列表
shallow[1].append(4)   # 修改共享子对象，会影响原列表
```

判断是否相互影响，关键要看操作修改的是**新外层容器**，还是二者共享的**嵌套对象**。

### 2. 深拷贝可能开销较大

深拷贝需要遍历对象图，时间和内存开销通常高于浅拷贝。对象很大时，应先判断是否真的需要完全隔离，也可以只复制即将修改的部分。

### 3. 循环引用不会导致无限递归

标准库 `deepcopy` 通过 `memo` 记录已经复制的对象，因此可以处理常见循环引用，并维持副本内部正确的引用关系。

## 使用场景

- **直接赋值**：有意共享同一状态；
- **浅拷贝**：只修改外层结构，或内部对象本来就应共享；
- **深拷贝**：嵌套可变状态必须隔离，例如复制配置模板后独立修改；
- **手动构造副本**：大型对象、外部资源或只需复制少数字段时，通常比盲目 `deepcopy` 更可控。

## 一句话总结

> 浅拷贝是“外壳新、内部引用共享”，深拷贝是“递归构造独立对象图”；判断是否会互相影响，要看被修改的对象是否仍被共享。

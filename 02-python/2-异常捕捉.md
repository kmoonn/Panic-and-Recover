# 异常捕捉

## 基本语法

```python
try:
    result = 10 / 0
except ZeroDivisionError as e:
    print(f"除零错误: {e}")
except (TypeError, ValueError) as e:
    print(f"类型或值错误: {e}")
except Exception as e:
    print(f"其他异常: {e}")
else:
    print("无异常时执行")
finally:
    print("始终执行")
```

- `else`：try 中无异常时执行（与 try 后直接写代码的区别：else 中的代码不会被 except 捕获）
- `finally`：无论是否异常都执行，常用于资源释放

## 常见内置异常

| 异常 | 触发场景 |
|---|---|
| `ZeroDivisionError` | 除以 0 |
| `TypeError` | 类型操作不匹配（如 `"a" + 1`） |
| `ValueError` | 值不合法（如 `int("abc")`） |
| `KeyError` | 字典 key 不存在 |
| `IndexError` | 索引越界 |
| `AttributeError` | 对象无该属性/方法 |
| `FileNotFoundError` | 文件不存在 |
| `ImportError` | 模块导入失败 |
| `StopIteration` | 迭代器耗尽 |

## 异常层级

```
BaseException
├── SystemExit          # sys.exit()
├── KeyboardInterrupt   # Ctrl+C
├── GeneratorExit       # generator.close()
└── Exception           # 所有业务异常的基类
    ├── ArithmeticError
    │   └── ZeroDivisionError
    ├── LookupError
    │   ├── IndexError
    │   └── KeyError
    ├── TypeError
    ├── ValueError
    ├── OSError
    │   └── FileNotFoundError
    └── ...
```

**捕获时用 `Exception`**，不要用 `BaseException`（会把 `SystemExit`、`KeyboardInterrupt` 也吞掉）。

## 自定义异常

```python
class BusinessError(Exception):
    """业务逻辑异常"""
    def __init__(self, code: int, message: str):
        self.code = code
        self.message = message
        super().__init__(message)

class InsufficientBalanceError(BusinessError):
    """余额不足"""
    def __init__(self, balance: float, amount: float):
        super().__init__(code=1001, message=f"余额 {balance} 不足 {amount}")
        self.balance = balance
        self.amount = amount
```

## raise 与异常链

```python
# 直接抛出
raise ValueError("非法参数")

# 异常链：底层异常包装成高层异常，保留原始堆栈
try:
    result = db.query(sql)
except DBError as e:
    raise BusinessError(500, "查询失败") from e
    # 输出时显示：BusinessError: 查询失败
    #             The above exception was the direct cause of: DBError: ...
```

## 上下文管理器与异常安全

用 `with` 保证资源释放，替代 `try/finally`：

```python
# try/finally 方式
f = None
try:
    f = open("data.txt")
    data = f.read()
finally:
    if f:
        f.close()

# with 方式（推荐）
with open("data.txt") as f:
    data = f.read()
# 自动关闭，即使 read() 抛异常也安全
```

自定义上下文管理器：

```python
class DatabaseSession:
    def __enter__(self):
        self.conn = create_connection()
        return self.conn

    def __exit__(self, exc_type, exc_val, exc_tb):
        if exc_type:               # 有异常
            self.conn.rollback()   # 回滚
        else:
            self.conn.commit()     # 提交
        self.conn.close()
        return False               # 不吞异常，继续向上抛

with DatabaseSession() as conn:
    conn.execute(sql)  # 异常自动回滚，正常自动提交
```

## 常见陷阱

### 1. 裸 except 吞掉所有异常

```python
# ❌ 吞掉 KeyboardInterrupt、SystemExit 等
try:
    ...
except:
    pass

# ✅ 至少用 Exception
try:
    ...
except Exception as e:
    log.error(e)
```

### 2. finally 中的 return 覆盖异常

```python
def foo():
    try:
        1 / 0
    finally:
        return 42  # ← 异常被吞！函数返回 42 而不是抛异常

print(foo())  # 42，ZeroDivisionError 消失了
```

### 3. except 顺序错误

```python
# ❌ Exception 在前，后面的子类永远不会被捕获
try:
    ...
except Exception:
    ...
except ValueError:    # 永远到不了
    ...

# ✅ 子类在前，父类在后
try:
    ...
except ValueError:
    ...
except Exception:
    ...
```

## 总结

| 要点 | 说明 |
|---|---|
| 捕获基类 | 用 `Exception`，不用裸 `except` 或 `BaseException` |
| 异常链 | `raise HighError() from low_error` 保留原始堆栈 |
| 资源安全 | `with` 上下文管理器 > `try/finally` |
| 顺序 | 子类异常在前，父类在后 |
| finally | 不要在 finally 中 return，会吞异常 |

## 一句话总结

> 用Exception捕获、子类在前、异常链保留堆栈、with管理资源、finally中勿return。

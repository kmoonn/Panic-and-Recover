# CPU与内存排查

线上问题排查是测开/后端的核心工程能力，关键思路是**分层缩小范围 + 具体命令 + 定位到根因**。

## CPU 高排查

1. `top` 找占用 CPU 高的进程
2. `top -Hp pid` 找占用高的线程
3. 线程 id 转 16 进制
4. Java 用 `jstack pid` 定位到代码栈（找死循环/频繁 GC）

## 内存高 / OOM 排查

1. `free -h` 看整体内存使用
2. `top` 看进程 RES（实际物理内存）
3. Java 用 `jmap` 导堆、`jstat -gc` 看 GC 频率
4. 定位内存泄漏（呼应武理工竞赛系统的 OOM 案例）

## 磁盘满排查

1. `df -h` 找满的分区
2. `du -sh /path/*` 逐层找大目录/大文件
3. 常见原因是日志没切割
4. `lsof | grep deleted` 找已删除但句柄未释放的文件（空间未真正释放）

## 排查核心思路

分层缩小范围：CPU 从进程到线程到代码栈，磁盘从分区到目录到文件。答出**分层缩小范围 + 具体命令 + 定位到根因**比背概念强得多，面试时可扣回项目里的真实案例。

## 一句话总结

> CPU 高：top→线程→jstack 定位栈；内存高：free→top→jmap/jstat；磁盘满：df→du→lsof 找已删未释放——核心是分层缩小范围到根因。
